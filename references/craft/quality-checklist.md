# 全流程质量检查清单

本文件是全流程质量检查的总闸口——从开书前到发布前，每个阶段的关键检查项
汇总成可执行的 yes/no 清单。每项检查都标注了来源文档，遇到不确定的判定时
回查对应文档的完整规则。

**使用方式**：每个阶段开始前/结束后，逐项过清单。每项标 [x]（通过）或 [ ]
（未通过/待检查）。任何一项不通过 = 该阶段未完成，不允许进入下一阶段。这是
`iron-law.md` 第 1 条「禁止跳过章节闭环」在工程层面的落地。

**与各文档的关系**：
- `iron-law.md` 的七条铁律是全流程的底线约束——清单中的所有检查项都不得违反
  铁律。
- `anti-ai-style.md` 的 7 Gate 是正文质量的双重防线（机器 + 人工）——清单中
  「单章写后」阶段包含 7 Gate 的逐项自查。
- `outline-safety.md` 的大纲安全七检是大纲质量的审查层——清单中「大纲」阶段
  包含七检的逐项落地。
- `format-and-structure.md` 的 8 条绝对禁止是排版的硬约束——清单中「单章写后」
  和「发布前」阶段包含格式自查。

## 一、开书前检查清单（10 项）

开书前 = 确定选题、写总纲、做市场调研之后，正式进入大纲和正文之前。
此阶段检查的是「这本书能不能开」——商业可行性、核心设定、工程就绪。
参照 `commercial-core.md` 的卖点论和 `iron-law.md` 第 7 条（不替作者做决定）。

- [ ] 1. **核心卖点能一句话说清**：这本书的「读者为什么要看」可以用一句话
  表达，且不超过一句。（来源：`commercial-core.md` 核心卖点。一句话说不清 =
  卖点不聚焦，不要开。）

- [ ] 2. **差异化卖点至少一个、不超过三个**：与同题材竞品相比，至少有一个
  记忆点（设定/人设/金手指/视角/节奏差异），且不超过三个。（来源：
  `commercial-core.md` 差异化卖点。一个都没有 = 靠运气；超过三个 = 没有记忆点。）

- [ ] 3. **核心卖点通过持续性测试**：核心卖点能支撑 100 章不重复。问自己「这个
  卖点支撑 100 章后会怎样」——如果能通过，开书；如果到 30 章就没东西写了，
  考虑做中短篇。（来源：`commercial-core.md` 持续卖点。）

- [ ] 4. **金手指差距类型已确定且与人设匹配**：金手指是信息差/资源差/能力差
  中的哪种？与角色的核心矛盾匹配吗？（被看不起→能力差，被欺骗→信息差，被
  剥夺→资源差。来源：`commercial-core.md` 金手指原理。）

- [ ] 5. **金手指有局限设计**：金手指有上限/代价/克制/干扰——不能是无限无敌
  的。信息差型有不完整性，资源差型有消耗场景，能力差型有天花板。（来源：
  `commercial-core.md` 金手指原理的注意事项。）

- [ ] 6. **至少两种期待感同时在线**：对结果期待/对过程期待/对成长期待中，至少
  有两种在全书规划中同时在线。只有一种 = 该期待兑现后追读动力消失。（来源：
  `commercial-core.md` 三种期待感。）

- [ ] 7. **前 30 章留存设计已完成**：黄金三章（留人）+ 前 10 章（立人设）+
  前 30 章（亮底牌）三阶段规划已有具体落点，不是「到时候再说」。（来源：
  `commercial-core.md` 前 30 章留存设计。）

- [ ] 8. **升级体系台阶总数已定**：如果是有升级线的题材，总台阶数在总纲中
  已确定，逐卷消耗速度已规划。不能「写到哪算哪」。（来源：`commercial-core.md`
  崩盘模式之升级体系天花板。）

- [ ] 9. **题材选择与平台适配**：核心卖点在目标平台上成立（纯爽文不在晋江、
  慢热悬疑不在番茄等）。如不适配，已考虑换平台或换卖点。（来源：
  `commercial-core.md` 留存策略的平台差异。）

- [ ] 10. **题材卡与专属禁用词已就绪**：目标题材的题材卡已加载，专属禁用词已
  拷入 `设定/禁用词.txt`，`check_text.py` 能自动加载。（来源：`anti-ai-style.md`
  Gate A 题材专属禁用词。）

## 二、大纲检查清单（15 项）

大纲阶段 = 写完卷纲后、动笔写章纲和正文前。此阶段检查的是「这份大纲能不能用」
——结构合理性、节奏分布、伏笔计划、契约安全。
参照 `outline-safety.md` 的大纲安全七检，以及 `outline-structure-theory.md` 的
结构选择和 `iron-law.md` 第 2 条（禁止裸写正文）和第 6 条（禁止任意改主线）。

### 结构与核心（第 1-5 项，对应七检第一、二检）

- [ ] 1. **核心情绪有具体落点**：本卷读完，读者获得的核心情绪满足是什么？能
  说出「这卷最爽的是第 X 章的 Y」，不是笼统的「爽」。（来源：`outline-safety.md`
  第一检。说不出来 = 水卷。）

- [ ] 2. **核心冲突可一句话说清**：本卷的核心冲突是谁和谁的什么矛盾？与上一卷
  的冲突有递进（升级/转向/深化），不是重复。（来源：`outline-safety.md`
  第二检。无递进 = 原地踏步。）

- [ ] 3. **结构层级选择正确**：根据题材特征选了正确的结构层级（一级单元剧/
  二级套娃升维/三级统一结构），且与核心卖点匹配。（来源：
  `outline-structure-theory.md` 结构层级选择。选错 = 写到中期崩。）

- [ ] 4. **五幕因果链完整**：本卷的五幕（建立→上升→转折→高潮→结算）各有明确
  功能，不跳步。每幕的「必须完成的事」都已完成。（来源：
  `outline-structure-theory.md` 五幕式因果链。跳步 = 因果链断裂。）

- [ ] 5. **中点反转已设计**：到本卷 50% 位置，有一个改变方向的事件（原来以为
  的敌人是盟友/新势力介入/目标转向）。不是「半本书原地打转」。（来源：
  `outline-structure-theory.md` 第三幕转折期。）

### 节奏分布（第 6-8 项，对应七检第三、五检）

- [ ] 6. **快/中/慢档分布合理**：快档 ≤2-3 次，慢档每 3-4 章至少 1 章，中档
  占比 ≥60%，快档后有慢/中档缓冲，卷末有快档爆发。（来源：`outline-safety.md`
  第三检和 `pacing-and-hooks.md` 三档制。）

- [ ] 7. **章节定位高低错落**：每章标注了定位（高压/推进/修炼/关系/低压/整理），
  高压章不连续（间隔至少 2 章），每 3-4 章至少 1 章低压或关系章。（来源：
  `outline-safety.md` 第五检。全卷高压 = 读者疲劳，全卷低压 = 无聊。）

- [ ] 8. **A/B/C 配额已预声明**：本卷每章预声明触发 A/B/C 中的哪项（至多 1 项），
  且有冷却规则（触发 A 后 2 章不得再触发 A）。（来源：`pacing-and-hooks.md`
  A/B/C 配额和 `iron-law.md` 第 5 条。同时触发 ≥2 项 = 越界。）

### 伏笔与信息管理（第 9-11 项，对应七检第四、六检）

- [ ] 9. **伏笔埋设有清单且与台账一致**：本卷计划埋的伏笔有具体清单，计划回收
  的伏笔在台账中有对应 ID 且状态为活跃（🟡），新埋伏笔有预期回收窗口，与
  `追踪/伏笔台账.md` 双向核对一致。（来源：`outline-safety.md` 第四检和
  `foreshadowing.md` 台账状态机。）

- [ ] 10. **可释放/必须压住清单已制定**：本卷明确哪些信息/能力/关系可以释放给
  读者，哪些必须压住。可释放的与终局储备解锁节奏一致，必须压住的有压制手段。
  （来源：`outline-safety.md` 第六检。给早了透支，给晚了读者等不住。）

- [ ] 11. **八条线每条至少有 1 个锚点**：主线/感情线/升级线/势力线/世界线/
  伏笔线/角色弧/读者契约——八条线在本卷结束时都有推进（至少 1 个锚点）。
  某条线整卷无推进 = 这条线死了。（来源：`outline-structure-theory.md` 布局八条线。）

### 契约安全与核心审查（第 12-15 项，对应七检第七检 + 可证伪）

- [ ] 12. **读者契约安全评级通过**：代理权（关键节点是主角吗）、结算权（核心
  收益给主角了吗）、期待债（有偿还吗，有违约吗）、终局储备（透支两问——动用了
  不该解锁的底牌吗，升级线逼近天花板了吗）——四项检查全部合规或已补强。
  （来源：`outline-safety.md` 第七检。契约破坏 = 必须修纲，不可带病动笔。）

- [ ] 13. **删题材核心对象后故事不退化**：把本卷的题材核心对象（修仙体系/CP
  关系/核心谜题/权力博弈）删掉，故事是否退化为通用职业升级文？不退化 = 通过。
  （来源：`outline-safety.md` 可证伪降级检查一。退化 = 题材核心绑得不够深。）

- [ ] 14. **删主角后情绪兑现变化**：把主角从大纲中删掉，情绪兑现是否不变？
  变了 = 通过。不变 = 主角是摄像头，须补主角因果链。（来源：`outline-safety.md`
  可证伪降级检查二。）

- [ ] 15. **核心梗单一且未漂移**：全书只有一个核心梗，所有情节单元都在核心梗
  的不同侧面。本卷的情节单元都能回答「这个单元在核心梗的哪个侧面」。（来源：
  `commercial-core.md` 核心梗。核心梗漂移 = 读者困惑。）

## 三、单章写前检查清单（10 项）

单章写前 = 拿到章纲后、正式动笔写正文前。此阶段检查的是「这一章的准备是否
就绪」——章纲是否完整、上下文是否衔接、追踪文件是否同步。
参照 `iron-law.md` 第 1 条（禁止跳过章节闭环）和第 2 条（禁止裸写正文）。

- [ ] 1. **章纲已就绪**：本章有完整章纲（情节点清单 + 档位声明 + A/B/C 预声明
  + 章尾钩子设计）。无章纲不写正文。（来源：`iron-law.md` 第 2 条。章纲缺失 =
  先补纲。）

- [ ] 2. **上一章追踪文件已全部更新**：摘要/角色状态/伏笔台账/时间线/节奏配额
  五文件全部更新完毕。有欠账先补账，禁止带欠账开写。（来源：`iron-law.md`
  第 1 条欠账门。可用 `scripts/resume.py {书}` 核验。）

- [ ] 3. **上一章的章尾钩子已确认**：本章开头 10% 内要接住上一章的钩子。已确认
  上一章的钩子是什么，本章如何承接。（来源：`pacing-and-hooks.md` 单章结构通式
  之「承接」。不写「上一章说到」，用动作或对话把读者带回情境。）

- [ ] 4. **档位已声明且与近 3 章分布合理**：本章档位（慢/中/快）已写入章纲批注。
  快档后不接快档（至少 1 章缓冲），连续 2 章快档 = 需插入慢档。（来源：
  `pacing-and-hooks.md` 三档制。）

- [ ] 5. **A/B/C 配额已预声明且未越界**：本章预声明触发 A/B/C 中的哪项（至多 1
  项）或「不触发」。已检查冷却期（如上一章触发 A，本章不得再触发 A）。（来源：
  `pacing-and-hooks.md` A/B/C 配额和 `iron-law.md` 第 5 条。）

- [ ] 6. **本章伏笔状态已检查**：扫一眼台账的 🟡（活跃）和 🔴（超期），确认本章
  有没有该推进/回收的伏笔。有则写进本章速记，无则确认「本章确实不需要」。
  （来源：`foreshadowing.md` 检索纪律。）

- [ ] 7. **本章核心情绪已确认**：本章要交付什么情绪（爽/虐/甜/燃/悬）？蓄积
  够了吗？如果本章是爆发章，前文的蓄积是否到位？（来源：`emotion.md` 蓄积→
  爆发→余韵。没蓄够就爆发 = 哑炮。）

- [ ] 8. **本章场景和 POV 已规划**：本章发生在什么场景？谁的 POV？如果有多 POV
  切换，切换信号已设计。如果是群像场景，角色功能已分配。（来源：
  `plot-special-topics.md` 多 POV 切换和群像场景管理。）

- [ ] 9. **本章不违反一章清光铁律**：非终局章节不解决核心矛盾。本章有情节点
  结算（读者得到了什么），但核心矛盾不清光。本章至少留下 1 个章尾钩子，至少
  新增 1 个未解决的次要问题。（来源：`iron-law.md` 第 4 条。）

- [ ] 10. **本章字数范围已确认**：本章字数在平台要求的范围内（番茄 2000-2500、
  起点 2000-3000、晋江 3000 上下）。章纲的情节点密度与字数匹配——不是把 5000
  字的内容塞进 2000 字的章里。（来源：`format-and-structure.md` 平台差异表和
  `commercial-core.md` 平台适配。）

## 四、单章写后检查清单（15 项）

单章写后 = 正文初稿完成后、更新追踪文件前。此阶段检查的是「这一章写得怎么样」
——AI 腔、格式、节奏、追踪、铁律。
参照 `anti-ai-style.md` 的 7 Gate、`format-and-structure.md` 的 8 条绝对禁止、
`iron-law.md` 第 1 条（章节闭环）。

### 7 Gate 去 AI 腔（第 1-7 项）

- [ ] 1. **Gate A 禁用词已清除**：叙述中无一级禁用词（仿佛/似乎/不禁/不由得/一丝/
  眼底闪过/嘴角勾起/映入眼帘/心中暗道/沉声道/淡淡地说等）。对话中的禁用词降为
  advisory，按读感判断。已跑 `check_text.py --gate-report`，blocking 命中已清零。
  （来源：`anti-ai-style.md` Gate A。）

- [ ] 2. **Gate B 毒句式已清除**：无「不是A而是B」「没有X只有Y」「这一刻，」
  「带着…」「声音不大，却带着…」「之所以…是因为」「他知道…」等高置信度
  AI 句式。修饰词已清扫（一个名词前不用多个形容词）。（来源：`anti-ai-style.md`
  Gate B。）

- [ ] 3. **Gate C 心理描写已外化**：无直接陈述情绪（「他很紧张」「她很愤怒」「她
  心中涌起莫名情绪」）。情绪用生理反应 + 动作 + 选择展示。（来源：
  `anti-ai-style.md` Gate C 和 `emotion.md`「给形状不给名词」、`writing-craft-extras.md`
  身体细节替代。）

- [ ] 4. **Gate D 节奏已调整**：句式不机械等长，段落长短交错。无连续排比句、无
  臃肿修饰堆叠。高潮/打脸压到最短（单句成段），推理/氛围保留长段，过场写疏。
  （来源：`anti-ai-style.md` Gate D 和 `format-and-structure.md` 长短交错规则。）

- [ ] 5. **Gate E 对话声线有差异**：遮住名字重读对话，能认出谁在说话。对话中
  有口语化表达，有动作穿插，无解释性对话（角色不解释自己的动机）。（来源：
  `anti-ai-style.md` Gate E 和 `dialogue.md` 遮名认人测试。）

- [ ] 6. **Gate F 结尾无升华**：章尾无总结性语句（「这次经历让他成长了」）、无
  感慨收尾。用动作/场景收尾，不用「他知道…」「这一刻…」收尾。章尾有钩子且
  自然。（来源：`anti-ai-style.md` Gate F。）

- [ ] 7. **Gate G 无解释腔/上帝感**：无「她不知道的是」「殊不知」「多年以后」
  等上帝剧透；无替读者定性（「演得真好」「这出戏她看过一遍」）；无软评判和
  安排感。（来源：`anti-ai-style.md` Gate G。删的是非故事性作者旁白，不是删情节。）

### 格式与排版（第 8-10 项）

- [ ] 8. **段落按戏剧单元断开**：段落不是机械按字数切，是按戏剧单元（动作链
  闭合/线索发现落地/情绪变化拐点/视线切换/新信息入场）断。无通篇等长段落。
  相邻段落间只有一个 `\n`，无空行。（来源：`format-and-structure.md` 第 1-2 条。）

- [ ] 9. **对话标签和标点合规**：对话标签不机械化（不每句都「他说」「她道」），
  四种位置轮换。无破折号 `——`，无标点堆砌（`!!!`/`???`/`……` 连用），标点跟
  语气走。正文无 Markdown 格式，无全角空格缩进，无工程元信息词。（来源：
  `format-and-structure.md` 第 3-8 条。）

- [ ] 10. **对话引号和章节标题符合平台约定**：番茄用 `""` + `###第X章`，盐言用
  `「」` + `1.`。全文统一一种格式，不混用。（来源：`format-and-structure.md`
  平台差异表。）

### 节奏与结构（第 11-13 项）

- [ ] 11. **四拍结构完整**：承接（接住上章钩子）→ 发展（核心事件展开）→ 结算
  （给读者交代）→ 钩子（章尾至少 1 个）。章尾钩子能用一句话描述，且与下一章
  兑现。（来源：`pacing-and-hooks.md` 单章结构通式和钩子纪律。）

- [ ] 12. **A/B/C 配额未越界**：本章至多触发 A/B/C 中的 1 项。同时触发 ≥2 项 =
  越界，须改纲重写。快档章后下一章须是慢档或中档。（来源：`iron-law.md` 第 5 条
  和 `pacing-and-hooks.md` A/B/C 配额。已跑 `rhythm_guard.py`，无越界。）

- [ ] 13. **本章删掉后后续会受影响**：本章删掉后，后续章节会受影响吗？不受影响 =
  注水章。非冲突场景有微型伏笔吗？没有 = 水章。（来源：`pacing-and-hooks.md`
  防注水六种伪装和节奏自检。）

### 追踪与闭环（第 14-15 项）

- [ ] 14. **追踪五文件已全部更新**：章摘要/角色状态/伏笔台账/时间线/节奏配额
  全部更新完毕，与本章正文同步。更新前不视为章节完成。（来源：`iron-law.md`
  第 1 条章节闭环。）

- [ ] 15. **机器闸口全部通过且已落盘**：`check_text.py --gate-report` 全部通过
  （blocking 清零，advisory 按读感判断），`rhythm_guard.py` 无越界，
  `normalize_punct.py` 已跑。门禁状态已落盘。（来源：`anti-ai-style.md` 写完一章
  的自查流程和 `iron-law.md` 第 1 条。）

## 五、卷末检查清单（10 项）

卷末 = 一卷正文全部写完、即将进入下一卷或下一阶段时。此阶段检查的是「这一卷
的整体质量」——卷级节奏、伏笔回收、契约履行、结构完整。
参照 `outline-safety.md` 的七检（卷级审查）和 `commercial-core.md` 的崩盘预警。

- [ ] 1. **卷级核心情绪已交付**：读者读完本卷，能说出「这卷最爽/最虐/最燃的是
  什么」。核心情绪有具体落点（哪一章的哪个事件），有足够蓄积，与读者契约一致。
  （来源：`outline-safety.md` 第一检。）

- [ ] 2. **核心冲突有起承转合且已递进**：本卷核心冲突从建立到爆发到结算，走完
  了完整弧线。与上一卷相比有递进（升级/转向/深化），不是重复上卷的冲突模式。
  （来源：`outline-safety.md` 第二检。）

- [ ] 3. **卷末有结算感和下卷钩子**：卷末主矛盾总爆发 + 余韵交付（旁观者反应/
  主角回味/局势变化）+ 下卷钩子（新地图/新对手/新秘密）。卷末是读者「弃书 or
  养书」决策点，要给足「这一卷值了」的结算感。（来源：`pacing-and-hooks.md`
  卷节奏和 `outline-structure-theory.md` 第五幕结算期。）

- [ ] 4. **伏笔回收计划已执行**：本卷计划回收的伏笔已全部回收，无 🔴（超期）
  遗留。新埋的伏笔有预期回收窗口。只埋不收的伏笔数量不超过新埋数的 50%（参照
  `foreshadowing.md`「只埋不收是庞氏骗局」）。（来源：`outline-safety.md` 第四检
  和 `foreshadowing.md` 密度常识。）

- [ ] 5. **八条线每条都有推进**：主线/感情线/升级线/势力线/世界线/伏笔线/
  角色弧/读者契约——八条线在本卷结束时都有至少 1 个锚点推进。某条线整卷
  无推进 = 这条线死了，需在下一卷补救或调整。（来源：`outline-structure-theory.md`
  布局八条线。）

- [ ] 6. **角色关系未固化**：本卷主要角色间的关系发生了至少一次变化（距离拉近/
  拉远/质变）。关系不变化 = 关系固化 = 后续无新冲突可写。（来源：
  `commercial-core.md` 崩盘模式之角色关系固化。）

- [ ] 7. **升级体系未逼近天花板**：主角的升级消耗速度在计划内，未逼近总台阶数
  的天花板。如果已逼近，确认是否在终局储备的计划释放范围内。（来源：
  `commercial-core.md` 崩盘模式之升级体系天花板。）

- [ ] 8. **读者契约安全**：本卷的代理权（关键节点是主角）、结算权（收益给主角）、
  期待债（有偿还无违约）、终局储备（未透支）四项均合规。评论区无「越来越水」
  「主角越来越弱/蠢」等预警信号。（来源：`outline-safety.md` 第七检和
  `commercial-core.md` 崩盘预警信号。）

- [ ] 9. **快档配额未超限**：本卷快档章不超过 2-3 次。快档之间有足够间隔。
  没有连续 2 章快档。卷末爆发后有余韵章（至少 1 章低压整理章）。（来源：
  `outline-safety.md` 第三检和 `pacing-and-hooks.md` 卷级档位分布。）

- [ ] 10. **世界观未膨胀失控**：本卷新增的设定区域不超过 1 个（设定冻结线）。
  旧角色和旧设定没有被遗忘。没有出现「设定太多看不懂」的读者反馈。（来源：
  `commercial-core.md` 崩盘模式之世界观膨胀和防御手段。）

## 六、发布前检查清单（10 项）

发布前 = 正文定稿后、正式上传平台前。此阶段检查的是「这批内容能不能发」
——最终质量、格式规范、平台合规、工程清洁。
参照 `format-and-structure.md` 的平台差异表和 `iron-law.md` 第 3 条（禁止混淆
正文与元信息）。

- [ ] 1. **7 Gate 机器闸口全通过**：所有待发布章节跑完 `check_text.py --gate-report`，
  blocking 全部清零。advisory 按读感判断，确属问题的已修改。（来源：
  `anti-ai-style.md` 写完一章的自查流程。机器闸口是第一道防线。）

- [ ] 2. **标点已归一化**：所有待发布章节跑完 `normalize_punct.py`。省略号 `……`、
  破折号 `——`、感叹堆叠 `!!!`、分隔线、全角空格等已清理。（来源：
  `format-and-structure.md` 与 `normalize_punct.py` 的关系。机器兜底。）

- [ ] 3. **格式 8 条绝对禁止全部通过**：段落按戏剧单元断开、无段间空行、对话标签
  不机械、无缩进、无 Markdown 混入正文、无破折号、标点跟语气走、无工程元信息
  混入。（来源：`format-and-structure.md` 8 条绝对禁止。逐章过一遍。）

- [ ] 4. **对话引号和章节标题符合平台约定**：番茄 `""` + `###第X章`，起点 `""` +
  无标题行，晋江 `""` + 纯文本标题，盐言 `「」` + `1.` 编号。全文统一，不混用。
  （来源：`format-and-structure.md` 平台差异表。）

- [ ] 5. **正文无工程元信息泄漏**：正文中无 `[说明]`/`（注：）`/`TODO`/`作者按`/
  `PS：`/`本章`/`上一章`/`伏笔`/`细纲`/`读者`等工程词。故事内真实阅读/讨论
  「第X章」的语境除外，但需人工确认并用 `<!-- 闸口:跳过 -->` 豁免。（来源：
  `iron-law.md` 第 3 条和 `format-and-structure.md` 第 8 条。）

- [ ] 6. **章尾钩子环环相扣**：每章章尾钩子在下一章开头 10% 内接住。无虚晃钩子
  （章尾吓人、下章发现是误会/做梦）——全书最多用 1-2 次。（来源：
  `pacing-and-hooks.md` 章尾钩子纪律。）

- [ ] 7. **角色称谓和设定前后一致**：同一角色的称呼前后一致（尤其历史题材，
  称谓是考据硬点）。设定名词（地名/功法/品阶/组织名）前后一致，无矛盾。
  （来源：`character-consistency.md`。可用 `scripts/check_text.py` 辅助检查。）

- [ ] 8. **伏笔台账与正文同步**：台账中所有 🟡（活跃）伏笔的状态与正文一致——
  正文里推进了的伏笔，台账已更新到对应章节。无 🔴（超期）伏笔遗漏未处理。
  （来源：`foreshadowing.md` 台账状态机和 `iron-law.md` 第 1 条。）

- [ ] 9. **字数符合平台要求**：每章字数在平台要求的范围内。无过长章（超出平台
  上限被截断）或过短章（低于平台下限影响推荐）。（来源：`format-and-structure.md`
  平台差异表和 `commercial-core.md` 平台适配。）

- [ ] 10. **开篇三章（如果是新书上架）通过开篇自检**：第一页 300 字内有压力源
  或冲突信号；第一章出场有名字的人物 ≤4 个；主角在三章内做过主动选择；第三章
  结束时读者已得到过一次兑现；章尾钩子 1→2→3 环环相扣。（来源：`opening.md`
  开篇自检清单。仅新书上架时检查。）

## 检查流程总览

```
开书前检查（10 项）
  ├─ 不通过 → 修核心设定/换卖点/换平台
  └─ 通过 ↓
大纲检查（15 项）
  ├─ 不通过 → 回卷纲修补对应项（参照 outline-safety.md 修复指引）
  └─ 通过 ↓
单章写前检查（10 项）→ 写正文 → 单章写后检查（15 项）
  ├─ 7 Gate 不通过 → 逐 Gate 修改（参照 anti-ai-style.md 分级处理策略）
  ├─ 格式不通过 → 逐条修改（参照 format-and-structure.md）
  ├─ 节奏越界 → 改纲重写（参照 iron-law.md 第 5 条）
  ├─ 追踪未更新 → 补更新后再进入下一章
  └─ 全通过 ↓
（循环：每章重复「写前→写正文→写后」）
  ↓
卷末检查（10 项）
  ├─ 不通过 → 卷级修补或调整下一卷规划
  └─ 通过 ↓
发布前检查（10 项）
  ├─ 不通过 → 逐项修改后重新检查
  └─ 通过 → 发布
```

**纪律**：每个阶段的检查不可跳过。跳过检查 = 带病进入下一阶段，后面的问题会
指数级放大——`outline-safety.md` 的原话：「一个卷纲的结构缺陷会在每章都体现，
修复成本是卷纲阶段的 N 倍。」`iron-law.md` 的原话：「铁律的存在是为了防止长篇
连载中小问题指数级放大的慢性死亡。」
