# 时间行动与物件归属专项审计

仅在章输入、章意图或授权动作触发时间压力、并行汇合或物件交接条件时必读全文；具体加载门见
`references/craft/scene-rendering.md` 与 `references/workflow/chapter-loop.md` Step 3A。未触发时不默认加载。

本文件维护专项规则正文，不能拿规则摘要替代；独立 Agent 需要实际内容。通用正文证据、转折因果、
事件授权与正式提交仍执行上述两文件。只做授权内的最小修复，不新增持久 schema；共享现有最多两轮
修复额度，不因专项重开预算。下面的顺序错误仍属于既有 blocking/P0，不以工艺评分覆盖。

## 专项规则

以下可行性与时间均按作品内设定判断，见 `references/craft/fictional-world.md`。
“合法时间来源”意为有授权/设定依据的来源，可为系统倒计时、法阵计时或神识感知；不局限于现实设备。
已有瞬移、时间暂停或秘境倍率时按其明确适用范围核算，不强套现实耗时；仍核对既定前置条件和代价。

### 动作预算

在倒计时或窗口期下，明确区分串行动作、并行动作和可压缩的常规办理；保留决定性行动与必要验收。
动作链无法容纳时，重组授权动作或阻断；不得模糊时间、让技术步骤瞬间完成，或造出未授权设备。

### 时间行动闭环

输入明确给出倒计时、截止时刻、窗口期，或关键行动的可行性依赖耗时时，先锁定输入、项目设定或
现场已建立事实提供的合法时间来源。不得为了补时间感而新增或擅造具有测时功能的计时器、刻度、
仪表、提示音或外部通知。

从合法报时、物理/程序阻力、可观察过程进展、并行行动的汇合、必要验收的等待中选择自然的时间证据；
至少一项时间证据须改变后续行动的取舍、分工、顺序、风险判断或验收。完稿后检查读者能否判断哪一步
或哪段等待消耗了窗口，以及时间变化为何促成此刻的下一项选择。承担主要窗口消耗的串行或并行分支，
不得只写起点和完成口令；须用授权动作中的中间进展、阻力变化或累积身体/环境反馈，让读者能重建该分支
如何耗时；不得为此新增动作、工具、事实或机械报时。没有可见时钟时，可只用已建立的
过程、环境或身体信号；不设最低报秒次数、固定时间锚点频率、动作数量或句式模板。

若输入或 `on_page_requirements` 把受保护下游动作或状态锁在多个前置分支的汇合条件之后，并行准备
仅可推进到汇合屏障。全部前置条件满足之前，任一分支的中间效果不得提前触发或造成受保护下游动作
或状态变化。若准备动作本身会触发该变化，须在授权事实内保持受保护状态不发生，改为串行或重组；
无法解决则阻断。提前触发属于既有顺序错误，按 blocking/P0 处理，不新增 P0 类别。

只有输入明确把受保护下游动作指定为多名参与者共同或同时执行时，汇合完成只解除前置屏障；全部指定
参与者就位前，任何一人不得单独启动，动作须从起始即共同或同时执行。“一人先启动、他人随后加入”
仍属于既有顺序错误，按 blocking/P0 处理。

若输入明确限定倒计时或显式报时只在改变程序或行动选择时出现，保留的显式读数须逐条改变后续
取舍、分工、顺序、风险判断或验收；只报进度的读数删去，或改用非计时证据，如阻力、过程进展、
并行汇合、验收等待。输入未作此限定时，仍只要求整体至少一项时间证据改变行动，不扩张为逐条义务。
现场已有合法倒计时且限时行动跨越多个阶段时，若后续某个剩余时间读数会实际改变行动范围、风险判断或
验收选择，须在该决策点呈现该读数；不得以避免机械报时为由省略有功能的后续读数。若后续没有新的选择
变化，则不新增读数；仍不设最低报时次数。
只有上述显式报时/读数功能违例且没有独立 P0 时，才归 P1、不阻断；若同时命中任何既有 P0 条件，P0 优先。
上述显式报时/读数 P1 的 `minimal_fix` 只处理该读数：纯进度读数删除或替换为非计时过程证据；遗漏有功能的
后续读数只在对应决策点补入来自既有合法时间来源的读数；不得改写无关动作或新增工具。其他类别按各自问题作最小修复。

### 物件归属

物件递交、夺回、放置、锁定或遗失后，在再次依赖该物件前应能唯一判断持有者或位置。只修主体、动词或位置指代，
不得新增未经授权的转手。
