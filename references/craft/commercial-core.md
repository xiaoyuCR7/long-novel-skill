# 商业创作核心方法

本文件是商业网文创作的**顶层方法论**。`reader-contract.md` 管读者契约的具体规则，
`pacing-and-hooks.md` 管节奏的结构原则，`platform-guide.md` 管各平台的差异基线——
本文件管的是**在这一切之上，一本书为什么能卖、为什么有人追、为什么不崩**。

分工：选题/开书/做总纲时查本文件定商业框架；具体章节的执行查其他文件。本文件是
「为什么要写这本书」层面的方法，不是「这一章怎么写」层面的方法。

## 卖点论

一本书的商业价值 = 它的卖点能不能支撑读者追完百万字。卖点分三层。

### 核心卖点（一句话说清）

核心卖点 = 这本书最根本的「读者为什么要看」。必须一句话说清，超过一句说明卖点
不聚焦。

| 类型 | 核心卖点示例 | 一句话测试 |
|---|---|---|
| 爽文 | 一个被废了修为的少爷获得逆天传承 | 能一句话说清「爽在哪」 |
| 甜文 | 冷面总裁与替嫁新娘的先婚后爱 | 能一句话说清「甜在哪」 |
| 悬疑 | 刑警追查十年前妹妹失踪案牵出连环阴谋 | 能一句话说清「谜在哪」 |
| 燃文 | 末世废柴觉醒唯一SSS级火系异能 | 能一句话说清「燃在哪」 |

**一票否决**：如果核心卖点说不清，这本书不要开。核心卖点模糊 = 不知道在卖什么 =
读者不知道在追什么 = 前十章流失。

### 差异化卖点（区别于同题材竞品）

差异化卖点 = 这本书与同题材竞品的不同之处。在核心卖点已确定的前提下，差异化决定
读者「为什么看这本而不是那一本」。

差异化的来源：
- **设定差异**：同样是修仙，别人的修仙世界有灵气衰退，你的有灵气暴走
- **人设差异**：同样是霸总，别人的霸总是真冷酷，你的是装冷酷实则社恐
- **金手指差异**：同样是系统，别人的系统给任务，你的系统只给差评
- **视角差异**：同样是大女主，别人的从宫斗开始，你的从商战开始
- **节奏差异**：同样是悬疑，别人的慢热推理，你的快节奏反转

**纪律**：差异化卖点至少一个，不超过三个。一个都没有 = 换皮书，靠运气；超过三个 =
没有记忆点，读者记不住。

### 持续卖点（支撑百万字）

持续卖点 = 核心卖点的可重复兑现能力。一个核心卖点如果只能兑现一次，就不是持续
卖点，是短篇点子。

| 核心卖点 | 持续性测试 | 通过/不通过 |
|---|---|---|
| 获得逆天传承 | 这个传承能支撑多少次「碾压」？ | 通过：升级体系有N阶，每阶有新对手 |
| 先婚后爱 | 婚后爱了之后还卖什么？ | 不通过（需要扩展：加商战/家族冲突） |
| 追查妹妹案 | 案子破了之后还卖什么？ | 不通过（需要扩展：牵出更大阴谋） |
| SSS级火系异能 | 异能到顶后还卖什么？ | 通过：异能进化路线+末世地图层级 |

**测试方法**：问自己「这个卖点能支撑100章不重复吗？」如果不能，要么扩展卖点维度，
要么把这本书做成中短篇（见 `platform-guide.md` 短篇平台）。

## 金手指原理

金手指是网文的核心商业引擎。理解金手指的本质，才能设计出有效果的金手指。

### 金手指的本质：三种差

金手指的本质不是「外挂」，而是制造主角与世界的**差距**。差距有三种类型，每种
决定不同的爽感：

| 差距类型 | 定义 | 爽感类型 | 典型金手指 |
|---|---|---|---|
| 信息差 | 主角知道别人不知道的 | 智商碾压/预判爽 | 重生回溯/系统提示/前世记忆 |
| 资源差 | 主角拥有别人没有的 | 底气碾压/资源爽 | 随身空间/无限财富/特殊血脉 |
| 能力差 | 主角能做到别人做不到的 | 实力碾压/战斗爽 | 逆天功法/特殊异能/超规格天赋 |

### 差距类型决定爽感设计

不同差距类型的爽感兑现方式不同：

**信息差型金手指**的爽感来自「预判」：
- 主角提前知道对手的底牌/陷阱/弱点
- 爽点设计：对手自以为隐蔽的计划被主角轻松看穿
- 注意：信息差型金手指容易写崩——信息差太大=主角无敌=没张力。必须给信息差设
  局限（信息不完整/有时效/有干扰）

**资源差型金手指**的爽感来自「底气」：
- 主角不缺钱/不缺药/不缺装备
- 爽点设计：别人争破头的东西主角随手拿出来
- 注意：资源差型金手指容易写无聊——纯堆资源没有技术含量。必须给资源消耗设场景
  （资源有上限/有副作用/有竞争者）

**能力差型金手指**的爽感来自「碾压」：
- 主角的战斗力/技能远超同级
- 爽点设计：越级挑战/以一敌众/秒杀
- 注意：能力差型金手指容易写腻——一直碾压=爽感钝化。必须给能力设天花板
  （有上限/有代价/有克制）

### 金手指与人设的绑定

金手指不能脱离人设独立存在（详见 `character-design.md` 的「金手指绑架人设」）。
商业层面补充一点：**金手指的差距类型应与角色的核心矛盾匹配**。

| 角色核心矛盾 | 适合的差距类型 | 逻辑 |
|---|---|---|
| 被看不起→想证明自己 | 能力差 | 用实力碾压证明价值 |
| 被欺骗→想要掌控 | 信息差 | 用预判掌控局面 |
| 被剥夺→想要安全感 | 资源差 | 用资源底气消除不安 |
| 被控制→想要自由 | 能力差+资源差 | 双重差距打破束缚 |

金手指与矛盾不匹配 = 读者觉得「这个金手指给谁都行」，角色与金手指的关系是松散的，
代入感不足。

## 三种期待感

读者追读一本书，期待的是三种东西。一本书至少要保持两种期待感同时在线。

### 三种期待感

| 期待类型 | 定义 | 驱动力 | 兑现方式 |
|---|---|---|---|
| 对结果期待 | 「最后会怎样」 | 悬念 | 结局揭晓/胜负分晓 |
| 对过程期待 | 「TA会怎么做」 | 手法 | 主角的具体操作/策略 |
| 对成长期待 | 「TA会变多强」 | 升级 | 境界提升/能力进化 |

### 期待感的保持纪律

- **至少两种在线**：只有一种期待感的书会在该期待兑现后立刻失去追读动力
  - 只有结果期待 = 悬疑推理，案子破了就结束（适合短篇，不适合长篇）
  - 只有过程期待 = 智斗/权谋，对手没了就结束
  - 只有成长期待 = 纯升级流，到顶了就结束
- **三种同时在线最强**：主角在变强（成长期待）的过程中用独特手法（过程期待）去
  解决一个最终悬念（结果期待）
- **期待感交替**：某一时刻主打一种，其余两种做副线。不要求三种平均分配，但不能
  让任何一种完全消失超过10章

### 期待感与卖点的关系

| 核心卖点 | 主打期待感 | 辅助期待感 |
|---|---|---|
| 爽文/升级流 | 对成长期待 | 对过程期待 |
| 悬疑/推理 | 对结果期待 | 对成长期待（主角能力成长） |
| 权谋/智斗 | 对过程期待 | 对结果期待 |
| 言情/甜文 | 对结果期待（CP能否在一起） | 对过程期待（怎么走到一起） |

## 崩盘原因

网文崩盘不是随机事件，而是可预测的结构性失效。以下是五种最常见的崩盘模式。

### 五大崩盘模式

| 崩盘模式 | 根因 | 前兆症状 | 不可逆点 |
|---|---|---|---|
| 核心矛盾过早解决 | 主线Boss/谜题在前期就被解决 | 主角已无对手，开始找新敌人 | 原Boss被击败后无法恢复张力 |
| 角色关系固化 | 主要角色间的关系不再变化 | 感情线已确认/敌我阵营已固定 | 关系不再产生新冲突 |
| 世界观膨胀失控 | 设定越加越多，收不回来 | 地图越开越大，旧角色/旧设定被遗忘 | 读者已经跟不上设定量 |
| 升级体系天花板 | 主角已到最高级，无法再升 | 升级速度明显放缓或停滞 | 到顶后战斗失去悬念 |
| 读者契约透支 | 期待债违约/终局底牌提前打光 | 读者评论开始出现「越来越水」 | 弃书潮形成，数据不可恢复 |

### 崩盘的预警信号

在崩盘的「不可逆点」到来之前，通常有3-5卷的预警期。预警信号：

- **追读数据下降但收藏还在涨**：新读者还在进，但老读者开始弃 → 早期问题，可修复
- **追读和收藏同时下降**：老读者弃+新读者不进 → 中期问题，修复成本高
- **评论区开始出现「越来越水」「没以前好看了」**：节奏/注水问题 → 检查注水六种伪装
  （见 `pacing-and-hooks.md`）
- **评论区开始出现「看不懂了」「设定太多」**：世界观膨胀 → 停止加新设定，收束旧设定
- **评论区开始出现「主角越来越弱/越来越蠢」**：代理权泄漏或能力 OOC → 检查
  `reader-contract.md` 的四问

### 防崩盘的工程化手段

| 崩盘模式 | 防御手段 | 检查工具 |
|---|---|---|
| 核心矛盾过早解决 | `reverse-brake.md` 的 A/B/C 配额 + 终局储备管理 | 卷末契约体检（`reader-contract-deep.md`） |
| 角色关系固化 | 每10章至少一次关系距离变化 | 角色状态文件的关系字段 |
| 世界观膨胀 | 设定冻结线：每卷最多加1个新设定区域 | 总纲的设定清单核对 |
| 升级体系天花板 | 开书定台阶总数，逐卷控制消耗速度 | `reader-contract-deep.md` 的剩余档数管理 |
| 读者契约透支 | 每章契约安全评级 + 透支两问 | `reader-contract.md` 执行清单 |

## 核心梗

### 核心梗的定义

核心梗 = 一本书所有情节单元共同服务的那个「核」。它不是核心卖点（核心卖点是给读者
的承诺），而是**内部叙事的统一主题**。

核心梗与核心卖点的区别：
- 核心卖点（对外）：「被废少爷获得逆天传承」——这是给读者的钩子
- 核心梗（对内）：「弱者的逆袭」——这是所有情节单元的主题

所有情节单元都应该是核心梗的不同侧面：
- 打脸情节 → 核心梗的「弱者反强」侧面
- 修炼情节 → 核心梗的「弱者变强」侧面
- 感情情节 → 核心梗的「弱者被看见」侧面
- 势力情节 → 核心梗的「弱者聚人」侧面

### 一本书只有一个核心梗

**纪律**：一本书只能有一个核心梗。多个核心梗 = 没有核心梗 = 情节单元各写各的 =
读者感到「这本书在讲什么」的困惑。

常见违规：
- 前30章核心梗是「逆袭」，30章后变成「种田」→ 核心梗漂移
- A线核心梗是「复仇」，B线核心梗是「恋爱」→ 两条线的情节单元互相干扰
- 核心梗不清：「这个角色成长的故事」太泛，不是核心梗

### 核心梗的自检

写每个情节单元前问：这个单元在核心梗的哪个侧面？如果答不上来，这个单元要么是
水章（与核心梗无关），要么是核心梗漂移（在写另一个梗）。

```
核心梗自检：
  本书核心梗：{一句话}
  本章情节单元：{一句话}
  核心梗侧面：{这个单元在核心梗的哪个侧面？}
  如果删掉这个单元，核心梗的哪个侧面会缺失？
```

## 留存四大支柱

读者为什么不弃书？因为四大支柱在同时起作用。

### 四大支柱

| 支柱 | 定义 | 驱动力 | 维护工具 |
|---|---|---|---|
| 追读动力 | 读者想看「下一章发生什么」 | 钩子 | `pacing-and-hooks.md` |
| 情感投入 | 读者对角色有感情 | 角色 | `character-design.md` |
| 世界探索欲 | 读者想了解这个世界的更多 | 设定 | 世界观文档（题材卡） |
| 期待兑现 | 读者看到承诺在兑现 | 契约 | `reader-contract.md` |

### 四大支柱的失衡诊断

| 失衡模式 | 症状 | 处方 |
|---|---|---|
| 钩子足但角色薄 | 读者追得快但不投入，弃书也快 | 补角色深度（`character-design.md`） |
| 角色好但钩子弱 | 读者喜欢角色但不追更，养书 | 加强钩子密度（`pacing-and-hooks.md`） |
| 设定厚但兑现慢 | 读者觉得世界观有趣但等不到兑现 | 加快期待兑现频率 |
| 兑现快但设定薄 | 读者爽完就走，没有长线黏性 | 补长线设定（伏笔/终局储备） |

**健康状态**：四大支柱均衡，没有明显短板。不要求四项等强，但不能有任何一项
低于「及格线」——及格线 = 读者不会因为这个原因弃书。

## 前30章留存设计

前30章是新读者留存的关键窗口。分三个阶段。

### 黄金三章（第1-3章）：留人

- **目标**：让读者从「点开」到「追更」
- **核心任务**：亮核心卖点 + 立主角人设 + 第一个钩子
- **纪律**：
  - 第1章必须出现核心冲突（不铺垫，直接进冲突）
  - 第1章必须展示金手指（不藏着，亮出来让读者看到差距）
  - 第3章必须给第一个小爽点（兑现核心卖点的承诺）
  - 三章内必须让读者知道「这本书在卖什么」

### 前10章（第4-10章）：立人设

- **目标**：让读者对主角产生情感投入
- **核心任务**：展示三层标签的前两层 + 建立核心关系 + 第一个剧情单元
- **纪律**：
  - 10章内主角的三层标签至少展示表面和真实两层
  - 至少建立1个核心关系（盟友/对手/感情对象）
  - 第一个剧情单元完成（蓄积→爆发→余韵的完整循环）
  - 第一个伏笔埋下并推进（不回收，只推进）

### 前30章（第11-30章）：亮底牌

- **目标**：让读者看到这本书的持续卖点
- **核心任务**：展示升级体系 + 扩展世界观 + 核心期待开始偿还
- **纪律**：
  - 30章内升级体系必须完整展示（读者看到成长路线）
  - 至少2个剧情单元完成，证明核心梗可以持续
  - 核心期待债开始偿还（不是全还，是开始还，证明作者不会欠债不还）
  - 终局储备的冰山一角露出（不揭露，只暗示有更大的东西）

### 前30章的留存检查

```
前30章留存检查：
  黄金三章：
    [ ] 第1章有核心冲突
    [ ] 第1章展示了金手指
    [ ] 第3章有第一个小爽点
    [ ] 三章内说清了核心卖点
  前10章：
    [ ] 主角三层标签展示了前两层
    [ ] 建立了至少1个核心关系
    [ ] 第一个剧情单元完成
    [ ] 第一个伏笔已埋+推进
  前30章：
    [ ] 升级体系完整展示
    [ ] 至少2个剧情单元完成
    [ ] 核心期待债开始偿还
    [ ] 终局储备冰山一角露出
```

## 与 platform-guide.md 的衔接

`platform-guide.md` 定义了各平台的基线差异（章长/更新/读者偏好/审核）。本文件
补充：同一套商业核心方法在不同平台的**留存策略差异**。

### 留存策略的平台差异

| 平台 | 前30章重点 | 兑现频率 | 容忍慢热度 | 核心风险 |
|---|---|---|---|---|
| 番茄 | 黄金三章极重，前3章定生死 | 每章小爽点 | 极低 | 慢热直接弃，不养书 |
| 起点 | 前10章立人设，允许适度铺垫 | 每卷大爽点 | 中等（老白愿意养） | 注水被追读数据惩罚 |
| 晋江 | 前10章立CP/人设 | 每章甜或虐 | 较高（社区氛围好） | 文风辨识度不足 |

### 平台适配的调整点

同一本书在不同平台发布时，按以下维度调整（不改核心卖点，改执行节奏）：

| 调整维度 | 番茄 | 起点 | 晋江 |
|---|---|---|---|
| 章长 | 2000-2500短章 | 2000-3000（大章4000） | 3000上下 |
| 前3章爽点密度 | 每500字一个 | 每章一个 | 每2章一个 |
| 钩子密度 | 每章2-3个 | 每章1-2个 | 每章1个 |
| 慢档章占比 | ≤20% | ≤30% | ≤40% |
| 伏笔回收周期 | 5-10章 | 10-20章 | 10-30章 |

**纪律**：平台适配只调执行节奏，不调核心卖点/核心梗/金手指。如果核心卖点在某平台
不成立（如纯爽文在晋江），换平台或换卖点，不要在不适配的平台上硬改核心设计。
