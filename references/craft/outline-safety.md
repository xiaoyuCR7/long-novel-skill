# 大纲安全七检与可证伪检查

本文件是 `outline-system.md` 的安全审查层。`outline-system.md` 定义了三级大纲体系
（总纲/卷纲/章纲）的职责、模板与改纲级联规则——管「大纲怎么写、怎么改」。本文件
定义**大纲写完后的安全审查**——管「这份大纲能不能用、有没有结构性缺陷」。

分工：写大纲时查 `outline-system.md` 的模板和流程；大纲写完后、动笔前查本文件做
安全审查。`reverse-brake.md` 的 A/B/C 配额是章级的节奏约束，本文件的七检是卷级/
单元级的结构约束。

## 大纲安全七检

做卷纲或章纲前，以下七个问题必须逐一回答。任何一个答不上来或答案是「没有」，
大纲不通过，必须补完再动笔。

### 第一检：本卷交付什么核心情绪

**问题**：这一卷读完，读者获得的核心情绪满足是什么？

**为什么必答**：一卷如果没有明确的核心情绪交付，就是「写了但没给读者东西」。
读者读完一卷后应该能说出「这卷最爽的是XX」「这卷最虐的是XX」——如果说不出来，
这卷就是水卷。

**通过标准**：
- 核心情绪与读者契约一致（爽文卷交付爽，不交付纯虐）
- 核心情绪有具体落点（不是「爽」，是「第X章打脸反派Y的爽」）
- 核心情绪有足够蓄积（不是突然爽，是有铺垫的爽）

**不通过的修复**：如果答不出核心情绪 → 这卷缺少高潮锚点，回到卷纲补锚点（见
`outline-system.md` 的大纲锚点配额）。

### 第二检：核心冲突是什么、是否有递进

**问题**：本卷的核心冲突是什么？与前卷相比有递进吗？

**为什么必答**：核心冲突是卷的骨架。没有核心冲突的卷是「日常合集」；有冲突但不
递进的卷是「原地踏步」——读者会觉得「这卷和上卷差不多」。

**通过标准**：
- 核心冲突可一句话说清（谁和谁的什么矛盾）
- 与前卷的冲突有递进关系（升级/转向/深化，不是重复）
- 核心冲突在本卷内有起承转合（不是从头打到尾，也不是全程铺垫）

**不通过的修复**：
- 答不出核心冲突 → 这卷可能缺少主线锚点，检查总纲的本卷规划
- 冲突无递进 → 检查是否在重复上卷的冲突模式，换递进方向（升级矛盾/转移战场/
  引入新维度）

### 第三检：卷节奏起承转合（快/中/慢档分布）

**问题**：本卷的快/中/慢档分布合理吗？

**为什么必答**：`pacing-and-hooks.md` 和 `reverse-brake.md` 定义了三档制的规则，
本检是把三档分布提到卷纲层面审查。一卷全是快档 = 透支；全是慢档 = 注水；全是
中档 = 平淡。

**通过标准**：
- 快档 ≤2-3次（`reverse-brake.md` 的配额）
- 慢档每3-4章至少1章（防止全程高压）
- 中档占比 ≥60%（节奏主体）
- 快档后有慢/中档缓冲
- 卷末有快档爆发（卷末是读者「弃书or养书」决策点）

**不通过的修复**：
- 快档过多 → 把部分快档降为中档，或拆分到下一卷
- 慢档过多 → 检查慢档章是否有微型伏笔（`reverse-brake.md`），没有就删或合并
- 无卷末爆发 → 在卷末补高潮锚点

### 第四检：伏笔埋设与回收计划

**问题**：本卷计划埋哪些伏笔、收哪些伏笔？与台账一致吗？

**为什么必答**：伏笔是长篇连载的 continuity 生命线。不计划的伏笔要么忘记回收
（欠债），要么临时硬塞（不合理化债务，见 `reader-contract-deep.md`）。

**通过标准**：
- 本卷计划埋设的伏笔有具体清单（不是「埋一些伏笔」）
- 本卷计划回收的伏笔在台账中有对应ID
- 回收的伏笔在台账中状态为 🟡（活跃），不是 🔴（超期）
- 本卷新埋的伏笔有预期回收窗口（哪一卷/哪一章）
- 与 `追踪/伏笔台账.md` 双向核对一致

**不通过的修复**：
- 伏笔无清单 → 回卷纲补伏笔计划
- 回收的伏笔超期 → 检查为什么超期（是忘了还是计划变更），补回收或调整台账
- 新埋伏笔无回收窗口 → 给每个新伏笔标注预期回收卷/章

### 第五检：章节定位高低层次

**问题**：本卷各章的定位是否高低错落？

**为什么必答**：一卷如果每章都是「高压推进」，读者会疲劳；如果每章都是「低压
日常」，读者会无聊。章节定位的高低层次 = 卷内的呼吸感。

**通过标准**：每章标注以下定位之一，且分布错落：
- **高压章**：主线冲突爆发/大情绪节点（快档）
- **推进章**：次要矛盾升温/信息获取/势力布局（中档）
- **修炼章**：升级/修炼/能力获取（中档或慢档）
- **关系章**：羁绊深化/关系变化/情感交互（慢档或中档）
- **低压章**：日常/风土/过渡（慢档）
- **整理章**：收束前文/消化余韵/为下一段铺垫（慢档）

分布要求：
- 高压章不连续（间隔至少2章）
- 每3-4章至少1章低压或关系章（给读者喘息）
- 修炼章和整理章不连续（都是慢档，连续会拖节奏）

**不通过的修复**：
- 全卷高压 → 插入关系章/低压章做缓冲
- 全卷低压 → 检查核心冲突是否足够强，或合并低压章提速
- 修炼+整理连续 → 中间插一章推进章或关系章断开

### 第六检：阶段可释放/必须压住的内容

**问题**：本卷哪些内容可以释放给读者，哪些必须压住不能给？

**为什么必答**：这是 `reader-contract-deep.md` 终局储备管理的卷级执行。每卷都要
明确「能给什么、不能给什么」——给早了透支，给晚了读者等不住。

**通过标准**：
- **可释放清单**：本卷可以给读者的新信息/新能力/新关系（与终局储备的解锁节奏
  一致，见 `reader-contract-deep.md` 的逐卷解锁表）
- **必须压住清单**：本卷不能给的东西（终局真相的最终层/终极战力的全力/身份终点
  的完全揭晓）
- 每项「可释放」的内容有释放方式（不是一次性给完，是分次给）
- 每项「必须压住」的内容有压制手段（用什么替代/用什么钩子补偿）

**不通过的修复**：
- 答不出「必须压住」→ 可能终局储备边界没定，回总纲补终局储备清单
- 可释放内容超出终局储备的解锁节奏 → 回退到正确的解锁阶段

### 第七检：读者契约/代理权/期待债/终局储备风险判定

**问题**：本卷的读者契约安全评级是什么？

**为什么必答**：这是前六检的综合判定。前六检是结构审查，第七检是契约审查——
结构没问题不代表契约没问题。

**通过标准**（对照 `reader-contract.md` 的三级评级）：
- **契约安全**：代理权/结算权/期待债/终局储备均合规 → 可写
- **需补强**：有轻微泄漏或铺垫不足 → 补交换/铺垫/成本后再写
- **契约破坏**：代理权丢失/终局底牌提前打光/期待债违约 → 必须修纲

具体检查项：
1. 主角代理权：本卷的关键节点四问答案都是主角吗？
2. 结算权：本卷的核心收益结算给主角了吗？（三层结算是否完整）
3. 期待债：本卷的期待债有偿还吗？有违约吗？
4. 终局储备：透支两问——动用了不该解锁的底牌吗？升级线逼近天花板了吗？

**不通过的修复**：
- 需补强 → 补对应环节后重新审查
- 契约破坏 → 修纲，不可带病动笔

## 七检速查表

| 检查项 | 核心问题 | 通过标志 |
|---|---|---|
| 1 核心情绪 | 交付什么情绪？ | 有具体落点的情绪 |
| 2 核心冲突 | 冲突是什么？递进了吗？ | 一句话说清+有递进 |
| 3 节奏分布 | 快/中/慢档合理吗？ | 快≤2-3、慢每3-4章≥1、中≥60% |
| 4 伏笔计划 | 埋什么/收什么？ | 有清单+与台账一致 |
| 5 章节定位 | 高低错落吗？ | 6类定位分布合理 |
| 6 释放/压住 | 能给什么/不能给什么？ | 两份清单+与终局储备一致 |
| 7 契约风险 | 契约安全评级？ | 安全或需补强（已补） |

## 可证伪降级检查

七检通过后，做最后的可证伪降级检查。这是大纲审查的**最后一道关**，防止「结构
都对但核心不对」的问题。

### 检查一：删题材核心对象

**操作**：把本卷的题材核心对象（修仙的「修仙体系」、言情的「CP关系」、悬疑的
「核心谜题」、历史的「权力博弈」）从大纲中删掉。故事是否退化为通用职业升级文？

**判定**：
- **是（退化了）**→ 题材核心对象绑得不够深。这个对象只是背景板，没有与主线
  冲突/角色矛盾/情绪引擎绑定。修复方向：让题材核心对象成为冲突的根源/角色的
  软肋/情绪的引爆点。
- **否（没退化）**→ 通过。题材核心对象与故事深度绑定。

**示例**：
- 修仙文删掉「修仙体系」后，如果故事变成「一个年轻人职场打怪升级」→ 修仙只是
  换皮，没绑深。修复：让修仙体系本身成为矛盾（体系的不公/体系的秘密/体系的
  终极真相与主角绑定）。
- 悬疑文删掉「核心谜题」后，如果故事变成「一个侦探的日常办案」→ 谜题没绑深。
  修复：让谜题与主角的个人线绑定（谜题的真相牵涉主角的身世/至亲/过去）。

### 检查二：删主角

**操作**：把主角从大纲中删掉。情绪兑现是否不变？

**判定**：
- **是（不变）**→ 主角只是摄像头。情绪是配角/事件驱动的，不是主角驱动的。修复
  方向：把情绪兑现绑定到主角的因果链上（让主角的决策/代价/成长成为情绪的来源）。
- **否（变了）**→ 通过。主角是情绪的承载者，删掉主角情绪就塌了。

**示例**：
- 删掉主角后，打脸依然发生（配角打的）、真相依然揭露（配角揭的）、胜利依然到来
  （配角赢的）→ 主角是摄像头。修复：把至少一半的情绪兑现绑定到主角身上（主角
  布局、主角打脸、主角付代价、主角获结算）。
- 删掉主角后，打脸没人打了、真相没人揭了、胜利没人赢了 → 通过。

### 可证伪检查与 `reader-contract.md` 的关系

`reader-contract.md` 也有可证伪降级检查。两者的区别：
- `reader-contract.md` 的版本：针对单个剧情单元（一章/一个场景）
- 本文件的版本：针对整卷大纲

两者原理相同（删核心对象/删主角），但粒度不同。卷级检查通过不代表章级都通过——
每卷的七检+可证伪通过后，章级仍需按 `reader-contract.md` 逐章检查。

## 与锚点配额的关系

`outline-system.md` 定义了大纲锚点配额（主线/关系/秘密/高潮锚点的每卷上下限）。
本文件的七检与锚点配额是**定性+定量**的互补关系。

| 维度 | 七检（本文件） | 锚点配额（`outline-system.md`） |
|---|---|---|
| 性质 | 定性审查 | 定量配额 |
| 检查内容 | 结构合理性、契约安全、核心绑定 | 锚点数量、间隔、分布 |
| 关系 | 七检是「对不对」 | 配额是「够不够」 |

**互补逻辑**：
- 锚点配额达标 ≠ 七检通过（锚点数量够了，但可能核心冲突无递进 → 第二检不通过）
- 七检通过 ≠ 锚点配额达标（结构都对，但锚点可能超限 → 配额检查不通过）

两者都必须通过。先过锚点配额（定量快检），再过七检（定性深检），最后过可证伪
（核心审查）。

## 对标节奏迁移

### 什么是对标节奏迁移

写卷纲时，找一本同题材的成功对标书，把它的卷级节奏结构（1/4·中点·3/4的关键
转折点）提取出来，换上自己的素材，排进本卷的卷纲。

### 迁移步骤

1. **选对标书**：同题材、同平台、数据表现好的完本书（不是连载中的——连载中的
   可能没写完就崩了）
2. **提取结构点**：标注对标书每一卷的：
   - 1/4 处：第一个小高潮/转折
   - 中点（1/2）：卷中高潮/核心转折
   - 3/4 处：卷末高潮前的最后铺垫/反转
   - 卷末：大爆发+下卷钩子
3. **换素材**：把对标书在这些结构点发生的事，换成自己本书的素材
   - 对标书1/4处是「主角第一次打脸小反派」→ 你的1/4处也安排一个「第一次小胜」
   - 对标书中点是「真相半揭」→ 你的中点也安排一个「关键信息揭露」
4. **排进卷纲**：把换好素材的结构点排进本卷卷纲的对应位置

### 迁移的纪律

- **只迁结构，不迁内容**：迁移的是节奏形状（什么时候快、什么时候慢、什么时候转），
  不是具体情节。照搬情节 = 抄袭。
- **只迁一卷，不迁全书**：每卷找对标书对应的一卷做迁移，不要拿对标书全书结构
  套自己全书——两本书的核心梗/卖点不同，全书结构不能照搬。
- **迁移后必须过七检**：对标书的节奏迁过来后，仍然要过七检+可证伪。对标书的
  节奏在TA的书里成立，在你的书里不一定成立（核心梗/人设/金手指不同）。
- **迁移不是必须的**：如果自己有清晰的节奏规划，不需要迁移。迁移是「不知道怎么
  排节奏时的参考」，不是「每次都必须做」的步骤。

### 迁移的常见错误

| 错误 | 症状 | 修复 |
|---|---|---|
| 照搬情节 | 对标书打脸师兄，你也打脸师兄 | 换成自己的素材（打脸的是谁、为什么打脸） |
| 忽略题材差异 | 对标书是爽文节奏，你是悬疑文 | 换同题材的对标书，或调整节奏点（悬疑的中点不是打脸而是真相半揭） |
| 忽略平台差异 | 对标书是番茄短章高频，你写起点长章 | 换同平台的对标书，或按平台调整章长和钩子密度 |
| 迁移后不过七检 | 结构对了但核心冲突无递进 | 七检不通过就改纲，不要因为「对标书是这样的」就硬上 |

## 七检+可证伪的执行流程

```
卷纲写完
  ↓
锚点配额检查（outline-system.md，定量快检）
  ├─ 不通过 → 调整锚点数量/分布
  └─ 通过 ↓
七检（本文件，定性深检）
  ├─ 任一检不通过 → 回卷纲修补对应项
  └─ 七检全通过 ↓
可证伪降级检查（本文件，核心审查）
  ├─ 删题材核心 → 退化 → 补核心对象绑定
  ├─ 删主角 → 不变 → 补主角因果链
  └─ 两检通过 ↓
卷纲安全审查通过，可进入章纲阶段
```

**纪律**：这个流程不可跳过。直接写章纲不做卷纲安全审查 = 带病进入执行层，后面
的章级问题会指数级放大（一个卷纲的结构缺陷会在每章都体现，修复成本是卷纲阶段的
N倍）。
