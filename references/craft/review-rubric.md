# 评审标准与多视角审稿

用途：卷级评审（每卷写完）、重大节点评审（上架前、签约前）、完稿评审。
单章靠 `workflow/chapter-loop.md` 的自查清单，不用本文件——本文件回答的是另一个问题：
**这本书作为商品，读者买账吗？**

## 评分维度与平台权重

七个维度，1–10 分。权重按目标平台取（平台基线见 `../platforms/platform-guide.md`）：

| 维度 | 说明 | 番茄 | 起点 | 晋江 |
|---|---|---|---|---|
| 钩子强度 | 章尾/卷尾的追读驱动力 | ★★★ | ★★ | ★★ |
| 节奏 | 信息释放与结算速度是否匹配平台读者耐心 | ★★★ | ★★ | ★★ |
| 情绪交付 | 爽/虐/甜的浓度与兑现率 | ★★★ | ★★ | ★★★ |
| 人设与关系 | 人物立得住、声线可分、CP/对手戏有火花 | ★★ | ★★ | ★★★ |
| 设定与结构 | 世界观自洽、卷结构清晰、长线可控 | ★ | ★★★ | ★★ |
| 文笔文风 | 可读性、无 AI 腔、文风辨识度 | ★ | ★★ | ★★★ |
| 商业潜质 | 题材热度、差异化卖点、改编面相 | ★★ | ★★ | ★★ |

分数锚定：6 = 能看但有明显弃书点；7 = 追读无碍、无记忆点；8 = 有明确追读理由；
9 = 同题材前 20%；10 = 现象级（慎用）。

## 机器量化层（评审前置检查）

人工评审前，先跑完机器检查，拿量化数据再做定性判断：

```bash
# 7 Gate 检测（Gate A/B 机器查，C-G 人工查）
python scripts/check_text.py "正文/第XXX章.md" --min-chars 2000 --gate-report

# 文风指纹偏离检测（与文风锚对比）
python scripts/style_fingerprint.py compare tmp_fp.md "设定/文风锚.md"

# 节奏配额检查（A/B/C 配额 + 事件冷却）
python scripts/rhythm_guard.py --chapter-file "正文/第XXX章.md" --quota "追踪/节奏配额.md"
```

**机器数据与人工评审的关系**：
- 机器报警但人工觉得没问题 → 标记为「待观察」，连续 3 章报警则强制处理
- 机器通过但人工觉得有问题 → 以人工判断为准，机器不覆盖人的阅读感受
- 机器和人工都报警 → 最高优先级，必须改

## 多视角审稿协议

生成者偏差决定了自己评自己的书必然偏松。单视角盲评也不够——不同读者看到的问题不同。
正确姿势是用多个无上下文的子代理做不同视角的盲评。

### 四视角盲评矩阵

| 视角 | 模拟读者类型 | 评审重点 | 给什么 | 不给什么 |
|---|---|---|---|---|
| 追读读者 | 已追 50+章的老读者 | 弃书点、追读动力、角色一致性 | 正文 + 目标平台 | 大纲、人物卡、创作意图 |
| 新读者 | 刚点开第1章的路人 | 前三章留人能力、爽点前置 | 正文前3章 + 第1章 | 任何设定文件 |
| 目标平台编辑 | 签约/推荐位的把关者 | 商业潜质、平台适配、签约面相 | 正文 + 平台基线 + 评分维度表 | 创作意图、改稿历史 |
| 同行作者 | 同题材写手 | 设定自洽、节奏配额、结构功底 | 正文 + 题材卡 + 节奏配额记录 | 卷纲（只看正文能否自洽） |

### 盲评执行协议

每个视角用一个新的、无上下文的子代理/会话：

1. **只给必要输入**：待评章节正文（建议一个完整剧情单元 5–15 章）+ 该视角需要的参考文件。
   **不给**创作意图、大纲、人物卡（除非该视角需要）。

### 盲评 Prompt 模板

每个视角的子代理使用以下统一模板结构（替换视角专属内容）：

```
你是一位{视角名称}。你将阅读以下网文章节，给出你的真实评价。

## 你要评的内容
{待评章节正文}

## 评审要求
1. 弃书点：在哪一章哪一段你想弃书？为什么？
2. 追读点：此刻你最想知道什么？
3. 按以下维度打分（1-10）并给出一句依据：
   {按视角显示相关维度}
4. 如果发现 P0 级问题（角色已死又出现/主线矛盾/时间线错乱），请标注。

## 重要
- 不要客套，不要凑好话，给出你最真实的阅读感受
- 指出具体段落和具体问题，不要泛泛而谈
- 如果你没有任何弃书冲动，说明追读动力充足
```

### 异源审核协议

理想状态：用不同模型（如 Claude + GPT + Gemini）交叉审核，避免同源偏见。

**降级策略**（按可用性逐级降级）：

| 级别 | 条件 | 审核方式 | 可靠性 |
|---|---|---|---|
| L1 异源多模型 | 有 2+ 个不同模型可用 | 不同模型各跑一个视角 | 最高 |
| L2 同模型多会话 | 只有 1 个模型 | 同模型开 4 个无上下文子会话，各赋不同视角 prompt | 高 |
| L3 同会话切换 | 子会话不可用 | 在主会话内用不同 system prompt 模拟 4 个视角 | 中 |

- L1 > L2 > L3 逐级降级，不跳级
- 降级到 L3 时，必须在评审结论中标注「同源评审，结果仅供参考」
- 防死循环：单章返工上限 2 次；连续 3 章有条件通过（L3 降级评审通过但存疑）则强制人工介入

2. **要三样输出**：
   - 弃书点：在哪一章哪一段想弃书，为什么（最重要的产出）；
   - 追读点：此刻最想知道什么（检验钩子是否生效）；
   - 按维度打分 + 一句话依据。
3. **结果使用**：只取可执行项（具体段落、具体节奏问题），不盲从分数；
   盲评指出的问题先对照题材卡与卷纲判断「是真问题还是读者个体差异」，再决定改不改。
4. **频率**：每卷至少一次（四视角全做）；上架/签约/大高潮前加做一次。

### 四视角结果的交叉分析

| 现象 | 含义 | 处理 |
|---|---|---|
| 四视角都报同一问题 | 确定性问题 | 必须改 |
| 三视角报、一视角不报 | 大概率问题 | 改，记录不报视角的理由 |
| 两两分歧（两视角报、两视角不报） | 读者群体分化 | 作者拍板，按目标平台读者倾向决定 |
| 只有一个视角报 | 个体差异 | 记录观察，暂不改，下次评审跟踪 |

## 与编辑团队协议的衔接

编辑团队（见 `editorial-team.md`）用于单章生产；本文件用于卷级/节点级评审。
两者衔接：

- 编辑团队的「连载核实官」检查单章一致性 → 本文件的「人设与关系」「设定与结构」维度
- 编辑团队的「反 AI 编辑」执行 7 Gate → 本文件的「文笔文风」维度
- 本文件评审发现的结构层问题 → 反哺到下一卷的编辑团队 Chapter Brief 模板

## 评审后的处置

问题分两类：

- **文本层**（改字句：钩子、节奏、文笔）→ 按 `workflow/revision.md` 局部修订；
- **结构层**（改走向：人设、主线）→ 先走改纲级联，作者确认后再动正文。

### 问题优先级

| 级别 | 标准 | 处理时限 |
|---|---|---|
| P0 | 机器 FAIL + 人工确认（如角色已死又出现、主线矛盾一章清光） | 立即改，改完才发 |
| P1 | 三视角以上弃书点在同一章 | 本卷内改 |
| P2 | 两视角弃书点 | 下次修订时改 |
| P3 | 单视角或可执行性低 | 记录观察 |

评审结论记入卷纲文件末尾的批注（日期 + 维度分 + 四视角弃书点汇总 + 三项最优先修改项），
下一卷写前复查这些项是否真的改了。

## 拆文对标评审

如果有拆文产出（见 `workflow/deconstruct.md`），评审时加入对标维度：

- **节奏对标**：本卷的快/中/慢档分布与对标书的差异是否在合理范围
- **钩子密度对标**：本卷章尾钩子数与对标书的差异
- **爽点浓度对标**：本卷爽点数/字数比与对标书的差异

差异不一定是问题，但差异 >30% 时需要解释原因（「本卷定位是铺垫卷所以慢」可接受，
「不知不觉就慢了」不可接受）。
