# 语义级节奏审查（Pacing Review）

本文件定义「写完后、门禁前」的语义级节奏审查——由你（Claude）亲自读章、亲自判断，
不是跑脚本。脚本（`rhythm_guard.py`、`check_text.py`）管规则级检测，本文件管语义级
判断——**脚本检测不到的隐性剧情加速、语义级节奏问题，由本审查兜底。**

## 为什么脚本不够

`rhythm_guard.py` 做的事：
- 检查 A/B/C 配额是否越界（同时触发 ≥2 项）
- 检查事件冷却是否违规
- 检查连续快档、慢档缺失

脚本**检测不到**的事：
- 写了三章打斗但主线一步没走（脚本看不出"打斗有没有推进主线"）
- 章末悬念是"模糊悬念"（"他感到不安"）还是"具体悬念"（"他看到了那张照片上不该出现的人"）
- 本章的"快档"是真正的快档还是注水快档（信息密度够不够）
- 是否存在关键词未覆盖的隐性加速（如连跳多个场景、时间跳跃缩略关键过程）

这些只能靠语义判断。

## 执行时机

**每章写完、`check_text.py` 和 `rhythm_guard.py` 跑完后、自查清单之前。**

对关键章节（卷末高潮/大反转/身份揭晓），审查必须更严格（见下方「关键章节加强审查」）。

## 审查四维度

### 维度一：档位判断

读本章正文，判断本章的实际节奏档位，与章纲预声明的档位对比。

| 实际档位 | 判定标准 |
|---|---|
| 慢档 | 主线矛盾零推进；主要场景 = 日常/羁绊/风土/修炼/铺垫；信息密度低 |
| 中档 | 次要矛盾升温（未爆发）；场景有推进感但无决定性变化；信息密度中 |
| 快档 | 主线格局发生实质性、不可逆的改变；有高潮场景；信息密度高 |

**档位不一致的处理**：
- 声明的慢档，实际是中档 → 本章可能注水了，但不算违规。记录偏差，考虑下章补慢档。
- 声明的快档，实际是中档 → 本章高潮没写到位，信息密度不够。**必须标注为「伪快档」，
  建议重写高潮段。**
- 声明的中档，实际是快档 → 本章实际推进了主线，但章纲没预声明。**核验 A/B/C 配额
  是否因此越界，如越界则门禁失败。**

### 维度二：A/B/C 配额语义核查

章纲已预声明本章计划触发哪些配额（A/B/C 中至多 1 项）。读正文后，判断实际是否触发：

| 配额 | 触发条件（语义级） |
|---|---|
| A（主线矛盾实质推进） | 本章主线格局发生实质性、不可逆改变。关键判断：**如果删掉本章，后面的主线剧情是否接不上？** 接不上 = 触发了 A。 |
| B（主要关系决定升级） | 主要角色关系到达决定性节点。关键判断：**本章之后，这两个角色的关系是否回不到本章之前的状态了？** 回不去 = 触发了 B。 |
| C（核心秘密完整揭露） | 核心秘密在本章被完整揭露（不是暗示、不是部分揭露）。关键判断：**读者看完本章后，是否知道了之前不知道的、改变对全书理解的关键信息？** 是 = 触发了 C。 |

**配额违规**：同时触发 ≥2 项 = 越界，门禁强制失败，必须改纲重写（见 Iron Law 第 5 条）。

**配额欺诈**：章纲声明触发 A，实际只触发了次要矛盾（不算 A）→ 章纲声明虚高，记录并
要求下章补回进度。

### 维度三：章末悬念质量

章末悬念是读者「点下一章还是关掉」的决定因素。审查四问：

1. **是否存在具体悬念**：章末有没有一个读者能清晰说出来的「想知道的事」？
   - 有具体悬念 → 记录悬念内容（一句话）
   - 只有模糊悬念（"他感到不安""未来会怎样"）→ **不合格，必须补具体钩子**
   - 完全没有悬念 → **不合格，除非是慢档日常章且后面紧跟快档章**

2. **悬念强度**：强 / 中 / 弱
   - 强：读者必须立刻知道结果（如反转半句、生死未卜）
   - 中：读者想知道但可以等（如新线索出现、新角色登场）
   - 弱：读者觉得「明天看也行」（如日常章的小钩子）

3. **悬念与前文的因果关系**：悬念是否来自本章的情节推进（而非凭空捏造）？
   - 来自本章情节 → 自然悬念，合格
   - 凭空抛出新信息 → 机械悬念，扣分但不失败

4. **悬念的接得住性**：下一章的章纲是否真的能接住这个悬念？
   - 下一章章纲已就位且能接住 → 合格
   - 下一章章纲未就位或接不住 → **警告，必须先补章纲再写下一章**

### 维度四：隐性加速检测

这是脚本检测不到的最关键项。逐项判断：

1. **场景跳跃**：本章是否跳过了应该展开的场景？
   - 例：A 决定去 B 地点 → 下一段直接到了 B 地点，中间的过程/心理/准备全跳过
   - 判定：如果跳过的场景包含读者期待的内容（如主角的准备、路上的思考），
     → **隐性加速，不合格**

2. **时间跳跃缩略**：本章是否用「几天后」「转眼间」缩略了关键过程？
   - 判定：如果缩略的时间段包含卷纲要求的剧情（如"主角在宗门修炼三个月"），
     且本章只用一句话带过 → **隐性加速，不合格**

3. **情绪跳跃**：本章是否跳过了情绪应有的过渡？
   - 例：角色刚经历重大打击，下一页就若无其事地行动
   - 判定：如果情绪跳跃不符合人物性格（如角色卡标注「情感细腻」但本章情绪淡漠），
     → **隐性加速，不合格**

4. **信息密度异常**：本章是否出现信息密度突然暴增或暴跌？
   - 暴增：一段内塞入大量设定/背景/人物关系（读者消化不良）
   - 暴跌：大段纯描写/纯心理/纯日常，无任何推进（读者觉得水）
   - 判定：暴增 → 信息过载，建议拆分到多章。暴跌 → 内容注水，建议删减或合并。

5. **对抗缺失**：本章是否缺少「主角想要什么 → 有什么阻碍」的基本对抗结构？
   - 判定：如果本章从头到尾主角没有遇到任何实质阻碍（想要什么就得到什么），
     → **无对抗章节，不合格（慢档日常章除外，但日常章也应有微型阻碍）**

## 审查产物格式

审查完成后，将结果写入 `追踪/门禁/pacing_review_ch{N}.md`，严格按以下模板：

```markdown
# 语义级节奏审查报告 — 第{N}章

## 一、档位判断
- **章纲声明档位**：[慢档 / 中档 / 快档]
- **实际档位**：[慢档 / 中档 / 快档]
- **档位一致性**：[一致 / 不一致（{说明}）]
- **判断依据**：[1-2句：主要场景类型、核心矛盾推进幅度]

## 二、A/B/C 配额语义核查
- **A（主线矛盾实质推进）**：[触发 / 未触发] — [1句说明]
- **B（主要关系决定升级）**：[触发 / 未触发] — [1句说明]
- **C（核心秘密完整揭露）**：[触发 / 未触发] — [1句说明]
- **配额违规**：[是 / 否]（同时触发 ≥2项 = 违规）
- **配额欺诈**：[是 / 否]（章纲声明与实际不符）

## 三、章末悬念质量
- **悬念等级**：[强 / 中 / 弱 / 无]
- **具体悬念内容**：[一句话描述章末留下的钩子]
- **悬念来源**：[本章情节自然产生 / 凭空抛出新信息]
- **下一章可接住**：[是 / 否]（基于章纲判断）

## 四、隐性加速检测
- **场景跳跃**：[是 / 否] — [如是，说明跳过了什么]
- **时间跳跃缩略**：[是 / 否] — [如是，说明缩略了什么]
- **情绪跳跃**：[是 / 否] — [如是，说明什么情绪被跳过了]
- **信息密度异常**：[是 / 否] — [如是，说明暴增还是暴跌]
- **对抗缺失**：[是 / 否] — [如是，说明缺失了什么对抗]

## 综合结论
- **节奏审查**：[通过 / 有条件通过 / 失败]
- **失败原因**：[若失败，列出具体原因；通过则填"无"]
- **整改建议**：[若失败或有条件通过，列出具体整改步骤]
```

## 结论判定标准

| 结论 | 条件 |
|---|---|
| **通过** | 四维度全部合格，无隐性加速，无配额违规，悬念质量达标 |
| **有条件通过** | 有非致命问题（如档位偏差但不违规、悬念偏弱但不致命），记录整改项，下章补偿 |
| **失败** | 任一以下条件触发：① A/B/C 同时触发 ≥2 项；② 存在隐性加速（场景跳跃/时间跳跃缩略）；③ 章末悬念为「无」且非慢档收尾章；④ 快档声明但实际为中档（伪快档）；⑤ 对抗缺失（非慢档日常章） |

**失败时**：禁止进入自查清单，必须先整改后重新审查。整改 = 修改正文对应段落，重跑节奏审查。

## 关键章节加强审查

以下章节类型，在四维度基础上增加额外审查项：

### 卷末高潮章

- [ ] 本章的情绪爆发是否压过了上一卷的爆发（力度升级）？
- [ ] 本章的代价是否足够（赢了但付出了什么）？
- [ ] 卷末钩子是否足够强到让读者追下一卷？

### 大反转章

- [ ] 反转是否有前置铺垫（回头能找到线索）？
- [ ] 反转后的情绪停留是否足够（读者和角色一起消化）？
- [ ] 反转是否改变了读者对前文的理解（而不只是改变了后文走向）？

### 身份揭晓章

- [ ] 揭晓前是否有足够的「快要揭晓了但还没」的延迟？
- [ ] 揭晓的瞬间是否用慢镜头写细（而非一笔带过）？
- [ ] 揭晓后各角色的反应是否逐一呈现（而非只写主角）？

## 与机器闸口的协作

本审查在 `check_text.py` 和 `rhythm_guard.py` 之后执行，在自查清单之前执行。

完整顺序：
```
写正文 → 标点归一化 → check_text.py（7 Gate）→ rhythm_guard.py（配额）→
**语义级节奏审查（本文件）** → 自查清单 → 追踪更新
```

机器闸口管「能检测到的规则违规」，语义审查管「脚本检测不到的隐性加速」。
两者互补，不可互相替代。
