# 语义级节奏审查（Pacing Review）

本审查由主 Agent 实际阅读当前候选稿，核对脚本无法判断的因果、兑现、详略和结尾契约。
`check_text.py`、`rhythm_guard.py` 的真实 blocking/FAIL 不能由人工意见替代或降级；
人工审查也不能因为脚本 exit 0 就省略。只读章纲时，结论限于章纲，不冒称正文验收。

## 执行边界与顺序

完整写章/修章遵循 `../workflow/chapter-loop.md`，不另建提交流程：

`核对来源/授权与章意图 → prepare → stage pending draft → 只读信号与 gates →
语义审查/自查 → stage 五表同步 → validate → commit`。

- 门禁读取当前 `{stage}/正文/{chapter_file}` 和 stage 追踪表；标点只运行
  `normalize_punct.py --check` 供人工复核，不默认批量归一化。
- 在 `check_text.py`、`rhythm_guard.py` 实际运行后做本审查，并纳入章节自查。
  语义报告与章意图都放在正式工程和 stage 之外，不手填机器 gate。
- 修复只针对已定位缺陷；同一章同一任务**最多自动修两轮**，机器/语义 P0 共享额度，
  切换 Agent、会话或重建事务不能重置。修改 stage 后重跑受影响的门禁与本审查，再 validate。
- 两轮后仍有 blocking/P0：输出 `gate_blocked`，保留 checkpoint 与 pending draft，
  canonical state 不变，不再自动改、不提交，也不能改称 advisory。
- 需改锁纲、设定等非事务输入时，先 recover，再按已有授权修改并重新 prepare；超出授权
  请求作者决定。只做审读且无必改项，不为走流程开启章事务。

## 审查四维度

### 一、实际档位与声明

以实际状态变化对照章纲及章意图，不把情绪烈度、打斗字数或“温暖”直接换算成档位：

| 实际档位 | 语义核对 |
|---|---|
| 慢档 | 不发生主线实质推进；可承担关系、生活质感、风土、准备与消化 |
| 中档 | 次要矛盾、任务或信息有进展，尚无主线决定性变化 |
| 快档 | 主线格局发生实质性、不可逆改变或已有授权的大结算 |

声明与实际不符时，指出是哪项变化及其正文位置，核查是否写漏、写超或声明错误。
慢档实际写成中档不等于注水；快档实际为中档也不能只凭信息密度不足就命令扩写高潮。
若漏掉授权的决定性回合，修复该回合；若实际越过配额或授权，按硬约束处理。
不自动要求下章“补进度”，尤其不能把终章问题推给不存在的下一章。档位分布与事件冷却
仍由既有 `rhythm_guard.py` 规则检查，不借本审查更改阈值或伪报声明。

### 二、A/B/C 配额语义核查

章纲预声明 A/B/C 中至多 1 项（也可不触发），正文核对其实际含义：

| 配额 | 触发条件与边界 |
|---|---|
| A（主线矛盾实质推进） | 主线格局发生实质性、不可逆改变。必要铺垫、一次任务进展或“删去会影响后文”本身不等于 A。 |
| B（主要关系决定性升级） | 主要关系到达结盟、决裂、告白、宣战等决定性节点。已有关系中的照顾、确认或一次普通让步不自动算 B。 |
| C（核心秘密完整揭露） | 核心秘密被完整揭露，不是暗示、部分信息或角色的猜测；区分读者获知与 POV 获知。 |

**配额违规**：同时触发 ≥2 项 = 越界，门禁强制失败，必须改纲重写（见 Iron Law 第 5 条）。
事实、授权、预算与配额硬约束不因文风、ending_mode 或审查意见放宽。声明与正文不符时
记录证据，按当前授权修复并重新过闸，不隐瞒触发、不用改标签掩盖实际变化。

### 三、按 ending_mode 审核结尾

先读取唯一章意图的 `ending_mode`、`hook_question` 和 `closure_requirements`，
不把章末悬念当成所有章节的合格条件。

**serial：已授权问题的因果与承接**

1. 正文留下的具体未决问题是什么？它应与 `hook_question` 对应，可由物证、选择或行动
   后果呈现，不必写成问句。“他感到不安”若没有可追问内容，回查授权问题是否写漏。
2. 问题是否来自本章或前文的既有因果？未经授权的新危机、新角色、新秘密是授权缺陷，
   不能只扣“机械悬念”分然后放行。
3. 本章该兑现的承诺是否已结算？不能用新的悬置顶替旧账。
4. 下一章章纲是否能承接？缺章纲或接不住时，在开写下一章前处理；不能凭空补钩子。
   强弱仅作工艺判断，没有阅读数据不声称它必然提高追读率。

**closed / finale：闭合与余韵**

- `hook_question` 为 `""`，按 `closure_requirements` 核对承诺、结果与关系落点。
- 不强制下一章悬念、微型伏笔、预告或后续快档。安静生活动作、明确回应、满足后的
  收拾与回味都可收束；没有悬念本身不构成失败。
- 闭合不是省掉关键兑现，也不是旁白升华。保留结果对当事人的意义；`finale` 不造续章
  规避预算或配额，冲突须请求作者在当前授权内取舍。

### 四、隐性加速与无作用重复

复用 `scene-rendering.md` 的信息、策略、关系、风险、节奏、视角功能判断：

| 观察项 | 实际缺陷与最小修复 | 应保留的反例 |
|---|---|---|
| 场景跳跃 | 跳过了改变决定的谈判、选择或必要交付，致后果无法理解；补回该授权回合 | 常规路程与搬运可略写，不要求途中补心理或新事件 |
| 时间缩略 | 把章纲要求展开的关键过程缩成结果，损失因果；恢复决定性过程 | “数月后”可压缩无须逐日呈现的等待，不因时间词自动失败 |
| 情绪承接 | 新反应与既有处境、动机矛盾且缺少可读原因；找回已有触发与选择 | 麻木、克制、直接坦白与缓慢内心戏都可符合声线，不强配身体反应 |
| 信息组织 | 读者无法分清说话人、时序或事实来源；调整已有信息的位置与连接 | 需要完整说明才能决策时可讲完，不按段长判过载 |
| 日常与重复 | 相同结论被无作用重述；只删并冗余部分 | 关系确认、必要验收、反复试探与生活质感不因“无新情节”而删除 |
| 目标与阻力 | 已授权目标/选择被写丢，人物行动没有可理解原因；补清原有因果 | 平静履约、休息、合作不必新增对抗或微型阻碍 |

没有正文证据就不能据场景名称判失败。先指出功能损失，再提改/留理由；不凑问题数量，
不把每个 beat 扩成一段。仅授权改指代/解释时保留动作次数与顺序，不能顺手删事件。
语义 P0 包括事实/授权错误、关键因果或承诺兑现缺失、结尾契约被破坏；普通详略偏好
与同调、直接表达、无悬念不能冒充 P0。

## 审查记录与结论

报告写在**工程外**本次已有工作目录，可复用同一修订报告，不新增 stage 文件或第二 Brief。
至少记录：审查范围与当前正文 SHA-256、声明/实际档位与依据、A/B/C 实际触发、ending_mode
及结算证据、具体缺陷短摘录与功能、改/留理由、机器结果与本任务已用修复轮次。
不适用项写 N/A 及原因；没有正文或未运行脚本则直说，不能填“通过”替代。

| 结论 | 条件与后续 |
|---|---|
| 通过 | 已审范围内未发现未解决的 blocking/P0；工艺信号已按语境判断 |
| 有建议 | 只有非阻断的详略/表达建议，列理由；不自动改纲或要求下章补偿 |
| 失败/待决策 | 仍有 blocking/P0，或修复需新增作者授权；不 commit，按剩余额度修复或停止 |

报告不是事实台账，也不是机器门禁文件。`validate` 不读取或验证语义报告；主 Agent 必须
真实完成自查。五表在 stage 同步后，运行 `chapter_transaction.py validate` 验证同一候选，
再在自查真实通过时 `commit --self-review-confirmed`；确切命令见 chapter-loop。
validate 后又编辑 stage 必须重验。提交前不覆盖 canonical 正文或追踪表。

## 关键章节加强审查

- **卷末/终局**：本卷承诺是否兑现，已授权代价是否落地，余韵是否来自变化后的当事人？
  不要求压过上一卷的情绪强度；serial 查承接，closed/finale 查闭合。
- **大反转**：证据与来源是否可追溯，反转前后解释如何变化，当事人能否据其知识调整？
  消化空间按实际需要安排，不固定反应段数或拖延时间。
- **身份揭晓**：谁知道了什么、通过何种证据、谁仍误信？各角色只按所知行动，重要关系
  后果须承接；不强迫每个在场者逐一震惊，不为补反应新增旁观者。

机器闸口与语义审查互补，不相互替代；真实通过本次检查不等于证明读者留存或整书文学质量。
