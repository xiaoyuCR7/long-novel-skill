# 角色设计操作手册

本文件是 `character-consistency.md` 的设计层前置。`character-consistency.md` 管的是
**防 OOC**——角色已经设计好了，怎么保证连载中不跑偏。本文件管的是**怎么设计角色**——
在动笔之前，如何构建一个有深度、有反差、能支撑百万字连载的角色。

分工：开书/加新角色时查本文件做设计；日常写作中防 OOC 查 `character-consistency.md`。
人物卡的静态字段（模板见 `assets/templates/character-card.md`）是两者的交汇点——
本文件指导如何填好人物卡，`character-consistency.md` 指导如何守住人物卡。

## 三层标签反差

好角色不是「一个标签」，而是「三层标签之间有张力」。扁平角色只有一个标签（「冷酷」
「热血」「腹黑」），读者三章就看穿了。立体角色有三层标签，层与层之间有反差，反差
制造悬念和深度。

### 三层定义

| 层级 | 含义 | 读者感知 | 揭示节奏 |
|---|---|---|---|
| 表面标签 | 角色初次登场时展现的样子 | 第一印象 | 前3章建立 |
| 真实标签 | 角色在压力下暴露的本性 | 认知反转 | 前30章逐步揭示 |
| 隐藏标签 | 角色自己都不知道/不愿承认的内核 | 深度共情 | 中后期关键节点揭示 |

### 反差要求

三组标签之间，**至少一组有反差**。反差越大，角色越有记忆点。

| 组合 | 反差类型 | 效果 | 示例 |
|---|---|---|---|
| 表面≠真实 | 表里不一 | 制造认知反转 | 表面冷酷实则深情 |
| 真实≠隐藏 | 自我矛盾 | 制造深度共情 | 真实是坚强，隐藏是恐惧被抛弃 |
| 表面≠隐藏 | 极端反差 | 制造震撼 | 表面嬉笑，隐藏是彻骨的虚无 |

**反差不是随机搭配**——两层之间的反差必须有**心理逻辑**。表面冷酷实则深情，逻辑是
「因为曾经深情受过伤，所以用冷酷自我保护」。没有逻辑的反差是精分，不是立体。

### 三层标签的填写

在人物卡的「核心性格」字段，按三层结构填写（模板扩展）：

```
## 核心性格（三层标签）

### 表面标签（初登场的样子）
1. {词}——{TA对外展示这个特质的行为}
2. {词}——

### 真实标签（压力下的本性）
1. {词}——{什么情境下会暴露这个真实面}
2. {词}——

### 隐藏标签（自己不愿承认的内核）
1. {词}——{什么极端情境才能逼出这一面}
2. {词}——

### 反差逻辑
表面→真实的转变原因：{一段话}
真实→隐藏的压抑原因：{一段话}
```

## 行为反差进阶

三层标签定义了角色的静态结构。行为反差是角色在故事中的**动态展现**——从「人设冲突」
到「选择困境」到「代价揭示」，三级递进。

### 第一级：人设冲突

角色遇到一个与其表面标签冲突的情境，产生初步反差。

- **触发**：情境挑战表面标签（冷酷的人遇到需要温情的场景）
- **表现**：角色的第一反应是按表面标签行事，但产生犹豫/不适
- **效果**：读者第一次察觉「这个角色不简单」
- **字数**：1-2章内完成，不需要大篇幅

示例：表面冷酷的剑修遇到一个孤儿求助。第一反应是转身走（按表面标签），但脚步
顿了一下（暴露真实标签的萌芽）。

### 第二级：选择困境

角色必须在两个标签之间做选择，且无论选哪个都有代价。

- **触发**：情境升级，迫使角色在表面标签和真实标签之间二选一
- **表现**：角色陷入两难，选择本身揭示真实标签，但选择的代价暴露隐藏标签
- **效果**：读者对角色产生深度共情——理解TA为什么纠结
- **字数**：3-5章的剧情单元，有足够的铺垫和消化空间

示例：剑修必须选择——保护孤儿暴露自己的位置被仇家追杀（选真实标签「深情」，
代价是安全），还是继续冷漠离开但余生被内疚折磨（选表面标签「冷酷」，代价是
内心）。选择本身揭示真实标签（深情），选择的痛苦暴露隐藏标签（恐惧重蹈当年
没能救下师妹的覆辙）。

### 第三级：代价揭示

角色做出选择后，代价兑现，隐藏标签完全暴露。

- **触发**：选择的后果落地，角色被迫面对自己一直回避的内核
- **表现**：角色为选择付出真实代价，在代价中暴露最深层的隐藏标签
- **效果**：读者完成对角色的情感投资——「我理解TA为什么是现在这样」
- **字数**：卷级弧线的高潮点，5-10章的积累后爆发

示例：剑修选择保护孤儿，被仇家追杀重伤。在生死边缘，他终于承认自己一直用冷酷
逃避的不是江湖险恶，而是当年师妹死时自己无能为力的恐惧。隐藏标签（恐惧无能为力）
完全暴露。

### 三级递进的设计纪律

- 三个级别不能跳级：没有人设冲突就直接到选择困境 = 读者没准备好，觉得突兀
- 三个级别之间要有间隔：不连续发生，间隔 10-20 章以上，让读者消化每一级的冲击
- 第三级之后角色进入新阶段：隐藏标签暴露后，角色的表面标签会调整（不再伪装了），
  开始新的三层标签循环（新表面=旧真实，新真实=成长后的新面，新隐藏=新的未解内核）

## 配角功能化

配角不是用来凑人数的。每个出场的配角必须至少承担一个**叙事功能**，否则就是冗余
角色，浪费篇幅。

### 五大功能

| 功能 | 定义 | 兑现频率 | 无此功能的后果 |
|---|---|---|---|
| 信息提供者 | 向主角/读者提供关键信息 | 出场即兑现 | 信息只能靠旁白交代，AI味重 |
| 情绪放大器 | 放大或对比主角的情绪 | 高潮章兑现 | 主角的情绪没有参照系，读者感受不到烈度 |
| 矛盾催化剂 | 制造或加速矛盾冲突 | 冲突章兑现 | 矛盾只能靠对手制造，节奏单调 |
| 价值标尺 | 用自己的价值观衬托主角的选择 | 选择章兑现 | 主角的选择缺乏对比，看不出深度 |
| 成长镜像 | 自己的弧光映照主角的成长弧 | 全程兑现 | 主角的成长没有参照物，读者感知不到变化 |

### 配角设计清单

设计每个配角时过一遍五项功能：

```
配角：{名字}
功能1：{信息提供者/情绪放大器/矛盾催化剂/价值标尺/成长镜像}——{具体怎么兑现}
功能2（可选）：{第二功能}——{具体怎么兑现}
无功能项：{哪些功能TA不承担，为什么}
```

**纪律**：
- 每个配角至少1个功能，最多2个（超过2个 = 角色过载，功能互相干扰）
- 同一功能的配角不要超过2个（两个信息提供者 = 信息冗余）
- 出场<3次的路人角色不需要功能化，但也不能有名字（有名字=读者会记住=期待后续出场）

### 功能化的反例

| 反例 | 症状 | 修复 |
|---|---|---|
| 花瓶配角 | 出场只为衬托主角帅/美 | 给一个功能，或删掉 |
| 传声筒配角 | 只负责交代信息，没有自己的性格 | 加一个次要功能（情绪放大器/价值标尺） |
| 工具人配角 | 需要时出现，不需要时消失 | 给一个成长镜像功能，让TA有自己的弧光 |
| 重复配角 | 两个配角功能完全一样 | 合并为一个，或给第二个换功能 |

## 九维人设

`assets/templates/character-card.md` 已有：核心性格、动机目标、底线恐惧、口癖声线、
能力、关系网。本文件扩展为**九维人设**，补充角色设计时容易遗漏的维度。

### 九维清单

| 维度 | 已有/扩展 | 含义 | 设计要点 |
|---|---|---|---|
| 核心动机 | 已有 | 角色行动的根本驱动力 | 一句话能说清，且与主线绑定 |
| 底线 | 已有 | 绝对不做的事 | OOC的试金石，遇到底线冲突时角色的反应定义TA |
| 口头禅 | 已有 | 语言的标志性特征 | 遮名字能认出是谁说的 |
| 小习惯 | **扩展** | 无意识的小动作/小偏好 | 让角色有「活人感」，非情节性细节 |
| 恐惧 | 已有 | 最怕什么 | 恐惧驱动角色的回避行为，是隐藏标签的入口 |
| 软肋 | **扩展** | 最容易被攻击的弱点 | 不是恐惧（怕什么），而是「被拿捏什么」（人在谁手里） |
| 成长弧方向 | **扩展** | 角色从头到尾会怎么变 | 开书时定方向，不定细节 |
| 与主角关系定位 | **扩展** | 在主角故事中的叙事角色 | 不是剧情关系（朋友/敌人），是功能关系 |
| 命运终局 | **扩展** | 角色的最终归宿 | 开书时定基调，不绑死细节 |

### 新增维度详解

**小习惯**：非情节性的、角色独有的小动作或偏好。不是「每次杀人前擦刀」（那是情节
特征），而是「喝茶时先转三下杯子」「走路喜欢靠左边」「紧张时数地砖」。小习惯的
作用是让角色在非高潮场景也有辨识度，防止「换个人名段落也成立」。

**软肋**：恐惧是「怕什么」，软肋是「被谁/什么拿捏」。一个角色可能不怕死（无恐惧），
但同伴在敌人手里就是软肋。软肋是对手攻击角色的**具体路径**——设计软肋等于设计
未来冲突的引爆点。

**成长弧方向**：角色从头到尾的变化轨迹。方向不定死细节，只定大趋势：
- 上升弧：从弱到强/从迷茫到坚定
- 下降弧：从强到弱/从坚定到动摇（悲剧角色）
- 螺旋弧：表面循环实则上升（每次回到原点但层次更高）
- 转变弧：从一种价值观转向另一种（反派转正/正派黑化）

**与主角关系定位**：不是「朋友/敌人/师徒」这种剧情关系，而是叙事功能关系：
- 镜像（映照主角的另一种可能）
- 对照（与主角形成价值观对比）
- 催化（逼迫主角做选择/改变）
- 锚定（为主角提供情感归属/价值确认）

**命运终局**：角色最终会怎样。开书时定基调（善终/悲剧/开放/转变），不定细节。
命运终局的作用是**约束成长弧方向**——如果终局是悲剧，成长弧就不能是上升弧；
如果终局是转变，中途就要铺垫转变的种子。

## 代入感构建

角色设计的目标不只是「不OOC」，更是让读者**代入**角色。代入感有四个来源。

### 四层代入感

| 层级 | 机制 | 实现手法 | 效果 |
|---|---|---|---|
| 五感沉浸 | 读者通过角色的感官体验世界 | 写角色的具体感知（触觉/嗅觉/痛觉），不只视觉 | 读者「身临其境」 |
| 选择共鸣 | 读者认同角色的选择 | 角色的选择符合读者「如果是我也会这么选」的直觉 | 读者「替角色做决定」 |
| 代价共情 | 读者感受到角色的痛苦 | 写代价的具体感受（不是「很痛」，是具体怎么痛） | 读者「替角色心疼」 |
| 能力渴望 | 读者想要拥有角色的能力 | 金手指/能力的爽感设计（见 `commercial-core.md`） | 读者「想成为TA」 |

### 代入感的优先级

不同题材的代入感主打层级不同：

| 题材 | 主打层级 | 次要层级 |
|---|---|---|
| 爽文/升级流 | 能力渴望 | 选择共鸣 |
| 虐文/悲剧 | 代价共情 | 五感沉浸 |
| 言情/甜文 | 选择共鸣 | 五感沉浸 |
| 悬疑/推理 | 选择共鸣 | 五感沉浸 |
| 热血/燃文 | 能力渴望 | 选择共鸣 |

**建议**：四层中主打一层、兼顾一层。能力渴望可与选择共鸣或五感沉浸搭配，
不必靠受苦或能力代价补足人设；代价共情路线也要写出人物自己的选择，避免只剩受苦。

## 金手指绑架人设

金手指（主角的外挂能力）应与作者选定的卖点、角色目标和行为发生联系。
下列矛盾、代价与局限绑定适用于传统挑战或人物成长路线，是可选设计。
作者已选无敌、无限或无代价路线时，用能力实现具体目标、产生可见成果即可，不自动补限制、软肋或惩罚。
虚构能力的规则与例外按 `fictional-world.md` 核对。

### 绑定原则

金手指的设计回答三个问题：
1. **这个角色会拿金手指做什么？**——能力如何兑现作者选定的卖点与角色目标；挑战路线可进一步关联核心矛盾
2. **金手指按什么规则生效？**——记录已有条件、代价与例外；无条件、无代价也是有效答案
3. **使用后有什么具体成果或变化？**——可以是解决根本问题、推进目标或改变关系，不要求金手指必然留下无法解决的软肋

### 可选的关联模式

| 模式 | 定义 | 示例 |
|---|---|---|
| 矛盾放大型 | 金手指放大角色已有的矛盾 | 角色渴望被认可→金手指给TA力量但让TA被人畏惧（力量与认可的矛盾） |
| 代价绑定型 | 金手指的代价与角色的恐惧/软肋绑定 | 角色恐惧孤独→金手指每次使用会疏远身边人 |
| 局限映射型 | 金手指的局限与角色的成长缺口映射 | 角色缺乏信任→金手指只对信任之人有效，必须学会信任才能变强 |
| 能力兑现型 | 能力直接满足角色愿望并推动具体目标 | 角色想开宗立派→无限资源让TA建宗、培养弟子、探索新功法，无需追加消耗或反噬 |

### 常见失配

检查能力是否兑现本书的设计，不把强度高或没有代价本身判为失败：

- **承诺反复**：已承诺万能、无限或无代价，却临时增加冷却、反噬或封锁；或跳过已明确的限制
- **兑现空转**：奖励不断出现，却看不到角色拿它做什么、目标如何推进；自动升级也应写出成果
- **人设脱节**：角色使用能力的选择与既定动机矛盾，正文没有转变依据；随机获取能力本身可以是设定
- **成长替代型**：仅在作者已选人物成长路线时，检查能力是否无依据跳过承诺的角色转变；直接满足愿望的路线不据此削弱能力

### 绑定检查

设计金手指后检查：
```
金手指：{描述}
作者选定路线与角色目标：{描述}
关联模式：矛盾放大/代价绑定/局限映射/能力兑现，或本书另定
关联描述：{能力如何推动目标、兑现卖点或关联核心矛盾}
生效规则与例外：{已有条件，允许无条件；未定项标待设计，不默认补限制}
代价：{仅填已设定的代价；无代价填“无”}
局限：{仅填已设定的边界；无限或万能按作者定义填写}
与软肋的关系：{仅在选用此设计时填写，否则填“不适用”}
```

## 防 OOC 检查清单（扩展）

`character-consistency.md` 定义了 OOC 的四种典型（行为/语言/能力/关系）和四道防线。
本文件补充**设计阶段的预检清单**——在角色设计完成、动笔之前，用这份清单预防
OOC。

### 设计预检清单

| 检查项 | 问题 | 通过标准 |
|---|---|---|
| 行为一致性 | 三层标签之间有心理逻辑吗？ | 表面→真实→隐藏的转变有因果关系 |
| 语言风格 | 口头禅/声线能遮名字认人吗？ | 抽3段对话，遮名字后能认出是谁说的 |
| 知识边界 | 角色知道什么/不知道什么，清楚吗？ | 角色不会说出超出TA信息来源的话 |
| 情绪反应 | 面对压力/惊喜/背叛的反应与人设一致吗？ | 反应方式与核心性格（三层标签）匹配 |
| 关系态度 | 对不同人的态度有差异化吗？ | 对上级/下级/朋友/敌人的态度各不相同 |
| 成长弧约束 | 成长弧方向与命运终局一致吗？ | 上升弧不配悲剧终局（除非是「上升后坠落」的设计） |
| 金手指匹配 | 能力是否符合作者路线，并与角色目标或人设发生联系？ | 规则、例外与具体兑现一致；无敌、无限、无代价可通过，不要求附加限制 |
| 软肋设计（条件项） | 作者选用软肋设计时，弱点是否具体、可理解？ | 可用「朋友X在敌人Y手里」等已定处境核对；未选此设计则不适用，不据此阻断或追加弱点 |

### 预检与日常检查的关系

- **设计预检**（本文件）：开书/加新角色时一次性过，目标是把 OOC 风险在设计阶段消除
- **日常检查**（`character-consistency.md`）：每章写后过，目标是发现连载中的 OOC 漂移

设计预检做好了，日常检查的负担会大幅减轻——80% 的 OOC 来源于设计阶段就没想清楚
（三层标签没有逻辑、知识边界模糊、金手指规则不清），而不是写作中忘了人物卡。

### 预检失败的处理

预检不通过时，不要「先写再说，后面再补」。OOC 的根源在设计阶段，越早修复成本越低：

- 三层标签无逻辑 → 重新设计隐藏标签，找到与真实的心理连接
- 语言风格不区分 → 给每个角色写3段示例台词，对比调整
- 知识边界模糊 → 列出角色「知道什么/不知道什么」的清单
- 金手指不匹配 → 回到绑定三问，核对作者路线、有效规则与角色目标；只修实际缺口，不因无代价或无限制而重设能力

修复后再动笔。一个设计阶段的预检，能省掉后期几十章的 OOC 补丁。
