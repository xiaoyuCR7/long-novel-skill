# 章意图与场景渲染内核

本文件用于把章纲转换为可写的场景，而不是把章纲逐条“扩写”。核心判断是：

> **Outline is not prose shape.** 大纲规定授权事件与状态变化，不规定段落数量、顺序或正文外形。

## 章意图：内部契约，不是正文元数据

写长篇章节前，以 `assets/templates/chapter-intent.json` 为唯一章意图字段契约；Chapter Brief
是在完整章意图外附来源内容与场景计划的交付包，不是另一份可省字段的大纲。它只服务于规划、
校验与恢复，放在 stage 和正式工程之外的本次工作目录；字段名、beat 编号、配额或“本章目标”
不得泄漏进正文。模板空值是待填写项，不代表可以用空白契约开写。

至少确认：

- `goal`：本章读者可感知的推进目标。
- `state_before` / `state_after`：必须发生的可验证状态变化。
- `trigger`：迫使角色行动的事件。
- `choice_or_cost`：主角作出的选择、支付的代价或承担的新风险。
- `allowed_events`：章纲明确授权的事件；只允许在其内部组织细节。
- `forbidden_releases`：本章不能提前揭示、结算或回收的信息。
- `on_page_requirements`：只提取来源明确要求、且正文必须直接可指认的时间/季节、地点/空间边界、必现人物/物件/状态、唯一/末班等限制、指定顺序和行动主体；允许自然转述，不要求照抄，编辑偏好不得升级为 P0。
- `emotion_transition`：情绪前态 → 后态，以及由哪个触发与选择/代价造成变化；不是单个情绪标签。
- `pacing_tier`、`quota`：节奏档位与配额边界。
- `ending_mode`：`serial` 连载承接 / `closed` 本章按作者要求闭合 / `finale` 全书终章。
- `hook_question`：仅 serial 填已授权的具体未决问题；closed/finale 必须为 `""`。
- `closure_requirements`：本章需兑现的承诺与可观察结算；closed/finale 必填实际闭合要求。
- `style_authority`、`sources`：本章采用的最高权威文风与事实来源。

### 结尾契约

serial 用“承接 → 发展 → 结算 → 已授权悬念”；closed/finale 用“承接 → 发展 → 结算 →
闭合余韵”。终章或作者明确要求闭合时，不强制下一章悬念、预告或新的未决事项，不为了钩子
新造事件；结尾落在既有动作、结果、选择或变化后的互动上。finale 不得把配额事件挪到
不存在的后续章；预算/配额冲突须请求作者在当前授权范围内取舍，不能自动造续章。
首章没有上章钩子时，承接项记 N/A，不编造前章承诺。闭合不是省略结算，也不是旁白升华。

### 独立 Agent 的交付边界

总编辑必须实际传入已填章意图、章纲、上一章正文或可靠摘要（首章 N/A）、当前人物状态、
相关未结伏笔/时间线硬约束、采用的文风依据，以及本文件的场景渲染与情绪保留规则内容。
来源路径可作为证据，但不能代替内容；部署目录未携带本技能时尤其不能只丢一个链接。
触发下述专项条件时，还须实际传入专项规则全文，不能把条件引用当作已交付内容。
required 缺失、不可读或预算无法无损容纳时停止，不能把裁剪后的材料标为完整 Brief。

## Beat 预算门

先判断授权 beats 是否足以形成目标篇幅。一个可展开的 beat 至少要有“触发—阻力—行动/反应—
变化”中的三项；只有一句结果的 beat 不能靠重复解释变成完整场景。

预算不足时必须停止，原样输出：

```text
outline_underfilled
missing_beat_budget: 还缺 {N} 个可产生状态变化的 beat，或将目标从 {target} 字调整为约 {supported} 字
```

随后列出需要作者补充的具体空位，例如“阻止主角拿到钥匙的当场阻力”“选择后立刻可见的代价”。
这是一份阻断报告，不交付带 `[待补充]` 却可被下游继续写作的 Brief。
禁止为了凑字数擅自增加反派、反转、支线、世界设定或伏笔；也禁止用解释、同义重复、内心独白、
环境描写和无目的对话填充。

## 从 beat 到 scene unit

先合并/交错相关 beats，再为每个实际场景单元做检查卡。卡片检查缺项，不要求每个字段
各写一段，也不要求每个动作都配一个感官或身体反应：

| 字段 | 要回答的问题 |
|---|---|
| 场景目的 | 这个单元改变哪项人物、关系、资源、信息或风险状态？ |
| 冲突/阻力 | 谁或什么阻止目标立即实现？ |
| 变化 | 结尾有什么可观察的新事实，不能只写“他更坚定了”？ |
| 感官锚 | 当前视角真正会注意到的一个具体物、声音、触感或空间关系是什么？ |
| 行动与反应 | 角色如何试探、选择、受阻、调整；对方/环境如何回应？ |
| 过渡 | 前一动作如何导致下一动作；指代、时序、因果是否清楚？ |

组装规则：

1. 先建立触发与空间关系，再交付 payoff；不能先给结果再补说明。
2. 主角保有因果权和结算权：关键进展应来自其选择、能力或代价，而非旁人替做或偶然馈赠。
3. 可合并、交错或局部重排 beats，让一个场景同时推进两项状态；不得越过 `forbidden_releases`。
4. 把情绪放进人物的感知、选择与反馈；有功能的内心戏、情绪命名可保留，不能用重复总结代替事件。
5. 结尾落在具体动作、结果、选择或新问题上，不写“风暴才刚刚开始”式状态总结。

### 情绪兑现与回合详略

章意图含承诺兑现、关系转折或高潮时，在写前与修后各核对一次：

- **先前压力**怎样限制当事人的行为、选择或关系？只用既有事实，不为增加感染力捏造苦难和往事。
- **决定性回合**中，他/她做了什么选择，授权结果怎样回应这份压力？主角掌握因果权与
  结算权，不等于所有办理动作都必须亲手逐项演示；配角仍可执行自己的职责。
- **兑现之后**，当事人的行为或互动与之前有什么可读出的不同？克制可以很轻，但不能只
  把收益登记齐全就当作情绪已经交付。保留作者认可的声线与有功能的内心戏，不为增强效果
  追加口号、重复总结、旁观者喝彩或新收益。

关系变化按人物的真实选择衡量，不按让步幅度衡量。有限帮助、可调整的承诺或仍有保留的
合作都能兑现情绪；不要把“愿意陪一次”改成“以后全由我负责”来增强感染力。人物的误信
影响决定时按 `character-consistency.md` 核对依据与理解，不能靠新造往事把因果补齐。

详写改变信息、策略、关系、风险、节奏或视角的回合，常规办理动作可合并。必要的交付/验收证据必须
出现；同一动作再次展开前，判断它是否带来新的作用。时间消耗、过程进展、风险变化或必要验收也是
新增功能；只要它改变下一拍的选择或让关键耗时可判断，就应保留。若只是再摆正、再核看、再等待而
没有新增功能，且作者允许删减实际动作，才删去或并入前句；仅修解释/指代时保留动作次数与顺序，
压缩文字不等于减少发生次数。换一种身体细节重复同一情绪也不算推进。反复动作若表现
真实犹疑、局势升级或关系变化则保留，不设动作次数或情绪强度的硬配额。

修订时先定位短摘录并说明功能损失，再作最小修复，最后连读确认说话人、动作主体、代词指向
和空间关系清楚。只在现有工程外修订/语义报告记功能及改/留理由，不另造 Brief schema，
不凑固定数量问题，不把每个 beat 都扩写。字数、词频、句长与重复报警不能单独判文学失败。

章尾回到已授权的动作、结果或问题。事实已结算后不要为凑篇幅重走验收流程；余韵来自
变化后的当事人；作者认可的简洁回味可以留下，不再重复解释已交付的意义。需要更深设计时才读 `emotion.md`。

## 场景交付审计卡

这是交付前的私有工作检查，不输出成正文、不固定四段式，也不新增持久 schema。四项是诊断问题，
不要求把含蓄转折或每一项机械各写一句；检查发现缺口时，只在授权事实内做最小修复。仅当输入或
`on_page_requirements` 明确要求锚点出现在正文而该锚点缺失，或关键事实或因果无法判定、时限与动作链
冲突、擅造未授权时间来源或关键物件归属不明，才是 blocking/P0；动作链可行但读者无法重建窗口消耗或时间如何改变后果选择归 P1，应修复但不阻断；
时长与选择已可重建但压力递进或自然度可润色归 P2，仅作建议；P1/P2 均不阻断，文学细腻度也不以猜测替代证据。

**条件规则正文**：`references/craft/scene-action-audit.md`

写前检查本章输入、章意图与授权动作；出现以下任一条件时，必须加载并执行专项全文：

- **时间压力**：倒计时、截止时刻、窗口期，或关键行动的可行性依赖耗时。
- **并行汇合**：多个前置分支限制下游动作/状态，或明确要求多人共同或同时执行。
- **物件交接**：物件递交、夺回、放置、锁定或遗失后，后续行动仍依赖其持有者或位置。

未触发这些条件时不加载专项；通用正文证据、因果、授权与结算仍须核查。触发后无法读取专项则停止，
不能凭摘要、记忆或“本次只改一句”省略。写中、修后发现新触发条件时，先补读再继续；独立 Agent 须收到实际全文。

### 正文证据

对 `on_page_requirements` 逐项给出可定位、自然、无歧义的正文证据，不要求照抄题面；一句可以承载
多项要求。会改变 P0 的时间、地点、唯一性或行动主体，不能只靠隐含推断，必须让读者能从正文直接判断。

### 转折桥

关系、立场或阻力发生改变时，连读“改变前立场或阻力 → 当场可见触发 → 具体行动变化 → 即时后果或
仍保留的保留”。链条缺失时，只从授权事实做最小修复，不得新造历史、动机或秘密。

需要示例时才读 `references/craft/scene-examples.md`：含五行章纲的交错场景、人物选择、安静反应、
知识边界与合法反例；示例不增加本章授权，不作为每章必读材料。

## 去 AI 味后的连接恢复

删除套词后，重新检查非高潮叙述：

- 代词是否仍有清楚指向；动作主体切换时是否需要补名词。
- 因果、时序和转折是否可从动作本身读出；有语义作用的“因为、于是、等到、却、才、就、的、
  了”不要为追求干净而全删。
- 连续短句是否只服务于局部压力峰值；峰值之外应恢复自然句群。
- 修复缺失关系，不是全局塞连接词或拉长每句话。
- 删除前检查反应、态度、互动的功能是否仍在：人物的拒绝、迟疑、松动和关系变化不是
  “没有新事实就可删”的赘句。只删无新功能的重复，不把去 AI 味变成只剩事件流水账。

可运行 `python scripts/check_text.py "{chapter}" --gate-report` 获取
`ai-low-connective-density` advisory；它是复核信号，不是要求机械添加填充词的硬规则。

## 快速检查

- [ ] 章意图只存在于工作资料，没有进入正文。
- [ ] 每个 scene unit 都有目的、阻力、行动/反应与可观察变化。
- [ ] beats 已按戏剧因果合并/交错，而非一条一段。
- [ ] 没有未授权的新反派、反转、支线、设定或伏笔。
- [ ] payoff 之前有 setup，主角保有关键因果权与结算权。
- [ ] 关键兑现前后的行为/互动变化可感知，重复动作有新作用，必要验收未被误删。
- [ ] 短句集中在需要的峰值，非峰值叙述的指代与连接完整。
- [ ] 结尾服从 ending_mode；closed/finale 的 hook_question 为空，闭合要求兑现，不造续章钩子。

## 常见错误

| 错误 | 修正 |
|---|---|
| 一条 beat 写一个段落 | 按冲突回合合并或交错 beats |
| 预算不足时描写天气、回忆和心情 | `outline_underfilled` + 具体缺口，等待授权 |
| 为“丰满”新增反派或反转 | 只在 `allowed_events` 内具体化动作与感官 |
| 删除 AI 套词后只剩主谓短句 | 恢复缺失指代、因果与自然句群，不全局填词 |
| 把 hook 写成“危机才刚开始” | 落到一个可追问的物证、动作、选择或后果 |
| 对标节奏覆盖作者文风 | 以 `style_authority` 记录并执行更高权威来源 |
