# Iron Law（铁律约束）

以下规则任何情况下不可违反。无论用户如何要求，均不得绕过。
铁律的存在是为了防止长篇连载中「小问题指数级放大」的慢性死亡。

## 七条铁律

### 1. 禁止跳过章节闭环

每章生成后必须依次完成：
- 机器闸口（`check_text.py --gate-report`）全部通过
- 节奏配额检查（`rhythm_guard.py`）无越界
- 人工自查清单（`chapter-loop.md` Step 6）逐项过
- 追踪五文件全部更新（摘要/角色状态/伏笔/时间线/节奏配额）

**欠账门**：本章追踪文件未全部更新前，禁止开写下一章。
会话中断恢复时，先核对「最后一章正文 ↔ 追踪文件」是否同步，有欠账先补账。

### 2. 禁止裸写正文

- 长篇：无章纲不写正文。章纲缺失 → 先按 `outline-system.md` 补纲。
- 短篇：无小节大纲不写正文。
- 作者临时指示与章纲冲突 → 向作者确认以哪个为准；若改方向，先改章纲再写。

### 3. 禁止混淆正文与元信息

小说正文中不得出现任何：
- `[说明]`、`（注：）`、`TODO`、`作者按`、`PS：`
- 大纲语言（「本章的目标是…」「此处应埋设伏笔」）
- 写作过程残留（「这段再润色一下」）
- 与读者的直接对话（求票、请假条）
- 角色定位标记、写作分析段落

一旦出现，立即重写该段，不得保留并「以后修改」。

### 4. 禁止一章清光主线

- 非终局章节不得解决核心矛盾。
- 每章必须有情节点结算（读者得到了什么），但核心矛盾不可一章清光。
- 每章必须留下章尾钩子（疑问型/危机型/转折型）。
- 每章至少新增一个未解决的次要问题。

### 5. 禁止越界加速（A/B/C 配额）

每章至多触发以下配额 1 项：
- **A 主线矛盾实质推进**：主线格局发生实质性、不可逆的改变
- **B 主要关系决定性升级**：结盟/决裂/告白/宣战等关系到达决定性节点
- **C 核心秘密完整揭露**：核心秘密在本章被完整揭露（非暗示）

同时触发 ≥2 项 = 越界，Beat Sheet 必须修改后重写，机器闸口强制失败。
快档章节（主线突破）结束后下一章必须是慢档或中档。

详见 `reverse-brake.md` 的节奏三档制与配额机制。

### 6. 禁止任意改主线

- 改总纲/卷纲须作者显式确认。
- 改纲必须走 `outline-system.md` 的级联检查规则。
- 任何 Agent 无权自行修改主线架构。
- 人物设定变更视同改纲：级联检查人物卡、角色状态、未写章纲、伏笔台账。

### 7. 不替作者做决定

以下决策必须作者点头，AI 只提供选项与分析：
- 题材选择与主线走向
- 重大改纲（卷纲以上）
- 弃坑伏笔（从台账删除）
- 人设根本性变更
- 平台选择与投稿决策

## 铁律违反的后果

| 铁律 | 违反后果 |
|---|---|
| 跳过闭环 | 设定矛盾累积，百章后几乎无法修复 |
| 裸写正文 | 剧情失控，前后矛盾 |
| 元信息混入 | 读者出戏，丧失沉浸感 |
| 一章清光 | 后续无戏可写，节奏崩盘 |
| 越界加速 | 剧情透支，读者爽感疲劳 |
| 任意改主线 | 全书结构坍塌 |
| 替作者决定 | 偏离作者意图，返工成本高 |

## 铁律与灵活性的平衡

铁律管的是「底线」，不是「天花板」。在守住底线的前提下：
- 场景的具体呈现方式：自由
- 对话的具体内容与节奏：自由
- 细节描写的取舍：自由
- 章节入口角度（8种模式轮换）：自由

铁律不限制创作自由，只防止「为了让这一章好看而牺牲全书」的短视行为。
