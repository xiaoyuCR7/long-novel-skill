# 信息团：概念、排版与密度控制

信息团是介于「情节点」和「剧情单元」之间的核心信息单元。`plot-budget.md` 管情节点
的字数预算，`opening.md` 管开篇的信息释放顺序——本文件管「信息团」这个中间层级的
定义、排版与密度控制，填补情节点预算与开篇信息释放之间的衔接空白。

## 一、信息团定义

### 什么是信息团

信息团 = 一段剧情要传达的**核心信息单元**。一个信息团对应一个「读者需要知道什么」，
而不是「角色做了什么」。

```
剧情层级：
  剧情单元（卷/篇章级别）── 一个大故事弧
    └─ 信息团（本文件管辖）── 一段剧情要传达的核心信息
        └─ 情节点（plot-budget.md 管辖）── 具体的事件/动作/对话
```

### 信息团 vs 情节点

| 维度 | 信息团 | 情节点 |
|---|---|---|
| 定义视角 | 读者视角：「读者需要知道什么」 | 作者视角：「角色做了什么」 |
| 粒度 | 一个信息团通常包含 1-3 个情节点 | 一个情节点是单个事件/动作/对话 |
| 概括性 | 必须能用一句话概括 | 可以是「主角到达擂台」这样的动作描述 |
| 预算归属 | 信息团没有独立字数预算，其字数 = 所含情节点预算之和 | 有情节点字数预算（密/中/疏三级） |
| 数量控制 | 一章最多 4 个信息团 | 一章通常 5-12 个情节点 |

### 信息团的一句话概括规则

每个信息团必须能用一句话概括，且这句话必须表达「读者知道了什么」，而非「角色做了什么」。

- 正确概括：「读者知道：青云宗在暗中监视主角的每一步行动」
- 错误概括：「主角发现有人跟踪他」（这是情节点描述，不是信息团概括）
- 正确概括：「读者知道：主角的金手指并非独一无二，还有另一个拥有者」
- 错误概括：「主角遇到另一个穿越者」（这是情节点描述）

### 信息团的构成

一个信息团由以下要素组成：

```
信息团 {
  核心信息：一句话概括（读者知道什么）
  承载情节点：1-3 个情节点（plot-budget.md 的密/中/疏点）
  信息载体：挂在什么动作/对话/物件上（不能是说明文，参见 anti-ai-style.md 防设定复述）
  信息差设计：三层信息差（见第五节）
  释放阶段：属于开篇/铺垫/高潮/余波哪个阶段
  与前后信息团的逻辑关系：递进/对比/印证/暗示
}
```

## 二、信息团之间的逻辑递进要求

信息团不是孤立的——它们之间必须有逻辑递进关系，否则读者会觉得「信息是散的」。

### 五种递进关系

| 关系类型 | 定义 | 示例 | 典型用法 |
|---|---|---|---|
| 因果递进 | 信息团 A 是信息团 B 的原因 | A: 读者知道反派在收集某种药材 → B: 读者知道这种药材能炼制控制人心的丹药 | 主线推进、悬疑线 |
| 层级递进 | 信息团 B 是信息团 A 的深化/细化 | A: 读者知道主角有金手指 → B: 读者知道金手指的具体规则和限制 | 金手指展开、世界观深化 |
| 对比递进 | 信息团 B 与信息团 A 形成对比或反差 | A: 读者知道宗门表面上对主角很好 → B: 读者知道宗门高层在暗中打压主角 | 反转铺垫、人设深化 |
| 印证递进 | 信息团 B 印证了信息团 A 的暗示 | A: 读者知道主角怀疑盟友有问题 → B: 读者知道盟友确实在暗中做手脚 | 伏笔回收、悬念推进 |
| 暗示递进 | 信息团 A 暗示了信息团 B 的存在 | A: 读者知道某件物品很特殊 → B: 读者知道这件物品与主线谜团有关 | 伏笔埋设、悬念铺设 |

### 递进失效的三种情况

1. **并列无递进**：两个信息团之间没有逻辑关系，只是「主角又知道了一件事」。
   - 例：信息团 A「读者知道宗门有五大长老」→ 信息团 B「读者知道隔壁宗门有三大护法」
   - 问题：两个信息团没有递进，读者觉得信息是灌进来的
   - 修复：要么合并为一个信息团，要么建立递进关系（如 A 是 B 的原因：因为五大长老，
     所以隔壁宗门急缺护法）

2. **重复递进**：信息团 B 传达的信息与信息团 A 本质相同，只是换了说法。
   - 例：信息团 A「读者知道主角很强」→ 信息团 B「读者知道主角比同辈强很多」
   - 问题：B 没有给出新信息，只是强化了 A，读者觉得「我已经知道了」
   - 修复：删除 B，或把 B 升级为一个新的信息维度（如「主角的强有代价」）

3. **跳跃递进**：信息团 A 和 B 之间的逻辑跨度太大，读者跟不上。
   - 例：信息团 A「读者知道主角在练气期」→ 信息团 B「读者知道主角能打败元婴期」
   - 问题：中间缺少「主角为什么能越级」的信息团，读者觉得不合理
   - 修复：在 A 和 B 之间插入中间信息团（如金手指的具体能力）

### 递进关系的检查方法

列出本章所有信息团的一句话概括，检查相邻两两之间是否符合五种递进关系之一。
如果某一对不符合，标记为「递进断裂」。

```
本章信息团递进链：
信息团 1「读者知道：主角被宗门高层盯上了」
  ↓ 因果递进
信息团 2「读者知道：盯上主角的原因是他表现出的修炼速度太快」
  ↓ 层级递进
信息团 3「读者知道：主角之所以修炼快，是因为金手指的特殊机制」
  ↓ 印证递进
信息团 4「读者知道：金手指的特殊机制与宗门老祖的秘密有关」
```

## 三、信息团排版

信息团排版 = 在开篇/铺垫/高潮各阶段，分配哪些信息团、以什么优先级释放。

### 开篇阶段（第 1-3 章）

`opening.md` 定义了开篇的信息释放顺序：危机感 > 人设 > 金手指暗示 > 世界观。
本文件将这一顺序映射到信息团层面。

| 章 | 信息团数量 | 信息团内容 | 优先级分布 |
|---|---|---|---|
| 第 1 章 | 1-2 个 | 信息团 1：危机感（读者知道主角面临什么麻烦）；信息团 2：人设（读者知道主角是什么样的人） | 危机感 50% + 人设 50% |
| 第 2 章 | 2 个 | 信息团 3：危机升级（麻烦比看起来更大）；信息团 4：金手指暗示（主角有不寻常的能力/身份） | 危机感 40% + 金手指暗示 30% + 人设深化 30% |
| 第 3 章 | 2 个 | 信息团 5：第一个兑现（读者看到主角的能力/选择带来的结果）；信息团 6：世界观的第一个碎片（只在需要解释兑现时释放） | 兑现 50% + 世界观 20% + 延展危机感 30% |

**开篇信息团的特殊约束**：
- 每个信息团必须挂在动作或冲突上（`opening.md` 的开篇禁忌：「大段背景交代」= 信息团没有挂载点）
- 第 1 章的信息团 1 和 2 必须在前 300 字内至少启动一个（`opening.md` 自检：「第一页有没有出现压力源」）
- 前 3 章的信息团总数不超过 6 个（平均每章 2 个，读者大脑的信息处理上限）

### 铺垫阶段（慢档/中档）

铺垫阶段是信息团释放的主力阶段。节奏慢，信息团可以有更充分的展开空间。

| 档位 | 信息团数量 | 信息团类型 | 优先级分布 |
|---|---|---|---|
| 慢档 | 2-3 个 | 人设深化、世界观碎片、微型伏笔、关系信息 | 人设 30% + 世界观 30% + 关系 20% + 伏笔 20% |
| 中档 | 2-3 个 | 矛盾升温信息、线索信息、势力信息 | 矛盾 40% + 线索 30% + 势力 30% |

**铺垫阶段的信息团节奏**：
- 每 2 章至少释放 1 个与主线谜团相关的信息团（即使是碎片）
- 世界观信息团必须「需要时才给」——主角走到宗门藏经阁 → 才释放「藏经阁的规则和历史」
- 慢档章的信息团必须有 1 个与读者契约相关（`reader-contract.md`：即使是慢档，也要兑现读者契约的微承诺）

### 高潮阶段（快档）

高潮阶段信息团释放最少，以动作和情绪为主。信息团在高潮中的作用是「让读者理解高潮的意义」。

| 高潮子阶段 | 信息团数量 | 信息团类型 |
|---|---|---|
| 高潮前夜（过渡章） | 3-4 个 | 集中释放与高潮直接相关的关键信息（危机是什么、敌人在哪里、主角有什么筹码） |
| 高潮爆发（快档章） | 1-2 个 | 仅释放「读者必须现在知道」的信息（如反转的真相碎片、金手指的关键机制） |
| 高潮结算（快档章末） | 1 个 | 高潮的意义信息（读者知道这一战的代价和后果） |

**高潮阶段的信息团约束**：
- 高潮爆发期间，信息团必须是「动作中自然带出的信息」，不能是「停下来解释的信息」
- 如果高潮中需要释放一个复杂信息团（如反转真相），用对话或闪回承载，不用叙述说明文
- 高潮结束后（余波阶段），再释放高潮中未解释完的信息团

### 余波阶段（慢档）

余波阶段的信息团释放有三个任务：

1. **解释高潮中未解释的信息**：高潮中读者可能只看到了「结果」，余波中释放「原因」
2. **为下一轮铺垫埋种子**：至少 1 个信息团指向下一阶段的主线方向
3. **人设深化**：高潮改变了角色，读者需要通过余波信息团理解「角色变了什么」

### 全卷信息团分布总览

| 卷内位置 | 信息团数量（累计） | 信息团密度 | 阶段重点 |
|---|---|---|---|
| 卷首（第 1-3 章） | 4-6 个 | 低（每章 1.5-2 个） | 危机感 + 人设 + 金手指暗示 |
| 卷中铺垫（慢档+中档交替） | 10-15 个 | 中（每章 2-3 个） | 世界观 + 势力 + 线索碎片 |
| 卷中高潮前夜 | 3-4 个 | 中高（每章 3-4 个） | 关键信息集中释放 |
| 卷中高潮 | 2-3 个 | 低（每章 1-2 个） | 动作驱动，信息极少 |
| 卷中余波 | 4-6 个 | 中（每章 2-3 个） | 高潮解释 + 新方向铺垫 |
| 卷末高潮 | 3-5 个 | 低→中高 | 真相碎片 + 卷末钩子 |
| 全卷合计 | 约 30-40 个信息团 | — | — |

## 四、信息团密度控制

信息团密度 = 一章中释放的信息团数量。密度过高 = 读者消化不良；密度过低 = 读者觉得水。

### 一章最多几个信息团

| 章节类型 | 信息团上限 | 原因 |
|---|---|---|
| 慢档日常章 | 3 个 | 慢档以深度为主，不是信息轰炸 |
| 中档推进章 | 3 个 | 中档是信息释放的主力，但仍有上限 |
| 快档高潮章 | 2 个 | 高潮以动作和情绪为主，信息团最少 |
| 高潮前夜过渡章 | 4 个 | 唯一允许 4 个信息团的类型，但要控制信息团的大小 |
| 开篇第 1 章 | 2 个 | 读者还没建立认知框架，信息团越少越好 |

**绝对上限**：任何一章不超过 4 个信息团。超过 4 个 = 信息过载，必须拆分到多章。

### 信息团密度与阅读体验

| 密度 | 每章信息团数 | 阅读体验 | 风险 |
|---|---|---|---|
| 过低 | 0-1 个 | 读者觉得「这章什么都没说」 | 弃书（内容空洞） |
| 偏低 | 1-2 个 | 读者觉得「节奏慢但舒服」 | 慢档可接受，中档偏水 |
| 适中 | 2-3 个 | 读者觉得「信息量刚好」 | 理想状态 |
| 偏高 | 3-4 个 | 读者觉得「信息量大，需要消化」 | 连续 2 章偏高 = 疲劳 |
| 过高 | 4+ 个 | 读者觉得「信息轰炸，记不住」 | 必须拆分 |

### 密度调节方法

**密度过高时的调节**：
1. 合并同类信息团：两个信息团如果传达的是同一方向的信息，合并为一个
2. 推迟非紧急信息团：将非当前场景必须的信息团推迟到后续章节
3. 拆分章节：如果信息团确实都必要，拆成两章

**密度过低时的调节**：
1. 深化现有信息团：不是增加新信息团，而是把现有信息团展开得更充分
2. 检查是否有遗漏信息：读者看完这章后，有没有「应该知道但不知道」的信息
3. 添加微型伏笔信息团：在不增加认知负担的前提下，埋一个微型伏笔

### 密度与 plot-budget.md 的对接

`plot-budget.md` 的情节点预算制与信息团密度的关系：

- 一个信息团的字数 = 其所含情节点预算之和
- 如果信息团密度正常（2-3 个/章），但情节点预算之和远超章目标 → 情节点预算标高了，需要压缩
- 如果信息团密度偏高（4 个/章），但情节点预算之和在章目标内 → 每个信息团展开不足，需要减少信息团数量、加深展开
- 如果信息团密度偏低（1 个/章），但情节点预算之和已达章目标 → 信息团内部展开过度，检查是否注水

## 五、信息团的「信息差」设计

信息差 = 同一信息团中，不同角色（和读者）知道的信息之间的差异。信息差是悬念和
爽感的来源——读者知道而角色不知道 = 期待感；角色 A 知道而角色 B 不知道 = 戏剧张力。

### 三层信息差模型

```
┌─────────────────────────────────────────┐
│           读者知道的信息                  │
│  ┌─────────────────────────────────┐    │
│  │       角色 A 知道的信息           │    │
│  │  ┌─────────────────────────┐    │    │
│  │  │   角色 B 知道的信息       │    │    │
│  │  │                         │    │    │
│  │  └─────────────────────────┘    │    │
│  └─────────────────────────────────┘    │
└─────────────────────────────────────────┘
```

### 四种信息差配置

| 配置 | 读者知道 | 角色 A 知道 | 角色 B 知道 | 效果 | 典型用法 |
|---|---|---|---|---|---|
| 读者全知 | 全部 | 全部 | 部分 | 读者有上帝视角，期待角色 B 的反应 | 打脸爽点、装逼桥段 |
| 读者等于主角 | 主角知道的 | 主角知道的 | 视情况 | 读者和主角一起探索，代入感最强 | 主线推进、悬疑探索 |
| 读者小于主角 | 部分 | 全部 | 部分 | 读者被主角蒙在鼓里，回收时恍然大悟 | 反转伏笔、主角隐藏实力 |
| 读者大于角色 | 全部 | 部分 | 部分 | 读者替角色着急，戏剧张力最强 | 角色误会、命运交错 |

### 信息差的释放时机

| 信息差类型 | 建立时机 | 释放时机 | 释放方式 |
|---|---|---|---|
| 读者知道 > 角色 A 知道 | 信息团释放时，只给读者，不给角色 A | 角色 A 发现真相时（爽点） | 角色 A 的反应 + 旁观者见证 |
| 角色 A 知道 > 角色 B 知道 | 信息团释放时，只给角色 A 和读者 | 角色 B 发现真相时（冲突点） | 对峙/揭露/决裂 |
| 角色 A 知道 > 读者知道 | 信息团释放时，只给角色 A | 反转揭示时（认知颠覆） | 倒序/闪回/第三方揭示 |

### 信息差设计的禁忌

1. **信息差过大**：读者完全不知道的信息太多 → 读者觉得「什么都看不懂」，弃书
2. **信息差过小**：所有角色和读者知道的一样多 → 没有戏剧张力，平淡
3. **信息差维持过久**：读者知道而角色不知道的信息，维持超过 10 章 → 读者觉得「角色太蠢」
4. **信息差释放太草率**：一个精心建立的信息差，一句话就释放了 → 浪费了戏剧张力

## 六、与 opening.md 的对接

`opening.md` 定义了开篇的信息释放顺序和前三章的分工，本文件将其映射到信息团层面。

### 对接点一：信息释放顺序 → 信息团优先级

`opening.md` 的信息释放顺序：
```
先认人 → 再懂处境 → 然后才轮得到世界
```

映射到信息团：
- 第 1 章信息团 1 = 人设（「先认人」）
- 第 1 章信息团 2 = 危机感（「再懂处境」）
- 第 2-3 章信息团 = 金手指暗示 + 世界观碎片（「然后才轮得到世界」）

### 对接点二：前三章分工 → 信息团分配

| opening.md 分工 | 信息团任务 | 信息团数量 |
|---|---|---|
| 第 1 章：勾住 | 信息团 1：人设 + 信息团 2：危机感 | 2 个 |
| 第 2 章：加码 | 信息团 3：危机升级 + 信息团 4：金手指暗示 | 2 个 |
| 第 3 章：兑现 | 信息团 5：第一个兑现 + 信息团 6：世界观碎片 | 2 个 |

### 对接点三：开篇禁忌 → 信息团约束

`opening.md` 的开篇禁忌映射到信息团约束：

| 开篇禁忌 | 信息团约束 |
|---|---|
| 大段背景交代 | 信息团必须挂在动作/冲突上，不能是说明文 |
| 群像开场 | 信息团的「三层信息差」中，角色 B 不能太多（第 1 章出场有名字角色 ≤4 个） |
| 梦境/穿越过程注水 | 信息团不能只释放「世界设定」而不释放「危机感」 |
| 把高能剧情攒到后面 | 信息团 1-2 必须包含「危机感」——读者三章内必须感知到「这本书有戏」 |

## 七、与章纲情节点预算的对接

`plot-budget.md` 定义了情节点预算制（密/中/疏三级），本文件定义信息团排版。
两者的对接关系如下：

### 对接点一：信息团 → 情节点预算映射

章纲编写时，先确定本章的信息团（读者知道什么），再将每个信息团拆分为情节点并标注预算。

```
章纲编写流程：
1. 确定本章信息团（本文件）
   ├─ 信息团 1：「读者知道：{核心信息}」
   ├─ 信息团 2：「读者知道：{核心信息}」
   └─ 信息团 3：「读者知道：{核心信息}」

2. 每个信息团拆分为情节点（plot-budget.md）
   信息团 1 → 情节点 1.1 (密:300) + 情节点 1.2 (中:200)
   信息团 2 → 情节点 2.1 (中:200) + 情节点 2.2 (中:150) + 情节点 2.3 (疏:40)
   信息团 3 → 情节点 3.1 (密:400) + 情节点 3.2 (中:200)

3. 求和校验（plot-budget.md）
   Σ = 300+200+200+150+40+400+200 = 1490
   章目标 = 2000
   1490 < 2000 → 预算不足，需增加展开
```

### 对接点二：信息团数量与情节点预算的关系

信息团数量直接影响情节点预算的合理性：

| 信息团数量 | 情节点数量（预计） | 每个信息团的平均情节点数 | 风险 |
|---|---|---|---|
| 1 个 | 3-5 个 | 3-5 个 | 信息团展开过度，可能注水 |
| 2 个 | 4-7 个 | 2-3.5 个 | 理想状态 |
| 3 个 | 6-9 个 | 2-3 个 | 理想状态 |
| 4 个 | 8-12 个 | 2-3 个 | 情节点过多，可能每个都展开不足 |

### 对接点三：章纲模板中的信息团字段

建议在章纲模板中增加信息团字段，作为情节点清单的前置步骤：

```markdown
## 信息团清单（本章读者需要知道什么）

> 每章 2-4 个信息团。每个信息团一句话概括（读者视角）。
> 信息团之间必须有逻辑递进关系。

1. 读者知道：{核心信息} — 优先级：{危机感/人设/金手指暗示/世界观}
2. 读者知道：{核心信息} — 优先级：{...}
3. 读者知道：{核心信息} — 优先级：{...}

递进关系：{1→2 的关系} → {2→3 的关系}

## 情节点清单（带字数预算）

> 密(≥250)/中(100-200)/疏(≈40)三级预算，求和 Σ ∈ [目标字数, 目标字数 × 1.1]。
> 每个情节点标注所属信息团。

1. {情节点} (密:___) — [信息团 1]
2. {情节点} (中:___) — [信息团 1]
3. {情节点} (中:___) — [信息团 2]
...
```

### 对接点四：预算偏差时的信息团诊断

当 `plot-budget.md` 的预算偏差发生时，从信息团角度诊断：

| 偏差情况 | 信息团诊断 | 处理 |
|---|---|---|
| 全章实际 >> 章目标 | 某个信息团展开过度（注水） | 定位超预算的信息团，压缩其情节点 |
| 全章实际 << 章目标 | 信息团数量不足或展开不足 | 增加信息团或深化现有信息团 |
| 某点实际 >> 预算 | 该信息团的承载情节点注水 | 检查该信息团是否可以用更少的字传达 |
| 某点实际 << 预算 | 该信息团的核心信息没有充分展开 | 检查是否有「读者应该知道但不知道」的信息缺口 |
