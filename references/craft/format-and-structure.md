# 格式与排版硬约束

> 正文交付的排版、断段、标点、对话格式规范，是写作的硬约束底座。
>
> 本文件管的是「写出来长什么样」——段落怎么断、标点怎么用、对话怎么排、平台怎么切。
> 不管「写什么内容」（那是章纲与题材卡的职责），也不管「写得好不好」（那是 `anti-ai-style.md` 的职责）。
> 任何题材、任何平台，正文的物理排版都必须过这一关。

---

## 核心原则：戏剧单元优先断段

段落不是按字数切的，是按戏剧单元断的。先判断「一件事是否完成」，再决定是否换段。

一段承载一个完整的戏剧单元，以下任一情况完成时断段：

- **动作链闭合**：一个连续动作从起手到落点走完（他抬手、扣下扳机、子弹嵌进墙里）。
- **线索发现落地**：角色注意到一个细节并完成一次判断（她看见桌上的药瓶，数了数，少了三片）。
- **情绪变化拐点**：一段情绪从起势到转折走完一个弧线（从压着火到爆发，或从试探到收回）。
- **视线/焦点切换**：叙述镜头从 A 移到 B（从角色的手移到对面的脸）。
- **新信息入场**：一句话或一个动作带来了新的事实，需要读者停下来接收。

同一瞬间的发生、感知、反应织在同一段，不拆成「动作层 / 感知层 / 反应层」三层。那是拆解笔记，不是小说。

字数只作诊断，不作切刀：一段读起来拥挤、混进了两个以上的拍点、或在手机屏上难以跟读时才拆。完整推理链、氛围铺陈、情绪递进未结束时，允许稍长段保留连贯性。

## 长短交错规则

通篇同长度是 AI 腔的指纹。段落要有呼吸，靠长短交错和疏密有别制造节奏。

### 长短交错

- **高潮 / 打脸 / 反转压到最短**：关键爆点用单句成段，一句话砸下去，读者来不及眨眼。
- **推理 / 氛围 / 情绪沉淀保留长段**：让读者在一个完整变化里走完一段路，不要中途打断。
- **过场写疏**：连接性内容一两句带过，不平均用力。
- **爽点写密**：转折 beat 把感知、动作、细节铺满，让读者「看见」而不是「被告知」。

### 疏密有别

每个 beat 一样长、一样细，正是 AI 腔的来源。正确的做法是按 beat 的功能分配笔墨：

| Beat 类型 | 笔墨策略 | 段落特征 |
|---|---|---|
| 爽点 / 转折 | 写密：感知、动作、细节全铺上 | 多个短段密集交替 |
| 推理 / 揭示 | 写实：完整推理链一气呵成 | 中长段保留连贯 |
| 氛围 / 压迫 | 写浓：环境细节织进情绪 | 中长段，句长稍拖 |
| 过场 / 连接 | 写疏：一两句带过 | 极短段或合并 |

不过度碎片化：连续多个极短段若仍属于同一镜头、同一件事，应合并成自然段。一串单句段读起来像提纲或诗行，不是小说。

## 8 条绝对禁止

以下规则在写作全程执行，不因题材、平台或风格而变。违反任何一条，该段重写。

### 1. 禁止机械等长分段

不要因为超过某个字数就强拆。先判断段落是否仍是一个完整戏剧单元。若混入多个动作、多条信息、多次视线切换才拆；完整推理、氛围、情绪链可保留稍长段。通篇每段都是 3-5 行、字数接近，是最典型的 AI 排版指纹。

### 2. 禁止段间空行

正文相邻段落之间只允许一个换行符 `\n`，不得出现空行或连续换行 `\n\n`。

网文是手机阅读，空行制造的不是「呼吸感」而是「割裂感」。段落紧密排列，靠长短交错制造节奏，不靠空行制造间隔。

### 3. 禁止对话标签机械化

高频或公式化的「他说」「她道」「他笑了笑说」用动作描写或上下文替代。普通「说」低频使用可保留。

错误范式：每句对话都跟一个标签，且标签高度同质化（他说 / 她道 / 他又说 / 她继续道）。这是 AI 对话的典型特征。正确做法见后文「对话格式规则」。

### 4. 禁止正文缩进

不使用全角空格 `　　` 或半角空格缩进。平台渲染器自行处理首行缩进，正文文件里不需要手动加。

### 5. 禁止正文混入 Markdown 格式

除统一的章节标题行（如 `###第X章 标题`）外，正文段落中不使用任何 Markdown 语法：

- 不用标题 `#` / `##` / `###`（章节标题除外）
- 不用加粗 `**文字**`
- 不用斜体 `*文字*`
- 不用列表 `-` / `1.` / `*`
- 不用分隔线 `---`
- 不用代码块 `` ` `` 或 ` ``` `

正文是纯文本小说，不是 Markdown 文档。

### 6. 禁止破折号硬造停顿

正文（含叙述、对话、心理描写）不使用破折号 `——` / `—` / `--`。改用句号、逗号、换行、动作 beat 或短句断开。

破折号在中文网文里是「假装有节奏」的廉价工具。真正想制造停顿，靠动作（他顿了一下）、靠换行、靠短句，不靠一个符号。

### 7. 禁止通篇句号化或标点堆叠

两类问题都要防：

- **通篇句号化**：每句话都以句号结尾，语气全被压平，读起来像说明书。该质问时用问号，该爆发时用感叹号（少量），标点要跟语气走。
- **标点堆砌**：`!!!` / `???` / `……` 连用，或无功能地乱撒 `？` / `！`。感叹号堆叠不等于情绪强烈，省略号堆叠不等于意味深长，它们只是噪音。

犹豫、吞咽、未说完用动作或句长变化表达，不用 `……` 硬造停顿。

### 8. 禁止正文混入工程元信息

正文的叙述、对话、心理描写里不得出现任何写作工程词：

- 章节号词：`第X章` / `上一章` / `本章` / `这一章` / `前文` / `后文`
- 创作词：`伏笔` / `细纲` / `章纲` / `大纲`
- 读者词：`读者会觉得` / `读者会看到` / `读者发现`

章节号只允许出现在标题行、文件名、追踪记录中。正文里要改成角色能感知的事件锚点或相对时间。

错误：「比第一章那三秒开火更疼」
正确：「比那三秒开火更疼」

例外：角色在故事世界内真实阅读、讨论「第X章」文本（比如角色是个网文作者），或真实身为作者、读者并谈论读者身份时，可保留相应词。这种豁免需人工判断，机器闸口（`check_text.py`）命中时会标 blocking，由作者确认后用 `<!-- 闸口:跳过 -->` 豁免。

## 语气标点谱系表

标点服务语气、人物声线和情绪节奏。不能通篇句号化，也不能为了「丰富」随机堆砌符号。先判断当前句子的功能，再选择标点。

| 语气 / 功能 | 标点策略 | 防线 |
|---|---|---|
| 压迫 / 冷静 / 克制 | 短句、逗号、句号，必要时用冒号压出判断落点 | 不人工加感叹号；克制不是每句都平铺句号 |
| 质问 / 试探 / 反问 | 问号 + 短促追问片段，配合动作停顿 | 避免每句话都以 `？` 结尾 |
| 爆发 / 打脸 / 惊讶 | 真正爆点可用 1 个感叹号，连续爆发最多 1-2 处 | 禁止 `!!!`、整段喊叫式感叹 |
| 犹豫 / 吞咽 / 未说完 | 逗号、句号、短句断开、动作 beat | 不用 `……` 制造停顿；优先用动作和句长变化 |
| 被打断 / 拖长音 | 不使用 `——`；改用动作打断、换行、短句或未完成动作 | 正文和对话都禁止 `——` / `—` / `--` |
| 信息揭示 / 判断落点 | 冒号、分号或单句成段制造落点 | 保持手机阅读友好，不写论文式分号串 |

### 执行要点

- **写对话时先看角色关系和权力位置**：强势角色常短句收束，试探角色多问号和半句，崩溃角色才允许少量感叹。
- **写叙述时用句长、逗号停顿和单句成段制造节奏**，不要把破折号当节奏工具，对话里也不要用。
- **精修时检查两类问题**：通篇句号化（语气全被压平）与随机标点堆砌（问号 / 感叹号不承载情绪功能，或用省略号 / 破折号硬造停顿）。
- **引号风格按项目 / 平台约定**：番茄用 `""`，盐言用 `「」`，两者都是合法对话格式，不得擅自互相替换。

## 对话格式规则

对话是网文正文的核心载体（通常占 20%-50%），格式直接决定可读性。

### 遮名认人测试

写完一段对话，遮住所有名字重读：能认出谁在说话，及格；认不出，全员一个声，重写。

声线的来源是人物卡：口头禅、句式长短、知识背景、对听话人的态度。谋士说话绕弯，武将说话砸钉，上位者话里带分量，小人物话里带讨好。口癖要点到为止：同一句口头禅一章出现两次以上就是噪音。

### 对话标签位置变化

对话标签不要永远出现在同一位置。四种位置轮换使用：

**标签在前**（建立说话人，适合段首或场景切换）：
```
她放下杯子，说："你走吧。"
他没有动。
"我说，你走吧。"
```

**标签在后**（强调台词内容，适合关键信息）：
```
"你走吧。"她说。
他没有动。
"我说，你走吧。"
```

**标签在中**（制造停顿，分隔两层意思）：
```
"你走吧，"她说，"别再来了。"
```

**标签省略**（连续对话，靠内容区分）：
```
"你走吧。"
"我不走。"
"你是不是聋了？"
"你是不是哑了？"
```

### 连续对话省略标签

两人对话连续出现时，省略标签，靠内容区分说话人。这是网文对话的默认形态。只有当说话人可能混淆、或需要强调某个动作时，才补一个标签或动作 beat。

**正确示例**（对话独立成行，标签按需，动作穿插）：
```
她把杯子放下。
"你走吧。"
他没有动。
"我说，你走吧。"
他抬起头，看了她一眼。
"不走。"
```

**错误示例**（对话嵌在叙述中，标签机械化）：
```
她把杯子放下，说道："你走吧。"他没有动，她又说："我说，你走吧。"他抬起头看了她一眼，说："不走。"
```

### 对话标签的替代

高频或公式化的「他说」「她道」「他笑了笑说」用以下方式替代：

- **动作 beat**：用一个动作带出说话人（她放下杯子。"你走吧。"）
- **上下文**：靠前文已经建立的情境，读者自然知道是谁在说
- **普通「说」低频保留**：偶尔用一次「说」不碍事，但不要每句都跟

## 平台差异表

不同平台对章节标记、对话引号有不同约定。未指定平台时，使用「番茄」作为默认（长篇）或 `###1.` + `""`（短篇）。

| 平台 | 章节标题行 | 对话引号 | 特殊要求 |
|---|---|---|---|
| 番茄小说 | `###第X章 标题` | `""` | 首段需有吸引力，章尾钩子决定点开率 |
| 起点中文网 | 无标题行（标题在元数据） | `""` | 正文直接从第一段开始，不带章节标记 |
| 晋江文学城 | 纯文本（不带 `###`） | `""` | 标题行用纯文本，不用 Markdown 标记 |
| 知乎盐言 | `1.` `2.` `3.`（无 `###`） | `「」` | 导语需单独标注，引号用日式角引号 |

### 平台切换原则

- **全文统一一种格式**，不要在同一本书里混用章节标记或引号风格。
- **跨平台分发时**，按各站规则改章节切分与引号，不要一章多发不管差异。
- **用户或平台指定盐言风格时**，`「」` 是合法对话格式，`normalize_punct.py` 的 `--quote-mode keep` 会保留原样，不得擅自改成 `""`。
- **长篇与短篇是两套生产逻辑**：长篇用章节标记（`###第X章`），短篇用小节编号（`###1.`）。详见 `references/platforms/platform-guide.md`。

## 写完后 10 项快速自查清单

每章写完，通读一遍，逐项自查。前 8 项对应「8 条绝对禁止」，后 2 项是排版收尾。

- [ ] 1. 段落是否按戏剧单元断开，而不是机械按字数切开？有没有通篇等长的段落？
- [ ] 2. 正文相邻段落之间是否只有一个 `\n`，没有空行 / `\n\n`？
- [ ] 3. 对话标签是否避免高频公式化（每句都「他说」「她道」）？普通「说」是否按语境低频保留？
- [ ] 4. 有无全角空格 `　　` 或半角空格缩进？
- [ ] 5. 正文段落中是否混入了 Markdown 格式（`#` / `**` / `*` / `-` / `---` / 代码块）？章节标题行除外。
- [ ] 6. 正文（含对话、心理描写）里是否还有 `——` / `—` / `--`？是否已改为逗号、句号、动作 beat 或短句断开？
- [ ] 7. 标点是否匹配语气？有无通篇句号化（语气全压平）？有无标点堆砌（`!!!` / `???` / `……` 连用）？有无用 `……` / `——` 硬造停顿？
- [ ] 8. 标题行以外，正文里有无工程元信息词（`第X章` / `上一章` / `本章` / `伏笔` / `细纲` / `读者`）？故事内真实阅读、讨论「第X章」的语境除外。
- [ ] 9. 对话是否独立成行？引号风格是否符合项目 / 平台约定（番茄 `""`，盐言 `「」`）？连续对话是否省略了标签？
- [ ] 10. 段落长短是否交错？高潮 / 打脸是否压到最短（单句成段）？推理 / 氛围是否保留了长段？过场是否写疏？

## 与其他文档的关系

本文件是「写作时的格式判断依据」（人），与标点归一化脚本互补，各管一段。

### 与 `scripts/normalize_punct.py` 的关系

| 维度 | `normalize_punct.py`（机器） | 本文档（人） |
|---|---|---|
| 性质 | 写完后的机械清理脚本 | 写作时的格式判断依据 |
| 作用时机 | 正文交付后、入库前 | 写作全程（从初稿到精修） |
| 处理对象 | 确定性的标点问题：省略号 `……`、破折号 `——`、感叹堆叠 `!!!`、分隔线、全角空格 | 不确定的格式判断：断段位置、长短交错、对话标签去留、语气标点选择 |
| 能力边界 | 只做确定性替换，不判断语气、不决定断段、不处理对话标签 | 只做人工判断，不做机械替换 |
| 互补关系 | 机器兜底：人写漏的标点问题，脚本扫一遍兜住 | 人工前置：人按本文档写对，脚本命中数趋近于零 |

**正确流程**：写作时按本文档判断格式（断段、标点、对话）→ 写完后跑 `normalize_punct.py` 兜底清理漏网标点 → 再跑 `check_text.py --gate-report` 做完整闸口检查。三者缺一不可，但不能互相替代。

### 与 `anti-ai-style.md` 的关系

- 本文档管「格式硬约束」：段落怎么断、标点怎么排、对话怎么写。
- `anti-ai-style.md` 管「去 AI 腔」：禁用词、毒句式、心理告知、结尾升华、解释腔。
- 两者有交集（如标点节奏、对话标签），但分工不同：本文档是排版底线，`anti-ai-style.md` 是文风底线。一段文字可以格式全对但 AI 味冲天，也可以没有 AI 腔但格式乱七八糟——两个都要过。

### 与 `iron-law.md` 的关系

- `iron-law.md` 的第 3 条「禁止混淆正文与元信息」与本文件第 8 条「禁止正文混入工程元信息」是同一条规则的两面：铁律管「为什么不能混」，本文件管「具体哪些词不能混、怎么改」。
- 铁律是全书级的底线约束，本文件是正文级的排版约束。铁律优先级更高。

### 与题材卡、平台指南的关系

- 题材卡（`references/genres/`）管「这个题材怎么写」：节奏、爽点密度、专属禁用词。
- 平台指南（`references/platforms/platform-guide.md`）管「这个平台怎么发」：字数、更新、推荐机制。
- 本文件管「正文长什么样」：排版、断段、标点、对话格式。
- 三者叠加使用：题材卡定内容打法，平台指南定生产约束，本文件定排版底线。平台指南中涉及章节标记、引号的部分，以本文件的「平台差异表」为权威。
