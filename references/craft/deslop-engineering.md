# 去AI味工程化

本文件是 `anti-ai-style.md` 的工程化延伸。`anti-ai-style.md` 定义了 7 Gate 的判定标准与
改法词典（管「什么算AI味、怎么改」）；本文件定义去AI味的**工程流程**——量化分级、
删除优先、三遍法、收敛终止、字数协议（管「按什么顺序改、改到什么程度停、改了多少字」）。

分工边界：
- `check_text.py` 负责机器能确定的 Gate A/B（禁用词、毒句式、工程词、解释腔、文末窗口）
  与密度/结构 advisory，输出 AI 味分数与轻/中/重度分级——这是 Gate A/B 机器检测。
- 本文件指导 Gate C-G 的人工润色流程：心理外化、节奏调整、对话去腔、结尾去升华、
  解释腔的语境变体判定——机器给候选，人工定终稿。

## 核心理念：删除优先，润色其次

去AI味最大的陷阱不是「改不掉」，而是「改过头」。AI 味的根源是过度圆滑、过度工整、
过度解释；去AI味的动作应该是「减」多于「加」——先删冗余，再补具体。但删除有风险：
一段看似AI腔的文字里可能埋着伏笔、钩子、角色特征或情节推进，删错了比留着更糟。

因此工程化的第一原则：**每条标记先判能否删除，再进润色**。

### 删除优先判断流程

对 `check_text.py` 标出的每一处命中，依次过三道关：

1. **信息关**：被标记的文字是否承载伏笔/钩子/角色特征/情节推进/必要信息？
   - 是 → 不可删，进润色（改写而非删除）
   - 否 → 进第 2 关
2. **冗余关**：删掉后，读者对当前段落的信息理解是否损失？
   - 是 → 不可全删，可压缩（删一半留一半）或改写
   - 否 → 进第 3 关
3. **节奏关**：删掉后，段落节奏是否变得突兀（信息密度骤降或句子断裂）？
   - 是 → 不可删，改写为更短的替代
   - 否 → 可删

只有三关全过才执行删除。删不掉的进润色队列。

### 删除标记的典型类型

| 标记类型 | 典型表现 | 删除判断 |
|---|---|---|
| 纯套话 | "空气仿佛凝固""时间仿佛静止" | 三关通常全过，直接删 |
| 解释腔 | "之所以…是因为""这意味着" | 信息关常不过（解释的是真因果），改写 |
| 心理告知 | "他很紧张""心中涌起愤怒" | 冗余关常不过（旁边有动作），压缩 |
| 升华结尾 | "这一刻他终于明白了" | 节奏关常不过（删了段尾悬空），改写为动作 |
| 设定复述 | 成段搬设定 | 信息关不过（有设定信息），改写为动作/冲突呈现 |

## 量化六级表

去AI味不是凭感觉，要量化。以下六项指标构成去AI味的「体检表」，其中前两项由
`check_text.py` 直接输出，后四项可从 `--gate-report` 与 `--style-stats` 的数据推算。

| 指标 | 含义 | 轻 | 中 | 重 |
|---|---|---|---|---|
| 禁用词密度 | 每千字命中禁用词数（机器输出） | ≤5/千字 | 6-15/千字 | >15/千字 |
| 连续排比段数 | 连续出现「不是A而是B」「没有X只有Y」等同构句式的段落数 | 0-2段 | 3-5段 | ≥6段 |
| 心理词占比 | 心理告知类命中（他很X/心中Y/一股Z）占叙述字数比例 | <1% | 1-3% | >3% |
| 对话标签密度 | 每千字「说道/沉声道/淡淡地说」等标签数 | ≤4/千字 | 5-8/千字 | >8/千字 |
| 平均段落句数 | 每段平均句子数（`--style-stats` 推算） | 3-6句 | 7-10句 | >10句或<2句 |
| 重复描写密度 | 同一情绪/动作在同一章用不同措辞重复表达的次数 | ≤2次 | 3-5次 | ≥6次 |

### 等级判定规则

取六项指标中**最严重的一项**定级（木桶效应）。例如：禁用词密度为轻（3/千字），但
连续排比段数为重（7段），则整章定为重度。

`check_text.py --gate-report` 输出的 AI 味分数（0-100）与六级表的对应关系：
- 0-19 分 → 轻度（与六级表「轻」对齐）
- 20-39 分 → 中度（与六级表「中」对齐）
- 40-100 分 → 重度（与六级表「重」对齐）

当机器分数与六级表判定不一致时（例如分数 18 但连续排比 6 段），以六级表为准——
机器分数是加权和，会因 advisory 项的权重稀释而偏低，六级表是逐项判定的更保守标准。

## 过度去AI味保护

去AI味本身也会制造问题：删太多会让文字变干、变碎、丢失叙事温度；改太多会让文字
从「AI腔」滑向「翻译腔」或「电报腔」。因此必须设删除比例上限。

### 删除比例上限分级

| 等级 | 删除比例上限 | 含义 |
|---|---|---|
| 轻度 | ≤15% | 删改不超过原文 15% 的字符 |
| 中度 | ≤25% | 删改不超过原文 25% 的字符 |
| 重度 | ≤35% | 删改不超过原文 35% 的字符 |

**计算口径**：删除比例 = （原文字符数 - 修订后字符数 + 新增字符数）/ 原文字符数。
注意是「删改总量」而非净变化——删 200 字加 100 字，删除比例按 300 字算，不是净 100 字。

### 超限处理

当一轮润色的删改量逼近上限时：
- 删改量 < 上限的 80%：正常继续
- 删改量在上限的 80%-100%：剩余标记改为「最小改动」策略（只改最毒的，其余保留）
- 删改量达到上限：停止删除，剩余段落标 `[需复核]`，输出当前版本

`[需复核]` 的语义：该段仍有AI味痕迹，但继续删除会超出安全阈值，需作者介入判断。
这比「强行删完导致文字失血」或「留着不管」都更诚实。

## 三遍法

去AI味不是一遍扫描改完，而是按层级递进的三遍。每遍有明确目标，避免「什么都想改
结果什么都改不好」。

### Pass 1：去泛化

目标：清除最确定的 AI 模式——禁用词、毒句式、工程词、解释腔、文末预告。

这一遍处理 `check_text.py` 标出的全部 blocking 命中，以及 advisory 中置信度高的项
（抽象总结密度、微动作复读）。操作以**删除+替换**为主，不做句子重构。

典型动作：
- "仿佛""似乎" → 删掉或换成具体感知
- "不是A，而是B" → 只写 B
- "之所以…是因为" → 删因果连词，让读者从动作拼
- "这一刻，他明白了" → 删掉
- "才刚刚开始""拉开序幕"（文末窗口）→ 删掉，换动作收尾

Pass 1 完成后重跑 `check_text.py --gate-report`，确认 blocking 清零。

### Pass 2：去书面化

目标：把过于工整、正式、书面化的表述拉回口语化和具体感。处理 Gate C（心理外化）、
Gate D（节奏）、Gate E（对话腔调）的候选项。

这一遍以**改写**为主，不删而是换表达方式：
- "他很紧张" → "他的手在抖"（心理外化）
- 拆臃肿长句、打断连续排比（节奏调整）
- 对话加口语词、删解释性台词（对话去腔）
- 删修饰词堆砌（"白色的药片" → "药片"）

Pass 2 的改动量通常大于 Pass 1，因为改写比删除动的字更多。注意累加删除比例。

### Pass 3：回自然感

目标：防止 Pass 1+2 把文字改得太干、太碎、太刻意——回补叙事温度。

这一遍不是「继续去AI味」，而是「修复去AI味的副作用」。操作以**微调**为主：
- 过短的电报句适当合并（"他站起。走到窗边。推开窗。" → "他站起身走到窗边推开窗"）
- 删太多修饰导致画面空白处补一个具体细节（不是补形容词，是补动作/物件）
- 段落呼吸感检查：连续短段后接一个稍长段，连续长段后插一个短段
- 朗读测试：默读一遍，哪里读着别扭就标出来微调

### 遍数与等级的匹配

| 等级 | 执行遍数 | 说明 |
|---|---|---|
| 轻度 | Pass 1 + Pass 3 | 只去泛化+回自然，跳过 Pass 2（书面化不严重） |
| 中度 | Pass 1 + Pass 2 + Pass 3 | 完整三遍 |
| 重度 | Pass 1 + Pass 2 + Pass 3 + 局部重写 | 三遍之外，对最严重的段落整段重写 |

重度章节的「局部重写」不算在删除比例内——重写是替换不是删除，但重写段落同样
需要标 `[需复核]` 供作者确认。

## 白名单机制

`check_text.py` 已支持白名单：书籍工程根目录放 `.deslop-whitelist`，命中段若子串
在白名单中则跳过。本文件补充白名单的**前缀标记扩展**。

### `!` 前缀豁免词

在 `设定/禁用词.txt` 中（注意是禁用词表，不是白名单文件），可用 `!` 前缀标记豁免词：

```
# 这是注释，check_text.py 正常跳过
仿佛
!缓缓
!淡淡
```

- 不带 `!` 的词：正常作为禁用词检测
- 带 `!` 的词：从禁用词表中移除（等效于加入白名单）

适用场景：
- **世界观术语**：玄幻中某个功法名叫「缓缓诀」，「缓缓」是专有名词而非AI口癖
- **角色绰号**：角色外号叫「淡淡」，对话中喊绰号不算违规
- **题材特需**：年代文中「同志」「组织上」是时代用语，不是书面腔

`!` 前缀词的语义是「这个词在本书中不是AI味，是设定的一部分」。它与 `.deslop-whitelist`
的区别：白名单是全局豁免（不区分语境），`!` 前缀是在禁用词表层面声明「这个词不该
出现在禁用词表里」。两者效果相同，但 `!` 前缀的好处是开书时在禁用词表一处管理，
不用维护两个文件。

> 实现说明：`check_text.py` 的 `load_wordlist` 当前跳过 `#` 注释行。`!` 前缀词需在
> 脚本层做一次过滤（去掉 `!` 前缀后不加入检测词表），或在加载后手动剔除。若脚本
> 未更新，可临时用 `.deslop-whitelist` 达到相同效果。

## 收敛终止

去AI味不是无限循环——改到一定程度必须停。以下三条规则定义「何时停」。

### 三条终止规则

1. **段级收敛**：同一段连续两轮润色无新改动 → 该段终止，标 ✅
2. **全文上限**：全文润色不超过 3 轮。第 3 轮结束后无论是否完全清零都停止
3. **复核阈值**：第 3 轮结束时若仍有 ≥10 处未清零标记 → 标 `[需复核]`，交作者

### 轮次定义

一轮 = 对全文跑一遍 Pass 1→2→3（或按等级跳过部分遍）+ 重跑 `check_text.py` 验证。

- 第 1 轮：初次润色，处理全部标记
- 第 2 轮：验证后发现的新问题（Pass 3 微调可能引入新 advisory）+ 第 1 轮漏网的
- 第 3 轮：收尾，只处理 blocking 级别残留，advisory 不再追

### 收敛判定流程

```
第1轮润色 → check_text.py 验证
  ├─ blocking=0 且 advisory≤5 → 通过，结束
  ├─ blocking>0 → 进第2轮
  └─ blocking=0 且 advisory>5 → 进第2轮（可选，看作者意愿）

第2轮润色 → check_text.py 验证
  ├─ blocking=0 且新增标记=0 → 通过，结束
  ├─ 仍有 blocking → 进第3轮
  └─ blocking=0 但有新增标记 → 进第3轮

第3轮润色 → check_text.py 验证
  ├─ 残留标记 <10 → 通过，结束
  └─ 残留标记 ≥10 → 标 [需复核]，结束
```

## 字数协议

每次去AI味润色后，必须报告字数变化。这不是形式主义——字数变化是判断「有没有改过头」
的硬指标。

### 协议字段

润色报告末尾必须包含以下四项：

```
字数协议：
  原文字符数：{N1}（非空白字符）
  修订后字符数：{N2}
  净变化：{N2-N1}（+/-{百分比}%）
  是否在tier上限内：是/否（tier={轻/中/重}，上限={15%/25%/35}%）
```

### 协议判读

- 净变化为负且 |净变化|/原文 > 删除上限 → 改过头，需回补
- 净变化为正且 >5% → 可能在「加字去AI味」（用更多字解释更少的信息），需检查是否有
  Pass 2 改写过度
- 净变化在 -5% 到 +5% 之间 → 正常区间，删与补基本平衡
- 净变化为 0 → 可能没真改（只删了又加了等量字），需抽查实际改动质量

## 与 check_text.py 的衔接

### 机器与人工的分工

| 阶段 | 负责方 | 内容 | 工具 |
|---|---|---|---|
| Gate A/B 检测 | 机器 | 禁用词、毒句式、工程词、解释腔、文末窗口 | `check_text.py --gate-report` |
| 量化打分 | 机器 | AI 味分数、轻/中/重度分级、六级指标前两项 | `check_text.py --gate-report` |
| 密度/结构 advisory | 机器 | 比喻密度、解释链、动作清单、复读句、碎句号 | `check_text.py --gate-report` |
| Gate C-G 润色 | 人工 | 心理外化、节奏调整、对话去腔、结尾去升华、语境变体 | 本文件指导 |
| 六级指标后四项 | 人工 | 心理词占比、对话标签密度、段落句数、重复描写 | `--style-stats` 辅助 + 人工统计 |
| 收敛验证 | 机器 | 每轮润色后重跑 check_text 确认 blocking 清零 | `check_text.py --gate-report` |
| 字数协议 | 机器 | 原文/修订后字符数 | `check_text.py` 的 count_chars |

### 标准工作流

```bash
# 0. 写完正文后先跑机器闸口
python scripts/check_text.py "正文/第037章_标题.md" --min-chars 2000 --max-chars 3500 \
  --ledger "追踪/伏笔台账.md" --current-chapter 37 --gate-report --gate-state

# 1. 读取报告，确定等级（轻/中/重），匹配遍数
# 2. 按三遍法执行人工润色（Gate C-G）
# 3. 润色后重跑验证
python scripts/check_text.py "正文/第037章_标题.md" --gate-report
# 4. 确认 blocking=0；若 advisory 仍多，进第2轮
# 5. 满足收敛条件后，输出字数协议
# 6. 更新门禁状态
python scripts/check_text.py "正文/第037章_标题.md" --gate-report --gate-state
```

### advisory 的处理原则

`check_text.py` 的 advisory 项（密度/结构类）默认不计入未通过。去AI味时：
- advisory 中与 blocking 同源的（如比喻密度高 + 命中「仿佛」）→ 随 blocking 一起改
- advisory 独立命中的（如碎句号但无禁用词）→ 按读感判断，确属问题才改
- advisory 是密度型指标，单次命中不一定是问题，成片才是 → 看分布不看单点

不要为了清零 advisory 而过度修改——advisory 的设计本意就是「机器拿不准，留给人工
判断」。把所有 advisory 都当 blocking 改，本身就是一种「过度工整」的AI味。

## 两遍式去AI味工作流

前文的「三遍法」是面向重度章节的深度流程（去泛化→去书面化→回自然感）。本节定义一个
更轻量的「两遍式」工作流，借鉴 `novel-creator-skill` 的 `humanizer-guide.md` 与
`oh-story-claudecode` 的 `story-deslop` 思路：第一遍按 7 类 AI 模式逐项清除，第二遍
让 AI 对自己的修改稿做自审复查。两遍式适合轻度/中度章节的常规润色，重度章节仍走三遍法。

### 两遍式与三遍法的关系

| 维度 | 两遍式 | 三遍法 |
|---|---|---|
| 适用等级 | 轻度、中度 | 中度、重度 |
| 遍数 | 2 遍 | 3 遍（重度+局部重写） |
| 第一遍目标 | 7 类 AI 模式逐项清除 | 去泛化（禁用词/毒句式/工程词/解释腔/文末预告） |
| 第二遍目标 | AI 自审（自问自答式复查） | 去书面化（心理外化/节奏/对话去腔） |
| 第三遍 | 无 | 回自然感（修复前两遍副作用） |
| 自审机制 | 有（第二遍即自审） | 无显式自审，靠收敛验证 |
| 选择原则 | 日常章、AI 味分数 < 40 | 关键章、高潮章、AI 味分数 ≥ 40 |

> 当 `check_text.py --gate-report` 给出 `deslop_grade == 轻` 或 `中` 时，默认走两遍式；
> `deslop_grade == 重` 时走三遍法。两套流程共享删除比例上限、收敛终止、字数协议。

### 第一遍：清除 7 类 AI 模式

第一遍是「清单式扫描」——对 7 类 AI 模式逐类检查、逐处清除。每类有明确的识别特征与
改法，不凭整体感觉，而是按清单走，确保不漏项。

#### 模式一：AI 高频词

**特征**：AI 生成文本偏爱的高频套词，出现密度远高于自然文本。多来自 `check_text.py`
的禁用词命中（Gate A）。

**典型词表**（与 `设定/禁用词.txt` 对齐）：
- 感知模糊类：仿佛、似乎、好像、隐隐、隐约、微微
- 情绪套词类：不禁、油然而生、心头一紧、心中一凛、一股……涌上心头
- 视觉套词类：映入眼帘、跃然纸上、尽收眼底、映入眼帘
- 动作套词类：缓缓、淡淡、微微一笑、嘴角上扬
- 程度套词类：格外、分外、尤为、颇为

**改法**：
1. 删除（最优先）：套词本身不承载信息，删掉不影响理解。如「他仿佛看到了……」→「他看到……」。
2. 替换为具体感知：把模糊词换成具体感官。如「隐隐传来声响」→「墙根传来窸窣声」。
3. 保留并加语境（仅当词义不可替代）：如「仿佛」用于明确的比喻修辞时保留，但须确保
   不是感知模糊而是修辞需要。

**清查动作**：逐词在全文检索，每个命中处三选一（删/换/留+语境），不留模糊判断。

#### 模式二：弱化副词

**特征**：削弱句子确定性的副词，让叙述变得飘忽、不果断。AI 用它们回避下判断。

**典型词**：似乎、好像、大概、也许、或许、多少有些、多少有点、似乎有些、隐隐约约、
仿佛在说、好像是、大概吧。

**危害**：堆叠后全文读起来「什么都不确定」，叙事力度被稀释。

**改法**：
- 删除副词，让动词直接承担判断：「他似乎有些紧张」→「他紧张」或「他攥紧了拳头」。
- 若确属不确定情境，用具体证据替代：「她好像生气了」→「她摔了门」。
- 同一段不超过 1 个弱化副词；连续 2 句都带弱化副词 → 至少删 1 个。

#### 模式三：意义膨胀

**特征**：用「一个/一次/一场/一种」+ 抽象名词的堆砌，把简单的感受撑成冗长表达。
AI 偏好这种「加重语气」的写法，实则稀释信息密度。

**典型句式**：
- 「一种难以言喻的孤独感涌上心头」
- 「他感到一阵前所未有的疲惫」
- 「空气中弥漫着一股说不清道不明的紧张」
- 「这是一个充满未知与挑战的时刻」

**改法**：
1. 删抽象名词，留具体动作/物件：「一种难以言喻的孤独感涌上心头」→「他一个人坐到天亮」。
2. 去量词膨胀：「一阵前所未有的疲惫」→「累」或「他靠在墙上不想动」。
3. 去形容词堆砌：「充满未知与挑战的时刻」→「不知道下一刻会发生什么」。

**判定**：出现「一种/一阵/一股/一个」+ 两个以上抽象名词/形容词 → 几乎必改。

#### 模式四：通用结论套话

**特征**：放之四海皆可的结论句，不提供任何具体信息。多出现在段尾、章末，是 AI
升华情结的重灾区。

**典型句式**：
- 「这一刻，他终于明白了……」
- 「一切，才刚刚开始。」
- 「故事，还在继续。」
- 「他知道，前方的路还很长。」
- 「这就是成长的代价。」
- 「命运的齿轮，悄然转动。」

**改法**：
1. 直接删除（首选）：这类套话几乎不承载信息，删掉段落更干净。
2. 替换为具体行动/物件收尾：「这一刻他终于明白了」→ 删，让上一句的动作做收。
3. 章末套话（「才刚刚开始」「拉开序幕」）→ 换成悬念钩子或未完成的动作。

**特别注意**：章末窗口的通用结论套话属于 Gate B 的文末预告，必须清除——它是 AI
味最刺眼的位置。

#### 模式五：论文式段落

**特征**：段落结构像议论文——总分总、首先其次最后、论点+论据+结论。小说不是论文，
这种结构让叙事变成说教。

**典型表现**：
- 「他之所以这样做，是因为……」「这意味着……」（解释腔，Gate B）
- 「首先……其次……最后……」的列举结构
- 段首抛论点、段中举证、段尾总结的封闭结构
- 「换句话说」「也就是说」「简而言之」的转译连接词

**改法**：
1. 删因果连词，让读者从动作拼因果：「之所以……是因为」→ 删，直接呈现动作序列。
2. 打散总分总：把「论点段」拆成场景片段，让结论从事件中浮现而非被陈述。
3. 删转译连接词：「换句话说」「也就是说」几乎必删——它们是 AI 解释冲动的标志。
4. 段尾总结句（「总之……」「可见……」）→ 删，让段落停在动作或对话上。

#### 模式六：对话同质化

**特征**：所有角色说话腔调一样——都是书面腔、都带解释、都长篇大论。AI 不会真正
区分角色声音，导致对话像「同一个人在自说自话」。

**典型表现**：
- 所有人都用「说道」「沉声道」「淡淡地说」做标签（对话标签同质化）
- 对话句子工整、完整、书面化，没有口语的断裂和省略
- 对话中夹带大段解释/设定复述（借角色之口说教）
- 不同角色语气词、句长、用词几乎无差异

**改法**：
1. 区分角色声音：根据角色卡（年龄/身份/性格/口音）给每个角色不同的语言特征。
   - 老者：短句、文言色彩、省略主语
   - 少年：口语词多、句子断裂、感叹
   - 上位者：祈使句、断言、不用语气词
2. 删解释性台词：角色不会当面把背景设定讲给「彼此都懂」的人听——把解释挪到叙述层
   或删掉。
3. 对话标签多样化与减省：连续对话只首句带标签；用动作代替标签（「他放下茶杯」代替
   「他淡淡地说」）。
4. 加口语断裂：真实对话有重复、打断、改口、省略。适当加入「那个……」「不，我是说……」。

#### 模式七：排比三连

**特征**：连续使用同构句式制造节奏感——「不是A而是B」「没有X只有Y」「既不……也不……」。
AI 偏爱这种工整的排比，但连用三次以上就成了机械感。

**典型表现**：
- 「不是退缩，而是前进」「不是逃避，而是面对」「不是放弃，而是坚持」（同构三连）
- 「没有退路，没有选择，没有希望」（三段式否定排比）
- 「是……是……更是……」（递进排比三连）

**改法**：
1. 三连砍二连：保留最有力的一句，删其余两句，或改写为不同句式。
2. 打破同构：把第二、三句换成不同结构的表达。
3. 排比降级为列举：用「、」串联代替完整句式重复。

**判定**：同一段内同构句式 ≥ 3 → 必改；全文同构排比段 ≥ 3 段 → 触发 Gate D advisory。

### 第一遍执行清单

第一遍按以下清单逐项执行，每项完成后打勾，避免遗漏：

```
□ 模式一 AI 高频词：全文检索禁用词表，逐处删/换/留+语境
□ 模式二 弱化副词：删副词，让动词承担判断，同段 ≤1 个
□ 模式三 意义膨胀：删「一X+抽象名词」堆砌，换具体动作
□ 模式四 通用结论套话：删段尾/章末套话，换动作收尾
□ 模式五 论文式段落：删因果连词/转译词/段尾总结，打散总分总
□ 模式六 对话同质化：按角色卡区分声音，删解释台词，标签多样化
□ 模式七 排比三连：三连砍二连，打破同构
□ 重跑 check_text.py --gate-report，确认 blocking 清零
□ 累加删除比例，检查是否逼近上限
```

### 第二遍：AI 自审

第二遍是「自问自答式复查」——把第一遍改完的稿子当成别人的稿子，问自己「哪里还有
AI 感」，强制列出 3-5 条，再逐条修改。这一遍借鉴 `humanizer-guide.md` 的「AI 自审」
机制：AI 改 AI 的稿，最大的盲区是「不知道自己哪里还像 AI」，因此必须强制列条目，
逼自己跳出第一遍的惯性。

#### 自审提问模板

对修改稿逐章提问（必须书面回答，不可只在脑子里过一遍）：

```
AI 自审 — 第{N}章

问题：通读修改稿，哪里还有 AI 感？请列出 3-5 条，每条指明位置与原因。

回答：
1. 位置：{行号/段落}；AI 感表现：{具体哪类模式残留}；原因：{为什么第一遍没改到}
2. ……
3. ……
4. ……
5. ……
```

#### 自审要点

自审不是泛泛而谈「整体还行」，必须落到具体位置。重点关注第一遍容易漏的三类盲区：

1. **第一遍改完引入的新 AI 感**：改写时可能用新的套话替代旧的套话（如把「仿佛」
   改成「宛若」，仍是 AI 高频词）。自审要查「改后的句子是不是又掉进另一类 AI 模式」。
2. **段落级的整体 AI 感**：第一遍是逐词逐句的，但有些 AI 感来自段落整体结构
   （如一段内连续三句都用「他+动词+宾语」的同构）。自审要跳出句子看段落。
3. **情绪表达的告知感**：第一遍可能只删了「他很紧张」的副词，但「他攥紧拳头，
   心跳加速」仍是告知（用了「心跳加速」这种生理套词）。自审要查情绪是否还在「告知」
   而非「呈现」。

#### 第二遍修改原则

- 自审列出的 3-5 条，逐条修改，不可只列不改。
- 修改仍受删除比例上限约束——若第一遍已逼近上限，第二遍以「改写」为主而非「删除」。
- 第二遍改完后再跑一次 `check_text.py --gate-report`，确认无新增 blocking。
- 若第二遍自审列不出 3 条（即真没有明显 AI 感了），可少于 3 条，但须说明「已无明显
  AI 感残留」并标注残留 advisory 数量。

### 两遍式收敛判定

```
第一遍（7 类清除）→ check_text.py 验证
  ├─ blocking=0 → 进第二遍
  └─ blocking>0 → 补改至 blocking=0，再进第二遍

第二遍（AI 自审）→ 列 3-5 条 → 逐条改 → check_text.py 验证
  ├─ blocking=0 且自审无新增 → 通过
  ├─ blocking=0 但自审仍有 ≥3 条 → 进第三遍自审（最多 2 轮自审）
  └─ blocking>0 → 补改后重跑
```

两遍式最多执行 2 轮自审（即第一遍 + 最多两次第二遍）。若两轮自审后仍有 ≥5 处未清零
标记 → 转 `[需复核]`，交作者；或判定为重度，转三遍法。

## 删除比例上限保护（两遍式配套）

前文「过度去AI味保护」一节已定义删除比例上限分级（轻度≤15%/中度≤25%/重度≤35%）。
本节针对两遍式工作流补充执行细则——两遍式因为遍数少、节奏快，更易在第二遍自审时
不知不觉超限，因此须有明确的累加与熔断机制。

### 上限分级（重申）

| 等级 | 删除比例上限 | 适用 |
|---|---|---|
| 轻度 | ≤ 15% | `deslop_grade == 轻`，两遍式默认 |
| 中度 | ≤ 25% | `deslop_grade == 中`，两遍式或三遍法 |
| 重度 | ≤ 35% | `deslop_grade == 重`，三遍法 |

> 计算口径同前文：删除比例 = (原文字符数 - 修订后字符数 + 新增字符数) / 原文字符数。
> 是「删改总量」而非净变化。

### 两遍式的累加规则

两遍式有两次改动（第一遍 + 第二遍），删除比例须**跨遍累加**，不可每遍各自从零计：

```
累计删改量 = 第一遍删改字符数 + 第二遍删改字符数
累计删除比例 = 累计删改量 / 原文字符数
```

每遍结束都须报告累计比例，而非当遍比例。

### 熔断机制（三档预警）

| 累计删除比例 | 状态 | 动作 |
|---|---|---|
| < 上限 × 60% | 绿灯 | 正常继续 |
| 上限 × 60% ~ 80% | 黄灯 | 第二遍改为「最小改动」策略：只改最毒的 3-5 处，其余保留 |
| 上限 × 80% ~ 100% | 橙灯 | 停止删除，剩余标记改写而非删除；无法改写的标 `[需复核]` |
| ≥ 上限 | 红灯 | 立即停止，剩余全部标 `[需复核]`，输出当前版本 |

**黄灯转橙灯的关键**：从「删」切换到「改写」。删除是减字，改写是换字（删改总量
仍在涨，但更慢）；当橙灯亮起，连改写都须克制，优先标 `[需复核]` 交作者判断。

### 熔断后的输出

熔断（橙灯/红灯）后，润色报告须显式声明：

```
删除比例保护：
  等级：中度（上限 25%）
  累计删改量：{N} 字
  累计删除比例：{X}%（{绿灯/黄灯/橙灯/红灯}）
  熔断状态：{未触发/已触发}
  [需复核] 标记数：{M} 处
  说明：{若熔断，说明剩余未处理标记已交作者}
```

## 过度去AI味保护（两遍式配套细则）

前文「过度去AI味保护」定义了上限分级与超限处理。本节补充三条操作性保护，确保
两遍式在快速润色时不伤及叙事骨架。这三条保护对三遍法同样适用，但两遍式因节奏快
更易违反，故在此强调。

### 保护一：不得整段删除

**原则**：去AI味以「句级/词级」改动为单位，禁止整段删除。

**理由**：一段文字即使 AI 味浓重，也往往承载着场景过渡、情绪铺垫、信息密度调节等
叙事功能。整段删除会破坏段落间的衔接，造成场景断裂、时间跳跃、情绪断层。

**例外**：仅当一段同时满足以下全部条件时，可整段删除：
1. 该段是纯套话，无任何具体信息（无人物名、无动作、无物件、无时间地点）。
2. 删除后前后段衔接自然，不产生逻辑断层。
3. 该段不处于段首（场景引入）或段尾（章末收束）的关键位置。

**替代方案**：对不能整段删除的 AI 味段落，采用「段内瘦身」——删句保段，把一段压缩
成两三句，保留其过渡功能但去掉套话。

### 保护二：删除前检查伏笔与因果锚点

**原则**：每一处删除/改写前，必须检查该处是否承载伏笔或因果锚点。

**伏笔锚点**：看似闲笔的物件、对话、动作，可能是为后续章节埋的伏笔。删除前须查
`追踪/伏笔台账.md` 与 `memory_update_ch{N}.md`，确认该处不是伏笔载体。

**因果锚点**：解释因果关系的细节（如「他握剑的手有旧伤」），可能是后续情节的逻辑
依据。删除会导致后续情节「无因而果」。

**检查流程**（对每一处待删文字）：

```
1. 该处是否在伏笔台账中登记？
   ├─ 是 → 不可删，改为改写（保留信息，换表达）
   └─ 否 → 进 2
2. 该处是否包含具体的物件/数字/称谓/时间？（可能是隐性伏笔）
   ├─ 是 → 标 [需复核]，交作者确认是否伏笔
   └─ 否 → 进 3
3. 该处删掉后，本章后续是否有情节依赖它？
   ├─ 是 → 不可删，改写
   └─ 否 → 可删
```

**与 memory-keeper 的协作**：反AI编辑删除前，应交叉校验 `memory_update_ch{N}.md` 的
`foreshadowing_updates` 与 `entity_updates`——凡涉及已登记伏笔/实体的文字，一律
改写不删除。

### 保护三：`[需复核]` 标注机制

**定义**：`[需复核]` 是「机器已识别 AI 味但因安全限制未能处理」的标记，表示该处
仍有问题但需作者介入。

**触发条件**（任一即标）：
1. 删除比例达到上限，剩余标记无法继续删除。
2. 待删文字可能承载伏笔/因果锚点，机器无法确认。
3. 改写会引入新的 AI 模式（改了 A 又掉进 B），机器无法找到「既去 AI 味又不引入新
   AI 味」的改法。
4. 该处是关键章的章末/高潮段，改错代价大，须作者把关。

**标注格式**：在正文对应位置用行内注释标注（不污染正文，单独成行）：

```markdown
<!-- [需复核] 行42：此处「仿佛」疑似AI高频词，但可能为比喻修辞，需作者确认是否保留 -->
```

**复核清单**：润色报告末尾汇总所有 `[需复核]` 项，供作者逐条处理：

```
[需复核] 清单：
1. 行42：「仿佛」—— 疑似AI高频词/比喻修辞待辨
2. 行78：整段情绪描写—— 删除比例已达上限，未处理
3. 行105：「他终于明白了」—— 通用结论套话，但位于高潮段，改写风险大
4. ……
```

**作者处理后的回流**：作者对 `[需复核]` 项做出处理后，反AI编辑须重跑
`check_text.py` 验证，并更新门禁状态。作者选择「保留不改」的项，须在
`memory_update` 或 `pipeline_todo` 中登记理由，避免后续章节重复标记。

## 自然文本基准表

去AI味需要一把「尺子」——知道自然文本长什么样，才能判断当前稿子离自然有多远。
本表给出自然文本与 AI 味文本在 8 个维度上的对比基准，供两遍式与三遍法对照参考。

> 基准值来自对自然网文（人工创作的高口碑长篇）的统计观察，非精确实验数据，用作
> 方向性参照而非硬性阈值。硬性阈值以 `check_text.py` 的六级表与 `--style-stats`
> 输出为准。

### 基准对比表

| 维度 | 自然文本 | AI 味文本 | 说明 |
|---|---|---|---|
| **段落长度** | 长短交错，平均 60-120 字；短段（1-2 句）占 20-30% | 段段等长，平均 100-150 字；几乎无短段 | AI 偏好均匀段落，缺乏呼吸感 |
| **对话标签** | 每 3-5 句对话最多 1 个标签；多用动作代替标签 | 每句对话都带「X说道/沉声道」；标签同质 | 自然文本靠上下文判断说话人 |
| **情绪表达** | 用动作/物件/环境呈现（「他把杯子捏裂了」） | 用心理词告知（「他愤怒极了」） | 呈现 vs 告知是核心分野 |
| **比喻** | 罕见且具体（1-2 次/千字，贴人物视角） | 高频且泛化（「仿佛」「宛如」满天飞，3+ 次/千字） | AI 比喻多为套式，不贴语境 |
| **语气词** | 口语对话中有「啊、嘛、呗、呢、吧」 | 对话书面化，无语气词；或乱用「呢」「吧」 | 自然语气词随角色性格变化 |
| **省略** | 大量省略主语、背景、过渡（读者能补） | 几乎不省略，每句都自洽完整 | AI 怕读者看不懂，过度交代 |
| **排比** | 偶发（同段 ≤1 次），且句式各异 | 高频同构排比（「不是A而是B」三连） | 排比是 AI 制造节奏感的首选 |
| **结尾** | 停在动作/对话/未完成事件上（悬念或余韵） | 停在总结/升华/预告上（「一切才刚开始」） | 章末是 AI 味最集中的位置 |

### 分维度的「自然」与「AI 味」对照示例

#### 段落长度

自然（长短交错，有呼吸）：
```
他没说话。

陈墨把剑横在膝上，指腹一下下蹭过剑鞘的铜扣。外头有人在练早课，木剑交击声隔着
院墙传进来，闷闷的。

「你到底去不去。」
```

AI 味（段段等长，无短段）：
```
他沉默了很久没有说话，似乎在思考着什么。窗外的阳光透过斑驳的树影洒落在地面上，
形成一片片光斑。陈墨把剑横在膝上，指腹缓缓蹭过剑鞘的铜扣，心中百感交集。外头有
人在练早课，木剑交击声隔着院墙传进来，显得格外清晰。你到底去不去，这个问题仿佛
悬在空气中，久久不散。
```

#### 对话标签

自然（少标签，靠动作）：
```
「去。」

陈墨站起身，剑入鞘。

「那就走吧。」
```

AI 味（句句带标签）：
```
「去。」他淡淡地说道。

陈墨站起身，将剑缓缓入鞘，沉声道：「那就走吧。」
```

#### 情绪表达

自然（呈现）：
```
他攥着杯子，指节发白。茶凉了也没喝。
```

AI 味（告知）：
```
他心中涌起一股难以言喻的愤怒，情绪久久不能平复。
```

#### 比喻

自然（具体、贴视角）：
```
那剑光快得像劈柴，没花架子，一下就是一下。
```

AI 味（套式、泛化）：
```
那剑光宛如一道银色的闪电，划破了寂静的夜空，仿佛要将天地一分为二。
```

#### 语气词

自然（随角色）：
```
「急什么嘛，」老头子磕了磕烟袋，「路又不会跑。」
```

AI 味（无语气词，书面腔）：
```
「不必着急，」老者平静地说道，「路途不会自行消失。」
```

#### 省略

自然（省主语、省过渡）：
```
推门。屋里没人。桌上摊着半张地图，墨还没干。
```

AI 味（不省略，句句自洽）：
```
他推开房门，发现屋里并没有人。他注意到桌上摊着半张地图，地图上的墨迹还没有干透，
似乎刚刚有人在这里看过地图。
```

#### 排比

自然（偶发、各异）：
```
他不是怕，是没力气怕了。累，饿，还想睡。
```

AI 味（同构三连）：
```
他不是在退缩，而是在积蓄力量；不是在逃避，而是在寻找时机；不是在放弃，而是在
等待重生。
```

#### 结尾

自然（停在动作/余韵）：
```
门关上。脚步声远去。

茶还热着。
```

AI 味（升华/预告）：
```
门关上的那一刻，他终于明白，这一切才刚刚开始。命运的齿轮，已然悄然转动。
```

### 基准表的使用方式

1. **写前对齐**：写作特工写第 N 章前，可速读基准表，校准本章节的自然文本取向。
2. **改中对照**：反AI编辑润色时，逐段对照基准表，凡偏离自然基准的维度即标记修改。
3. **量化校验**：`check_text.py --style-stats` 输出的统计指标（段长、句长、对话比等）
   可与基准表数值对照，偏离大的维度优先处理。
4. **文风校准联动**：`style_calibration_ch{N}.md` 的漂移检测维度与基准表维度对齐——
   当漂移分数高时，基准表指明回调方向。

## 与 check_text.py --deslop 模式的集成关系

`check_text.py` 除前文所述的 `--gate-report`（门禁检测）与 `--style-stats`（风格统计）
模式外，还提供 `--deslop` 模式——机器辅助去AI味的半自动通道。本节定义两遍式工作流
与 `--deslop` 模式的集成关系。

### --deslop 模式的职责边界

| 能力 | 由谁负责 | 说明 |
|---|---|---|
| 命中检测（7 类 AI 模式） | `check_text.py --gate-report` | 机器检测，输出命中位置与类别 |
| 候选改法建议 | `check_text.py --deslop` | 机器给出候选改法（删/换），供人工或 Agent 采纳 |
| 终稿改法判定 | 人工/反AI编辑 Agent | 机器只给候选，终稿由人工/Agent 定 |
| 删除比例计算 | `check_text.py` 的 `count_chars` | 机器计算原文字数与删改量 |
| 伏笔/因果锚点检查 | 人工/反AI编辑 + memory-keeper | 机器不判伏笔，须交叉校验台账 |
| 收敛验证 | `check_text.py --gate-report` | 每轮润色后重跑确认 blocking 清零 |

### --deslop 模式的工作流位置

```
check_text.py --gate-report          ← 检测，输出命中 + 分级
        │
        ▼
确定等级（轻/中/重）→ 选择流程（两遍式 / 三遍法）
        │
        ▼
第一遍：人工/Agent 按 7 类清单清除
        │  （可调用 check_text.py --deslop 获取候选改法）
        ▼
check_text.py --gate-report          ← 验证第一遍，确认 blocking=0
        │
        ▼
第二遍：AI 自审，列 3-5 条，逐条改
        │  （可调用 check_text.py --deslop 对自审发现的新命中取候选）
        ▼
check_text.py --gate-report          ← 验证第二遍，确认无新增 blocking
        │
        ▼
check_text.py --deslop --final-check ← 终检：输出残留 advisory 与 [需复核] 建议
        │
        ▼
输出字数协议 + [需复核] 清单 + 更新门禁状态
```

### --deslop 模式的输入与输出

**输入**：
- 正文文件路径
- `设定/禁用词.txt`（AI 高频词表）
- `.deslop-whitelist`（白名单）
- `--gate-report` 产出的 `check_ch{N}.json`（命中位置，避免重复检测）

**输出**（`--deslop` 模式）：
- 候选改法清单：每条命中给出「删除 / 替换」候选，标注置信度
- 删改量预估：按候选改法执行后的预估删改字符数
- 残留标记：机器无法给出候选改法的命中（如语境依赖强的改写），标 `[需人工]`

```json
{
  "chapter": 37,
  "candidates": [
    {
      "line": 42,
      "pattern": "ai_high_freq",
      "original": "仿佛",
      "action": "delete",
      "confidence": 0.95,
      "reason": "感知模糊词，删除不影响理解"
    },
    {
      "line": 78,
      "pattern": "meaning_inflation",
      "original": "一种难以言喻的孤独感涌上心头",
      "action": "replace",
      "candidate": "他一个人坐到天亮",
      "confidence": 0.6,
      "reason": "意义膨胀，候选为具体动作；但需确认是否丢失情绪铺垫"
    }
  ],
  "need_human": [
    {
      "line": 105,
      "pattern": "generic_conclusion",
      "original": "这一刻他终于明白了",
      "reason": "位于高潮段，改写风险大，需人工定夺"
    }
  ],
  "estimated_delete_chars": 187,
  "estimated_delete_ratio": 0.066,
  "tier": "轻"
}
```

### 集成的三条原则

1. **机器给候选，人工定终稿**：`--deslop` 的候选改法置信度 < 0.8 的一律不自动 apply，
   须人工/Agent 确认。置信度 ≥ 0.95 的纯删除类（如「仿佛」「似乎」）可自动 apply，
   但须记录在润色报告中备查。

2. **删改量预估前置**：`--deslop` 在给出候选前先估算删改量与删除比例，若预估已超
   上限 × 80%（橙灯），则只输出最毒的若干候选，其余标 `[需人工]`，避免引导 Agent
   超限删除。

3. **--deslop 不替代自审**：`--deslop` 是第一遍的辅助（给候选改法），不替代第二遍的
   AI 自审。第二遍自审是「跳出机器视角的人脑/AI 复查」，`--deslop` 无法替代这种
   整体性判断。两遍式的核心价值正在于第二遍的自审，不可省略。

### --deslop 与既有门禁的衔接

`--deslop` 模式不产出独立的门禁产物——它的候选改法是过程数据，采纳后体现在改后正文
与 `--gate-report` 的重新验证中。具体衔接：

- `--deslop` 读取 `check_ch{N}.json` 的命中作为输入（不重复检测）。
- 候选采纳后，正文被修改，须重跑 `--gate-report` 更新 `gate_ch{N}.json` 的
  `text_check` 段与 `deslop_score`。
- `--deslop` 的 `need_human` 项与两遍式的 `[需复核]` 项合并，统一进入润色报告的
  `[需复核]` 清单。
- `--deslop --final-check`（终检）输出的残留 advisory，作为收敛判定的依据——
  残留 < 10 处则通过，≥ 10 处则标 `[需复核]`。

### 标准命令序列（两遍式 + --deslop）

```bash
# 0. 门禁检测，输出命中与分级
python scripts/check_text.py "正文/第037章_标题.md" --min-chars 2000 --max-chars 3500 \
  --ledger "追踪/伏笔台账.md" --current-chapter 37 --gate-report --gate-state

# 1. 读取 check_ch37.json，确定 deslop_grade → 选择两遍式（轻/中）

# 2. 第一遍：获取候选改法
python scripts/check_text.py "正文/第037章_标题.md" --deslop
# → 人工/Agent 按候选 + 7 类清单清除，apply 到正文

# 3. 第一遍验证
python scripts/check_text.py "正文/第037章_标题.md" --gate-report
# → 确认 blocking=0；若未清零，补改

# 4. 第二遍：AI 自审（列 3-5 条，逐条改）
# → 可对自审新发现调用 --deslop 取候选

# 5. 第二遍验证
python scripts/check_text.py "正文/第037章_标题.md" --gate-report
# → 确认无新增 blocking

# 6. 终检：残留 advisory 与 [需复核] 建议
python scripts/check_text.py "正文/第037章_标题.md" --deslop --final-check

# 7. 输出字数协议 + [需复核] 清单，更新门禁状态
python scripts/check_text.py "正文/第037章_标题.md" --gate-report --gate-state
```

> **注**：`--deslop` 与 `--final-check` 为本文件约定的扩展模式，若 `check_text.py`
> 当前版本未实现，可由 Agent 按 `--gate-report` 的命中手动执行第一遍清除、按
> `--style-stats` 的统计辅助第二遍自审，流程不变，仅候选改法由人工/AI 自行生成。
