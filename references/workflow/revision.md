# 大修流程（revision）

适用场景：改纲波及已写章节、开篇重写、平台迁移改写（同一本书按另一个平台的节奏重切）、
盲评后的大规模修订。小改（改字句、顺逻辑）不需要本流程，直接在章节上改即可。

## 原则

- 先改纲，后改正文——纲是正文的依据，顺序反了就是拿正文迁就现场。
- 已发布章节的修改必须作者确认；未发布章节按改纲级联直接修。
- 大修期间冻结新章：修完之前不写新内容，防止新旧版本交错污染。

## 流程

### Step 1：冻结与登记

在 `设定/题材定位.md` 的变更记录里登记本次大修：原因、范围、起始日期。
通知作者冻结期开始。

### Step 2：改纲级联

按 `outline-system.md` 的改纲级联规则，先把大纲体系改到位并作者确认。

### Step 3：圈定受影响章节

- 用 Grep 在 `正文/` 里搜受影响的实体：被改的人物名、地点、设定名词、伏笔 ID 对应的物件。
- 列受影响章节清单（文件末尾附格式），逐章标注改法：重写 / 局部修 / 不动。

### Step 4：逐章修订

按清单执行。每章改完重跑机器闸口：

```bash
python3 scripts/check_text.py "正文/第XXX章_标题.md" --min-chars {下限}
```

在章节文件末尾追加一行修订记录：`> 修订 {日期}：{改了什么，对应哪次改纲}`。
（修订记录是给作者看的，发布前剔除。）

### Step 5：追踪文件回写（关键，最易漏）

- `章节摘要.md`：受影响章节的摘要条目**重写**（不是追加），并检查后续章节摘要里
  引用的旧信息是否还成立。
- `角色状态.md`：以修订后的最新正文为准重算当前状态；变更记录如实追加。
- `伏笔台账.md`：修正埋设/回收章节号；被删掉的伏笔销账（注明「修订删除」）；
  新增的伏笔补登记。
- `时间线.md`：同步修正。

### Step 6：解冻

全文一致性抽查（抽改动的上下游各 2–3 章连读）→ 机器闸口全绿 →
题材定位变更记录里登记「大修完成」→ 恢复单章循环。

## 受影响章节清单格式

```markdown
## 大修 {日期}：{主题}
| 章节 | 改法 | 影响点 | 状态 |
|------|------|--------|------|
| 第012章 | 局部修 | 删去{设定}的首次出场 | 完成 |
| 第015章 | 重写 | {人物}动机线变更 | 进行中 |
```
