# 导入已有书稿（import-book）

适用场景：作者带着已有书稿接手——别处写了几十章、断更多年的老书、
或之前没用本 skill 工程化管理的作品。目标：把散稿变成标准书籍工程，接入单章循环。

## 原则

- 反建的一切信息先标 `[推定]`，经作者确认后才删标记——哪些是伏笔、
  哪些是人物真面目，只有原作者知道，猜错了就是埋雷。
- 不改原稿一个字。导入期只做「理解」和「建档」，修订是之后单独的事。

## 流程

### Step 1：建骨架

按 `assets/templates/book-structure.md` 建工程目录，已有章节按 `第XXX章_{标题}.md`
拷入 `正文/`（保持原内容原顺序，编号补齐三位）。填 `设定/题材定位.md`
（题材/平台按作者当前打算填，不考古）。

### Step 2：通读取样

- 30 章以内：全部通读。
- 30 章以上：每 10 章读首章、末章 + 抽中间一章；大高潮章节（作者指出或数据好的）必读。
- 边读边记：出场人物、疑似伏笔、设定名词、时间标记。

### Step 3：反建档案

- **人物卡**（`设定/角色/`）：从言行归纳「不变量」——说话方式、行为模式、底线。
  拿不准的标 `[推定]`。
- **角色状态**：以最后一章为快照点建档；变更记录不补历史，只写「截至第 N 章」。
- **伏笔台账**：已回收的直接进 ✅；没收的进 🟡 并标 `[疑似]`，回收窗口留空待作者填；
  分不清是伏笔还是闲笔的，列在台账末尾「待确认」区，问作者。
- **章节摘要**：按模板八字段补登，可一章一条批量做；老章节「关键实体」字段务必填，
  这是日后检索的命根子。
- **时间线**：只记正文中明确出现的时间标记，不推测。

### Step 4：补登记大纲

- 已写部分：总纲按「已发生的实际走向」反推填写（注明「追认版」）；已写区间
  不需要逐章补章纲，卷纲按单元补简版即可。
- 未写部分：从下一章起按正常流程出章纲。

### Step 5：作者会签

把 `[推定]`/`[疑似]` 清单一次性给作者过：确认、修正、或删除。
会签完删标记，工程正式生效。

### Step 6：接入循环

下一章起走标准单章循环（`chapter-loop.md`）。前 3–5 章写作时对原稿文风做一次校准：
用 `scripts/check_text.py --style-stats` 量化老章节，填进 `设定/文风锚.md`，
保证续写不「变味」。

## 逆向工程四阶段流程（增强版）

导入已有旧稿不再只是「把文件搬进目录」，而是完整的逆向工程，产出与从头开书同等的结构化资产。

### Stage 1：结构扫描
- 扫描旧稿文件，统计章数、各章字数、总字数
- 检测文件命名是否规范，不规范的批量重命名（三位补零）
- 判断长短篇：单章均长 >1500 字为长篇，<1500 字为短篇
- 产出：`参考资料/结构扫描报告.md`

### Stage 2：提取与结构化
长篇：
- 逐章提取关键实体 → `追踪/entity_index.json`（entity_index.py build）
- 逐章生成摘要 → `追踪/章节摘要.md`
- 提取角色 → `设定/角色/{角色名}.md`
- 提取伏笔线索 → `追踪/伏笔台账.md`
- 建立时间线 → `追踪/时间线.md`

短篇：
- 提取核心框架（情绪目标/反转/人设）→ 评估是否补写为五段式
- 提取角色 → 角色卡

### Stage 3：对标分析
- 如果有对标书，跑 deconstruct.py 对标分析
- 提取文风指纹 → `设定/文风锚.md`（style_fingerprint.py extract）
- 产出：`对标/` 目录结构化资产

### Stage 4：补齐缺失资产
- 按 book-init.md Step 2-5 补齐：世界观/读者契约/总纲/卷纲/章纲
- 追踪文件已有则校验（validate_tracking.py），格式不合规的修复
- 跑 resume.py 确认无欠账
- 产出：完整的书籍工程，可立即进入 chapter-loop 写作循环

> Stage 2 的提取工作量大时，可按「每批 10-20 章」分批处理，每批后跑 validate_tracking.py 复核。
