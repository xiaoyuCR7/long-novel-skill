# 日更写前 fail-fast 检查（daily-failfast）

日更批量模式下，每章动笔前必跑的五类资料完备性检查。缺必读资料即 fail-fast 停止，
输出明确修复动作，绝不带病开写。本文件是 `daily-batch.md` 的写前检查清单，与
`chapter-loop.md` 的单章循环互补。

## 何时用这个

- 进入 `daily-batch.md` 的串行批量模式，准备连写 2–3 章时，每章 Step 1（读章纲）之后、
  Step 2（检索）之前跑一遍。
- `auto-write.md` 托管模式每章 PLANNING→WRITING 之间也跑（托管把 fail-fast 纳入自动补账逻辑）。
- 不适用：短篇（走 `short-story-loop.md`）；单章精写且作者明确说「跳过检查直接写」
  （风险自担，但机器闸口仍不可跳）。

## 与 chapter-loop.md / daily-batch.md 的分工

三份文档管三件不同的事，不要混用：

| 文档 | 管什么 | 触发粒度 |
|---|---|---|
| `chapter-loop.md` | 单章完整写作循环（Step 0–8） | 每章 |
| `daily-batch.md` | 多章串行编排、批次级检查、退化防护 | 每批（2–3 章） |
| `daily-failfast.md`（本文件） | 每章写前的资料完备性检查 + fail-fast | 每章写前 |

`daily-batch.md` 管「一批怎么连写不退化」，`chapter-loop.md` 管「一章怎么写好」，
本文件管「开写前资料齐不齐、不齐就停」。本文件的检查插在 `chapter-loop.md` 的
Step 1（读章纲）与 Step 2（检索）之间，是 Step 2 检索的前置门——资料不齐的检索是无效检索。

## 核心原则：fail-fast 优于硬写

日更最大的隐性成本不是写慢，而是「资料缺失状态下硬写出一章废稿」。废稿要返工，返工比
从头写更耗时，还会污染追踪文件。因此本文件遵循 fail-fast 原则：

- **缺必读资料 → 立即停止，不尝试绕过。** 模型不得用「凭印象」「大概是这样」补齐缺失
  资料后继续写。
- **停止时输出可执行的修复动作**，而不是泛泛报错。修复动作必须指向一个具体工作流或命令。
- **修复后从断点继续**，不重跑已通过的检查项。

## 五类必读资料

逐类检查，顺序固定（1→2→3→4→5）。前四类缺失即 fail-fast 停止；第五类缺失只跳过不停止。

### 资料一：对标情绪模块

- **路径**：`对标/{对标书名}/情绪模块.md`
- **作用**：本章要交付什么情绪、用什么情绪曲线推进，参照对标书的情绪模块设计。日更连写
  最易情绪断裂（上一章燃、这一章突然平淡），情绪模块是基准锚。
- **缺失处理**：**fail-fast 停止**。
- **修复动作**（模型须输出给作者）：

  ```
  [fail-fast] 缺失必读资料：对标/{书名}/情绪模块.md
  原因：情绪模块是对标拆文产物，写作时作为本章情绪曲线的基准锚。
  修复：请先运行拆文流程（references/workflow/deconstruct.md），
        至少完成对标书「情绪模块」维度的拆解，产出 对标/{书名}/情绪模块.md 后再开写。
  指令示例：python scripts/deconstruct.py "{对标书文本路径}" --focus emotion
  ```

- **检查方式**：确认 `对标/{书名}/情绪模块.md` 存在且非空。有多本对标书时，取
  `设定/题材定位.md` 中登记的主对标书。

### 资料二：对标节奏

- **路径**：`对标/{对标书名}/节奏.md`
- **作用**：本章档位（快/中/慢）与 A/B/C 配额预声明要对标对标书的节奏分布，防止日更连写
  时档位失衡（连续快档或连续慢档）。
- **缺失处理**：**fail-fast 停止**。
- **修复动作**：

  ```
  [fail-fast] 缺失必读资料：对标/{书名}/节奏.md
  修复：请先运行拆文流程（deconstruct.md），完成对标书「节奏」维度拆解，
        产出 对标/{书名}/节奏.md 后再开写。
  ```

- **检查方式**：确认 `对标/{书名}/节奏.md` 存在且非空，与资料一同一对标书。

### 资料三：题材定位 + 题材卡

- **路径**：`设定/题材定位.md` + `references/genres/{对应题材卡}.md`
- **作用**：题材卡约束本章的爽点类型、场景颗粒、声线要求、专属禁用词。没有题材卡 =
  写作没有题材边界约束。
- **缺失处理**：**不停止，自动生成**。
  - `设定/题材定位.md` 缺失 → 先问作者主题材（不猜），写入后继续。
  - 题材定位存在但题材卡未匹配 → 用 `references/genres/INDEX.md` 的别名表匹配：
    1. 读 `设定/题材定位.md` 的主题材字段。
    2. 在 `genres/INDEX.md` 别名表里查主题材 → 命中则加载对应题材卡。
    3. 匹配不到 → 回退 `references/craft/` 通用工艺，并提示作者可按 INDEX.md 末尾规范新建题材卡。
- **修复动作**（匹配不到时）：

  ```
  [warn] 题材卡未匹配：主题材「{题材}」在 genres/INDEX.md 无对应卡。
  已回退通用工艺（references/craft/），本章按通用规则写。
  建议：按 INDEX.md 末尾规范新建 references/genres/{题材}.md，补全题材约束。
  ```

- **注意**：题材包加载协议（SKILL.md）要求只载一张卡，本检查只确认「能载到一张」，
  不改变加载逻辑。

### 资料四：文风锚 / 文风

- **路径**：`设定/文风锚.md` 或 `设定/文风.md`
- **作用**：本章正文要对齐这本书的腔调。文风锚含腔调关键词、样板段落、量化基线
  （六维指纹 + AI 味分数基线）。
- **缺失处理**：**fail-fast 停止**（两个文件都不存在）。
- **修复动作**：

  ```
  [fail-fast] 缺失必读资料：设定/文风锚.md（且 设定/文风.md 不存在）
  原因：无文风锚则正文腔调无基准，日更连写必漂移。
  修复：请先创建文风锚。有样章→用 style_fingerprint.py extract 反推量化基线；
        无样章→先填腔调关键词与「不用的腔调」，前 3–5 章写完后补量化基线与样板段落。
  详版：references/workflow/book-init.md Step 2。
  ```

- **检查方式**：先查 `设定/文风.md`（见自定义文风模式），不存在再查 `设定/文风锚.md`。
  两者皆无 → fail-fast。

### 资料五：对标章节摘要（按情绪挑 1 章）

- **路径**：`对标/{对标书名}/章节/第K章_摘要.md`
- **作用**：按本章计划的情绪/基调，从对标书章节摘要里挑 1 章作为节奏与情绪落点的参照。
  这是「临场对照」，不是必读基准。
- **挑选规则**：读本章章纲的「目标情绪」「档位」字段 → 在 `对标/{书名}/章节/` 目录里
  找情绪/档位最接近的一章摘要。
- **缺失处理**：**跳过，不停止**。该对标书尚未拆到章节级（只拆了情绪模块/节奏）是正常的，
  缺这一项不影响开写。
- **提示**：跳过时在写前速记里标注「未找到对标章节参照，情绪落点凭情绪模块把握」。

## 自定义文风模式

`设定/文风.md` 是作者自定义文风的可选文件。当它存在且含实质内容时，进入自定义文风模式：

- **判定标准**：`设定/文风.md` 存在 且（字数 ≥ 200 字 或 含至少一个风格小节标题，如
  `## 声线`/`## 句式`/`## 用词偏好`/`## 不用的腔调`）。
- **进入自定义文风模式后**：
  - `设定/文风.md` 成为本书正文腔调的第一基准。
  - `设定/文风锚.md` 与对标文风降级为参考（仍可读，但冲突时以 `设定/文风.md` 为准）。
  - 机器闸口 `style_fingerprint.py compare` 的对比基线改用 `设定/文风.md` 提取的指纹
    （若文风.md 含样板段落）。
- **未达判定标准**：`设定/文风.md` 存在但内容过少（< 200 字且无风格小节）→ 视为占位文件，
  不进入自定义模式，仍以 `设定/文风锚.md` 为准；提示作者补全文风.md 或删除占位。

自定义文风模式适用于：作者已有强烈个人文风、不想被对标书腔调带偏的场景。开书时若选了
自定义文风，应在 `设定/题材定位.md` 标注「文风模式：自定义」，让后续会话恢复时知道用哪个基准。

## fail-fast 执行协议

每章写前按以下协议执行，模型须严格按步骤输出：

```
1. 顺序检查资料一→五，每类输出一行状态：
   [OK]   资料一 对标/{书名}/情绪模块.md
   [OK]   资料二 对标/{书名}/节奏.md
   [GEN]  资料三 题材定位 + 题材卡（已匹配/已回退）
   [OK]   资料四 设定/文风锚.md（或 [CUSTOM] 设定/文风.md 自定义模式）
   [SKIP] 资料五 对标章节摘要（未找到，已跳过）

2. 任一必读项 [MISS] → 立即输出修复动作块（见各资料修复模板），停止后续检查与写作。
   修复动作块格式：
   [fail-fast] 缺失：{路径}
   原因：{一句话}
   修复：{具体工作流/命令}

3. 全部通过（或仅资料五 SKIP）→ 输出「写前检查通过」，进入 chapter-loop.md Step 2 检索。

4. 资料三 [GEN] 回退通用工艺时，不停止，但在写前速记标注「无题材卡约束，按通用工艺」。
```

**纪律**：
- 模型不得自行「脑补」缺失资料的内容后继续写。例如情绪模块缺失，不得凭章纲推测情绪曲线
  就开写——必须 fail-fast。
- 修复动作必须可执行：指向 `deconstruct.md`、`book-init.md`、具体脚本命令，或具体的
  「新建文件并填写哪些字段」。
- fail-fast 停止后，作者修复资料，重新进入本检查，从资料一重跑（已通过项快速确认即可，
  重点验修复项）。

## 日更质量门

批量模式下「快」不等于「跳」。每章仍须走完整单章循环，三个质量门一个不能少：

1. **机器闸口**：`check_text.py`（7 Gate + 字数 + 禁用词 + 毒句式 + 伏笔超期 + 量化打分）
   + `rhythm_guard.py`（A/B/C 配额 + 事件冷却 + 档位）+ `style_fingerprint.py compare`
   （每 5–10 章）。FAIL 项必须处理完才进下一步。
2. **自查清单**：`chapter-loop.md` Step 6 的 13 项逐项过，任一答「否」回去改。
3. **追踪更新**：章节摘要/角色状态/伏笔台账/时间线/节奏配额五文件回写 +
   `validate_tracking.py` + `entity_index.py build`。

**不允许的跳步**（即使日更赶进度）：
- 跳过机器闸口直接发布。
- 只更新章节摘要不更新伏笔台账（伏笔断线是连载硬伤）。
- 用「下一章一起补追踪」拖延（铁律第 1 条：欠账未清禁止开写下一章）。
- 批量模式下「先写完 3 章正文再统一过闸口」——必须一章一闭环。

`daily-batch.md` 的串行纪律已经要求「前一章 Step 8 完成且追踪更新后才开下一章 Step 0」，
本文件在此基础上加「每章写前的资料完备性检查」。两者叠加 = 日更批量模式下的双保险。

## 五类资料检查清单（可勾选）

```
日更写前 fail-fast 检查 · 第 N 章
[ ] 资料一  对标/{书名}/情绪模块.md 存在且非空
[ ] 资料二  对标/{书名}/节奏.md 存在且非空
[ ] 资料三  设定/题材定位.md 存在；题材卡已匹配（或已回退通用工艺并标注）
[ ] 资料四  设定/文风锚.md 存在  /  设定/文风.md 自定义模式已激活（二选一）
[ ] 资料五  对标章节摘要已挑 1 章（或已标注 SKIP 原因）
[ ] 文风模式  [ ] 锚定模式  [ ] 自定义模式（文风.md ≥200字）
[ ] 质量门预案  本章将完整走 机器闸口→自查→追踪更新，不跳步
```

## 与其他工作流的关系

| 场景 | 用哪个 |
|---|---|
| 每章写前查资料齐不齐 | `daily-failfast.md`（本文件） |
| 一批 2–3 章怎么连写 | `daily-batch.md` |
| 单章完整写作循环 | `chapter-loop.md` |
| 缺对标拆文素材 | `deconstruct.md`（补拆） |
| 缺文风锚 | `book-init.md` Step 2（创建文风锚） |
| 缺题材卡 | `genres/INDEX.md`（匹配/新建） |
| 托管连写 N 章 | `auto-write.md`（托管模式把本检查纳入自动补账） |

本文件不替代任何工作流，只在每章写前加一道资料完备性闸门。资料齐了，才放行进入
`chapter-loop.md` 的检索与写作。
