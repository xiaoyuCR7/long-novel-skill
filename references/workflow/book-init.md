# 开书流程（book-init）

从零到开书提案，再到获准写第一章的流程；按本轮授权执行，不要求每次走完全程。
需要落盘时产物放在书籍工程目录里；
模板统一从 `assets/templates/` 拷贝后填写，不要原地改模板。
（带已有书稿接手不走本流程，走 `workflow/import-book.md`。）

## Step 0：创意与定位（按动作核对前提）

先区分作者已确认的信息、可设计的提案与作者保留的决定，再整理以下信息；缺项不等于全流程停止：

- 一句话卖点（这本书看什么？）
- 主题材（+ 可选辅题材）→ 决定加载哪张题材卡
- 目标平台（番茄/起点/晋江/知乎盐言/番茄短篇/其他）→ 决定章长与更新排产
- 目标总字数与更新计划（日更几章、每章多少字）
- 读者契约三要素：核心快感、兑现频率、红线（绝不写什么）→ 详见 `craft/reader-contract.md`
- 对标作品（1–3 本，没有可跳过）

| 当前动作 | 真正前提与缺项处理 |
|---|---|
| 讨论定位/设定 | 只处理作者要求的内容；「只聊设定」「先别排纲」不授权总纲、卷纲或章纲 |
| 设计开书包 | 允许规划，且已有信息足以支撑相应设计；交付定位、读者契约、核心设定、总纲、首卷及首批 5–10 章章纲，用户指定批量优先。新设计标「提案，未锁定」，不等待所有定位字段齐全 |
| 更新排产 | 日更章数、章长等排产参数；缺日更只把排产留待定，不阻断总纲/卷纲/章纲，不承诺完结日期 |
| 锁纲/写正文 | 对应作者授权、章纲与 required context 及既有写前门禁；开书包或模板齐全不等于获准写作 |
| 发布 | 发布前才核对正式书名、平台、简介/标签/封面等所需资料与发布门禁；资料缺失不阻断开书提案，外部提交仍需明确授权 |

书名和对标可待定；样章及 benchmark/对标校准是可选输入，不是开书门槛。
题材、平台、核心承诺、篇幅等缺项若影响某项设计，只停依赖该选择的部分并提出具体问题，
继续其余有依据、获授权的交付。关键事实冲突同样局部阻断；不得为凑齐模板擅定平台、
捏造已发生事实或覆盖作者红线。新创作只在授权范围内作为提案，不冒充已确认设定。

需要建工程时使用 Step 1 的骨架（结构见 `assets/templates/book-structure.md`），将信息分别填进
`设定/题材定位.md`（模板：`assets/templates/genre-profile.md`）和 `设定/读者契约.md`
（模板：`assets/templates/reader-contract.md`），明确标注待定项与提案状态。

## Step 1：一键建骨架（init_book.py）

把 Step 0 的「目录骨架 + 模板拷贝」从手工活变成一条命令：

```bash
python scripts/init_book.py "{书名}" --genre {主题材} --platform {目标平台}
# 指定父目录：--dir "D:/存放/小说"
# 目录已存在且非空时加 --force 重建缺失模板（不动 正文/ 与 大纲/）
```

脚本会按 `assets/templates/book-structure.md` 的布局创建：

```
{书名}/
├── 大纲/  正文/  对标/  参考资料/
├── 设定/  题材定位.md（已轻量预填书名/主题材/平台）、读者契约.md、文风锚.md、敏感词替换表.md、禁用词.txt、角色/
├── 追踪/  伏笔台账.md、角色状态.md、章节摘要.md、时间线.md、节奏配额.md、门禁/
└── .deslop-whitelist（白名单模板）
```

五个追踪文件 + 三个设定文件均从 `assets/templates/` 原样拷贝；
`设定/题材定位.md` 已按传入的书名/主题材/平台做了轻量预填，其余字段留占位待 Step 2–5 填写。
书名未定时可用清楚标为临时的工程目录名，但目录名不等于定书名；将脚本预填书名改标为
「待定（工程目录为临时名）」。未确认字段保持待定，不把脚本默认值或模板占位当作作者决定；
参数不足以安全调用脚本时手工建骨架，不擅填题材或平台来满足参数。

> 也可手工创建目录与拷贝模板，但推荐用脚本——保证路径与文件名约定一致，
> 下游 `resume.py` / `validate_tracking.py` / `entity_index.py` 等都依赖这套约定。

骨架建好后，按 SKILL.md 的题材包加载协议，从 `references/genres/INDEX.md`
匹配并读入已确定的主题材卡；目标平台确定后读 `references/platforms/platform-guide.md` 的对应基线。
题材/平台未定时不猜选规则；只暂缓依赖该选择的适配，通用规划可继续。
**有可访问且与当前任务相关的对标材料时再分析**：抽读可用的前/中/后段各几章，记录爽点分布、钩子位置、
段落特征（可用 `scripts/check_text.py --style-stats` 量化），产出本书的差异化打法，
填进题材定位的「对标与差异化」，并为 Step 2 的文风锚积累参数。
只有书名、链接不可访问或材料不完整时，明确「未分析」或实际分析范围，不凭印象冒充拆书；
在作者输入与通用工艺范围内继续开书提案，不等待对标或 benchmark 完成。

## Step 2：世界观、人物与文风

玄幻、修仙、武道、系统及超现实混合题材先按 `references/craft/fictional-world.md` 设计。
作者允许开脑洞/设定提案即可以创造世界法则、能力与制度，不要求现实法律或科学论证；
将新方案标为提案，不冒充已确认设定。已明确无敌/无代价路线时不强加限制或惩罚。

- `设定/世界观.md`：只写「不写就会崩」的部分——世界运转的核心规则、力量/财富/权力体系、
  地理与势力格局。细则随写随补，不要开书就写十万字设定。
- `设定/角色/{角色名}.md`：先做主角，再做 2–5 个核心配角（模板：`character-card.md`）。
  人物卡重点写「不变量」（核心性格、底线、口癖），写法见
  `references/craft/character-consistency.md`。
- `设定/敏感词替换表.md`（模板：`assets/templates/sensitive-word-replacement.md`）：**与世界观同步建**——
  世界观里出现的每个地理/机构/人物名，逐一问「这是不是真实世界的东西」，是 → 登记真实
  指称与全书代称。覆盖三块：地名代称系统、别称置换规则（机构/职务/群体）、地名脱敏处理
  方法（模糊化/架空化/时间脱敏）。都市现实向、历史、军事、娱乐圈、官场商战等高敏题材必建，
  纯架空奇幻无现实指称时不需要逐项现实核验，此表可不建或只留表头，不因空表阻断创作。
  方法论见 `references/craft/sensitive-word-replacement.md`；把必禁真实专名并入
  `禁用词.txt` 可让 `check_text.py` 自动拦截（机器核对）。
- `设定/禁用词.txt`：只登记本书实际适用、作者明确要求或认可的禁词（机器闸口自动加载）；
  题材卡的候选文风词不能整段自动升级为硬禁令，系统/混合世界观中已允许的“面板、数据”等词不得误禁。
- `设定/文风锚.md`（模板：`style-anchor.md`）：作者有样章就从样章反推量化基线；
  没有就先填「腔调关键词」与「不用的腔调」，前 3–5 章写完后补量化基线与样板段落。
  量化基线可用 `scripts/style_fingerprint.py extract` 提取。

## Step 3：总纲

填 `大纲/总纲.md`（模板：`outline-master.md`）：主线一句话、分卷规划表、终局方向、
红线、读者契约摘要、终局储备边界。总纲不求细，求方向不错；它是之后所有卷纲的锚。
作者保留的最终反派、终局真相等写「待作者决定」，只记录不提前使用的边界；
不得通过候选人、幕后身份或伏笔暗示变相替作者定案。未授权排纲则不执行本步及 Step 4。
方法见 `references/workflow/outline-system.md`。

## Step 4：首卷卷纲 + 首批章纲

- 填 `大纲/卷纲_第1卷.md`（模板：`outline-volume.md`）：本卷契约、剧情单元划分、
  情绪弧线、本卷伏笔计划、大纲锚点配额、卷级档位规划草表。
- 填首批章纲 `大纲/章纲_第001章.md` 起（模板：`outline-chapter.md`），**默认首批 5–10 章即停靠**，
  用户指定批量优先；未要求时不要一口气排完整卷，首批后根据实际情况滚动补纲（见 `outline-system.md`）。
  每份章纲须声明节奏档位与 A/B/C 配额预声明。
- 前三章的章纲按 `references/craft/opening.md` 的黄金三章要求设计，
  开篇强度按「全书中等以上」排产。

## Step 5：初始化追踪文件

`init_book.py` 已经把五个追踪文件骨架拷好，这里做内容初始化（模板：`foreshadowing-ledger.md`、
`character-state.md`、`chapter-summary.md`、`timeline.md`、`rhythm-quota.md`）：

- 角色状态：录入已确认的初始状态；人物卡的新提案单独标注，不写成已发生事实。
- 伏笔台账：登记开书就计划埋设的开篇伏笔，标明尚未埋设，不冒充正文已发生的伏笔。
- 章节摘要、时间线：建好骨架，待写后填充。
- 节奏配额：建好骨架（模板：`rhythm-quota.md`），含 A/B/C 配额记录表、
  事件冷却记录表、档位记录表的空表头，待写后逐章追加。

初始化完跑一次格式校验，确认骨架合格（之后每 10 章或新会话首次再校验一次）：

```bash
python scripts/validate_tracking.py "{书名}"
```

## Step 6：停靠点——给作者确认

先执行 `outline-system.md` 的「批次衔接复核」：连读首批章纲，核对相邻章的时间、持有/
知情状态与主张/承诺。逐文件齐全或追踪格式通过，不等于故事连续性通过；发现矛盾先修
获授权的未写计划，不把未写提案回填为已发生事实。

按授权完成的开书包标明「提案，未锁定」，向作者汇报一页纸摘要：实际交付的定位、核心设定、
总纲主线、首卷契约与首批章纲，另列待定项、局部阻塞及未执行的检查。日更未定就只标排产待定。
确认提案、锁纲与授权写正文是不同动作；**获得写作授权且写前前提齐备后才进入写作**。
作者要改就改在获授权的文件里，不把口头讨论当已锁定结果；未授权时不发布。

## 后续衔接

开书完成后，进入写作阶段，每次开工先跑一次会话恢复：

```bash
python scripts/resume.py "{书名}"
```

它会报告上一章门禁是否通过、追踪文件是否同步、伏笔台账有无 🔴 超期、下一章章纲是否就位。
有欠账先补账，无欠账才开写（铁律第 1 条）。单章写作循环见 `references/workflow/chapter-loop.md`。
