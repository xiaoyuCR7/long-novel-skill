# 跨 Agent 审核协议（cross-review）

章级跨 Agent 审核：把已写章节交给另一个模型/会话，以「资深网文编辑」视角找茬，捕获同源
模型审不出的问题。本文件是章级审核；卷级多视角盲评用 `references/craft/review-rubric.md`。

## 何时用这个

- `auto-write.md` 托管模式每 10 章自动触发一次（托管不依赖人工，到点自动送审）。
- 人工日更每 10 章主动送审一次（`daily-batch.md` 累计到 10 章时）。
- 单章门禁通过但作者「手感不对」、想找第二意见时，单独送审该章。
- 上架/签约/卷末前加做一次。

不适用：卷级商品评审（用 `review-rubric.md` 四视角盲评）；单章生产内审（用
`editorial-spawn.md` 团队流程或 `chapter-loop.md` 自查）。

## 与 review-rubric.md 的分工

| 文档 | 粒度 | 视角 | 触发 |
|---|---|---|---|
| `review-rubric.md` | 卷级（5–15 章一个剧情单元） | 四视角盲评（追读读者/新读者/平台编辑/同行作者） | 每卷/重大节点 |
| `cross-review.md`（本文件） | 章级（单章或连续 10 章） | 单视角资深编辑找茬 | 每 10 章/按需 |

`review-rubric.md` 回答「这卷作为商品读者买账吗」，本文件回答「这几章有没有硬伤和弃书点」。
两者互补：卷级盲评看整体，章级跨审看细节。

## 审核路由表

跨 Agent 审核的核心价值是「异源」——不同模型有不同偏见，交叉审核能发现同源审不出的问题。
按当前会话的模型选路由：

| 当前写作模型 | 送审目标 | 路由类型 | 可靠性 |
|---|---|---|---|
| Claude | Codex / GPT | 异源审核 | 最高 |
| OpenCode（Claude 内核） | GPT / Gemini | 异源审核 | 最高 |
| Codex / GPT | Claude | 异源审核 | 最高 |
| 任一模型（无第二模型） | 同模型新会话（无上下文） | 同源多会话 | 中 |
| 任一模型（无新会话能力） | 同会话切换编辑视角 | 同会话切换 | 低 |

**降级原则**：优先异源 → 退而求其次同源多会话 → 最后同会话切换。不跳级。降级到同会话切换时，
审核结论必须标注「同源同会话审核，结果仅供参考」。

异源审核的实操：把待审章节正文 + 审核提示词导出为文本，由作者粘贴到另一个模型
（或用支持多模型的工具链）执行，再把审核报告贴回。本协议不规定传输工具，只规定审核提示词
与报告格式。

## 审核官人设

所有路由统一人设，确保审核尺度一致：

```
你是一位有十年经验的网文连载编辑，专审商业网文。
你的工作风格：零容忍找茬，不客套，不凑好话。
- 发现问题直说，指出具体段落、具体句子。
- 不写「总体不错」「有一定可读性」这类废话。
- 没问题就说「没找到硬伤」，不硬挑。
- 你的目标是帮作者避免弃书和崩盘，不是夸作者。
```

## 三维度审核报告

审核官按三个维度审，每个维度独立出具结论。报告模板：

```markdown
# 跨 Agent 审核报告 · 第 {X}–{Y} 章

## 维度一：逻辑硬伤
逐一列出，无则写「无」。
- [类型] 第 X 章 {段落定位}：{问题描述}
  类型枚举：角色已死又出现 / 时间线错乱 / 主线矛盾 / 设定冲突 / 伏笔断线 / 能力越界
- ...

## 维度二：阅读体验
- 弃书点：第 X 章 {段落}，原因：{为什么想弃}
- 追读动力：此刻最想知道 { }；若答不上来 = 追读动力不足
- 节奏问题：{哪章太快/太慢/注水}
- 情绪断裂：{哪章情绪接不上前一章}

## 维度三：去 AI 化
- 7 Gate 命中：Gate {A-G} × {N} 处，举例 {句子}
- 文风漂移：与本书文风锚对比，{哪一维漂了}
- 毒句式：{否定翻转/万能状语/声音套话} × {N} 处
- AI 味主观评分（1-10）：{分}，依据：{ }

## 结论
- P0：{条目}  ← 立即改，改完才发
- P1：{条目}  ← 本卷内改
- P2：{条目}  ← 下次修订
```

三个维度的判定来源：
- **逻辑硬伤**：纯客观，交叉对照追踪文件（角色状态/伏笔台账/时间线）即可判定。审核官
  不一定有追踪文件，所以这一维主要靠正文内部一致性 + 审核官的连载经验。
- **阅读体验**：主观但可执行——弃书点和追读动力是两个硬指标，答得出来就有价值。
- **去 AI 化**：可与机器闸口 `check_text.py --gate-report` 的输出对照；机器查到的 Gate 命中，
  审核官应能给出具体句子佐证；机器没查到但审核官主观觉得 AI 味重的，记为 P2 观察。

## P0/P1/P2 分级与处置

| 级别 | 标准 | 处置时限 | 处置方式 |
|---|---|---|---|
| P0 | 逻辑硬伤（角色已死又出现/主线矛盾/时间线错乱/设定冲突） | 立即改，改完才发 | 当章返工，走 `chapter-loop.md` Step 4–7 |
| P1 | 阅读体验重大问题（弃书点/追读动力不足/节奏断裂/情绪断裂） | 本卷内改 | 记入卷纲批注，本卷结束前修订 |
| P2 | 文风/节奏微调（Gate 命中少/文风漂移轻/AI 味略高） | 下次修订 | 记入 `revision.md` 修订清单 |

**P0 处置纪律**：P0 是「发出去就翻车」的级别，必须立即改、改完才发。托管模式
（`auto-write.md`）遇到跨审 P0 → 熔断停止，不继续写下一章。

## 批处理审核

每 10 章批量送审，而非逐章送审（逐章送审成本高、且单章难判节奏问题）：

- **送审单元**：连续 10 章正文（一个完整剧情单元最佳）。
- **送审内容**：10 章正文 + 审核官人设 + 三维度报告模板。不给大纲、人物卡、创作意图
  （盲审原则，避免审核官被作者意图带偏）。
- **可选附送**：本书文风锚（让审核官判文风漂移有基准）；近 10 章机器闸口报告（让审核官
  对照机器查到的 Gate 命中）。追踪文件不送（审核官靠正文内部一致性查逻辑硬伤，不靠追踪文件）。
- **审核结果落盘**：`追踪/cross_review/ch{X}_{Y}.json`，X=起章，Y=止章。

落盘 JSON 结构：

```json
{
  "range": "ch025-ch034",
  "review_at": "2026-07-28T15:00:00",
  "route": "claude->gpt",
  "degradation": "L1",
  "reviewer_persona": "十年网文连载编辑",
  "logic_hard_faults": [
    { "chapter": 28, "type": "时间线错乱", "location": "第3段", "detail": "上章结尾是夜里，本章开头是中午，无时间过渡" }
  ],
  "reading_experience": {
    "drop_points": [{ "chapter": 30, "location": "章中", "reason": "主角突然原谅仇人，动机不足" }],
    "read_drive": "想知道主角如何破解符文陷阱",
    "pacing_issues": ["第31章注水，整章无信息推进"],
    "emotion_breaks": ["第29章燃→第30章平淡，情绪没接住"]
  },
  "de_ai": {
    "gate_hits": { "B": 3, "C": 2, "F": 1 },
    "style_drift": "对话声线趋同，遮名字认不出谁说的",
    "toxic_patterns": ["否定翻转 x2", "万能状语 x1"],
    "ai_score": 4.1
  },
  "verdict": { "P0": 1, "P1": 3, "P2": 5 },
  "round": 1
}
```

## 防死循环

跨审也可能陷入「改了审、审了改」。硬规则：

1. **单章最多 3 轮审核**：同一章送审 3 轮仍有 P0 → 停止自动返工，把争议点列给作者裁决。
2. **连续 3 章「有条件通过」→ 强制人工介入**：「有条件通过」= 无 P0 但有未解决 P1。
   连续 3 章说明系统性问题（纲/设定层面），暂停送审，走 `revision.md` 或
   `outline-system.md` 改纲。
3. **审核不迭代**：同一批 10 章同一审核官只审一轮，不因「报告不满意」重审。要第二意见 →
   换路由（异源换另一个模型），不原地重审。
4. **轮次记入 JSON** 的 `round` 字段，跨章累计，防丢失。

## 异源审核降级策略

与 `review-rubric.md` 的 L1/L2/L3 一致：

| 级别 | 条件 | 审核方式 | 标注 |
|---|---|---|---|
| L1 异源多模型 | 有 2+ 不同模型可用 | 不同模型审核 | `degradation: L1` |
| L2 同模型多会话 | 仅 1 模型但可开无上下文新会话 | 同模型新会话审核 | `degradation: L2` |
| L3 同会话切换 | 无法开新会话 | 主会话切换编辑视角 | `degradation: L3`，结论标注「同源同会话，仅供参考」 |

- L1 > L2 > L3 逐级降级，不跳级。
- L3 降级审核通过的章，门禁标「有条件通过」，下次有机会做 L1/L2 时复审。

## 与其他工作流的关系

| 场景 | 用哪个 |
|---|---|
| 每 10 章跨 Agent 找茬 | `cross-review.md`（本文件） |
| 卷级四视角盲评 | `review-rubric.md` |
| 单章生产团队内审 | `editorial-spawn.md` |
| 托管模式自动触发跨审 | `auto-write.md`（每 10 章自动调用本协议） |
| 跨审 P0 当章返工 | `chapter-loop.md` Step 4–7 |
| 跨审 P1/P2 积累修订 | `revision.md` |

本文件与 `editorial-spawn.md` 的区别：编辑团队是「生产时内审」（写完当场审，防废稿出厂），
跨审是「出厂后抽检」（写完一段后回头审，防同源盲区）。两者不替代，叠加使用。
