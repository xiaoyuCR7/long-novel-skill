# 拆文七阶段管道（deconstruct-pipeline）

工业级对标书拆解管道。`deconstruct.md` 是轻量四维统计（用 `deconstruct.py` 脚本跑量化
扫描），适合快速摸底；本文件是**模型+脚本配合的七阶段深度拆解**，产出与从头开书同等
规格的结构化资产，直接供写作循环召回。

七阶段不是七步线性流程——Stage 0 是全局概览，Stage 1 是停靠点（可提前交付预览），
Stage 2-3 是逐章+聚合的核心分析，Stage 4-6 是设定/报告/文风的专项深化。中断后从
`_progress.md` 恢复，跳过已完成阶段。

## 与 deconstruct.md 的分工

| 维度 | `deconstruct.md` | 本文件 |
|---|---|---|
| 方法 | 脚本确定性统计（四维） | 模型+脚本配合（七阶段） |
| 产出 | 量化统计/结构分析/节奏分析/文风指纹 | 逐章摘要+聚合索引+设定档案+汇总报告+文风视图 |
| 耗时 | 分钟级 | 小时级（可分批续跑） |
| 适用 | 快速摸底、文风校准 | 深度学习对标、迁移结构资产 |
| 脚本 | `deconstruct.py` | `deconstruct.py` + 模型推理 |

两者不互斥：先跑 `deconstruct.md` 的四维统计做底稿，再启动本管道做深度拆解。

## Stage 0：概要提取

**目标**：200 字 thin first-pass 全书概要 + 章节边界表，为后续阶段建索引骨架。

**执行**：
1. 模型通读全书（或分批读取），写一段不超过 200 字的情节概要。概要只抓主线骨架，
   不写细节——这是「索引页」不是「内容页」。
2. 识别章节边界：扫描 `对标/{书名}/原文/` 下所有文件，记录每章的文件名、章节号、
   字数、首尾句摘要。产出章节边界表。

**产出**：章节边界表写入 `对标/{书名}/_progress.md` 的「章节边界表」区段。

`_progress.md` 是管道的进度中枢，结构如下：

```markdown
# 拆文进度（{书名}）

## 元数据
- schema_version: 2
- 书名: {书名}
- 总章数: {N}
- 总字数: {M}
- 拆文启动时间: {ISO时间}
- 最后更新: {ISO时间}

## 章节边界表
| 章节号 | 文件名 | 字数 | 首句摘要 | 末句摘要 | 状态 |
|---|---|---|---|---|---|
| 001 | 第001章.md | 3200 | {...} | {...} | done |
| 002 | 第002章.md | 2800 | {...} | {...} | pending |
| ... | | | | | |

## 阶段进度
| 阶段 | 状态 | 完成时间 | 产出文件 |
|---|---|---|---|
| Stage 0 | done | {时间} | _progress.md |
| Stage 1 | done | {时间} | 快速预览.md |
| Stage 2 | in_progress | - | 剧情/逐章摘要/ |
| Stage 3 | pending | - | - |
| Stage 4 | pending | - | - |
| Stage 5 | pending | - | - |
| Stage 6 | pending | - | - |

## 失败记录表
| 章节号 | 阶段 | 失败原因 | 重试次数 | 状态 |
|---|---|---|---|---|
| 047 | Stage 2 | 章节文本为空 | 0 |待修复 |
```

**恢复机制**：管道中断后重新启动时，先读 `_progress.md` 的「阶段进度」和「章节边界表」，
跳过状态为 `done` 的阶段，从 `in_progress` 或第一个 `pending` 阶段续跑。失败记录表里
的章节单独重试，不影响其他章节的进度。

## Stage 1：黄金三章深度拆解

**目标**：对标书前三章是「读者留存的关键窗口」，深度拆解其钩子结构、信息投放节奏、
人设亮相手法，停靠产出快速预览。

**执行**：
1. 逐句分析前三章的钩子位置与类型（章首钩/章中转折钩/章尾悬念钩）。
2. 标注信息投放顺序：世界观信息→金手指信息→核心矛盾信息→人设信息，各自在第几段
   第几次出现。
3. 提取人设亮相手法：主角第一次出场用什么场景、什么动作、什么对话建立第一印象。
4. 分析留存设计：第一章结尾留什么悬念、第二章开头怎么承接、第三章给读者什么甜头。

**停靠产出**：`对标/{书名}/快速预览.md`。这是管道的第一个可交付物——即使后续阶段
未完成，作者也能从快速预览获得前三章的写法参考。

快速预览.md 结构：
- 三章钩子结构图（每章的钩子位置/类型/承接关系）
- 信息投放节奏表（什么信息在第几章第几段投放）
- 人设亮相手法分析
- 留存设计要点（3-5 条可复用要点）

## Stage 2：逐章摘要

**目标**：每章产出结构化摘要，作为聚合分析和写作召回的基础数据。

**执行**：逐章处理，每章产出：
- **情节点清单**：每章拆 10-40 个情节点（视章长而定），每个情节点 150-200 字密度，
  记录「谁做了什么→导致了什么→情绪落点」。情节点不是复述剧情，是提取因果链。
- **关键信息提取**：本章投放了哪些硬设定/新角色/新地名/新规则，记入关键信息表。
- **扩写技法提取**：本章用了什么扩写手法（细节放大/情绪延展/环境烘托/心理独白），
  记录手法的触发场景和执行方式。
- **逐章写法公式**：本章的结构骨架公式化——如「压制→试探→反转半句→章尾钩」，
  供写作时匹配套用。

**产出**：`对标/{书名}/剧情/逐章摘要/第XXX章.md`，每章一个文件。

**密度标准**：情节点密度 150-200 字/个。低于 150 字 = 摘要太薄，聚合分析时信息不足；
高于 200 字 = 摘要太厚，沦为复述。每章的情节点数量根据章长动态调整：2000 字章 10-15
个，3000 字章 15-25 个，4000+ 字章 25-40 个。

## Stage 3：聚合分析

**目标**：把逐章摘要聚合为全书级索引，这是管道的核心产出阶段。

**十步聚合**（按序执行）：

1. **故事框架识别**：从逐章摘要提取全书的故事骨架——主线是什么、分几个阶段、
   每阶段的核心事件。产出故事框架图。
2. **剧情聚合**：把散落在各章的剧情线聚合为主线/副线/暗线，标注交叉点。
3. **关键信息推进索引**：把 Stage 2 提取的关键信息按时间排列，标注每条信息在哪章
   投放、哪章回收、哪章被引用。这是后续写作时查「这个设定什么时候建立的」的权威索引。
4. **情绪触动点与爆发节奏**：标记全书的情绪高点/低点/转折点，标注每个情绪节点的
   蓄积章数和爆发方式。产出情绪节奏曲线。
5. **可复现模块卡**：识别全书的可复用情绪模块（打脸/逆袭/虐恋/解谜等），每个模块
   提取结构骨架（起承转合四步），记入模块卡。
6. **角色合并去重**：逐章摘要中同一角色可能用不同称呼出现（全名/昵称/职位），合并
   去重，统一为标准角色名。
7. **角色分级**：按出场频率/剧情权重/情绪影响力把角色分为 S/A/B/C 四级。S 级=主角，
   A 级=核心配角，B 级=功能配角，C 级=背景角色。
8. **散落情节兜底**：检查有没有被聚合遗漏的情节碎片（只出现一次的角色/未被主线
   收编的事件），归入「散落情节」区，标注是否有后续回收。
9. **桥段标签**：给每个剧情单元打标签（升级/战斗/感情/阴谋/日常/探索），产出标签
   索引，供写作时按标签召回。
10. **质量检查**：对聚合产出做质量校验（见下文质量阈值）。

**关键产出文件**（权威索引，写作时直接召回）：

- `对标/{书名}/剧情/节奏.md`：关键信息推进索引 + 爽点循环 + 情绪触动点 + 爆发节奏。
  这是节奏问题的权威参考——写到某章感觉节奏不对时，读此文件查对标书在这个位置
  怎么处理节奏。
- `对标/{书名}/剧情/情绪模块.md`：读者需求分析 + 情绪引擎拆解 + 爽文套路框架 +
  可复现模块卡。这是情绪设计的权威参考——设计打脸/逆袭/虐恋场景时，读此文件查
  对标书的模块结构。

## Stage 4：设定+角色完整档案

**目标**：从拆文产物提取对标书的完整设定和角色档案，规格与本书的设定文件对齐。

**三部分产出**：

1. **设定提取**（`对标/{书名}/设定/`）：世界观/力量体系/社会结构/地理/规则约束，
   从逐章摘要的关键信息表聚合并补全。
2. **角色档案**（`对标/{书名}/角色卡/{角色名}.md`）：每个 S/A 级角色一份完整档案，
   含身份/性格/核心欲望/成长弧光/功能定位。B/C 级角色合入「配角速查表」。
3. **角色关系含演变追踪**（`对标/{书名}/角色关系.md`）：角色间的关系图谱 +
   关系演变时间线（谁和谁的关系在第几章发生了什么变化）。

## Stage 5：汇总报告

**目标**：产出一份写法技巧清单，作为写作时的快速参考。

**写法技巧清单**覆盖以下技法类别（每类 3-5 条具体技法，配原文位置标注）：

- **一笔两用**：同一段文字同时服务两个目的（如对话既推进剧情又暗示人设）
- **延迟揭示**：关键信息先埋线索不揭底，延后数章才揭晓，制造回扣感
- **视角欺骗**：利用 POV 角色信息差误导读者预期
- **对比锚点**：用配角/前例做对比锚点，放大主角的特殊性
- **行为循环**：角色重复性行为模式（口头禅/习惯动作），用于人设强化
- **身体反应替代心理**：用生理反应写情绪，不直接写情绪名词
- **跨章回扣**：前章埋的细节在后章回收，制造连贯感

**产出**：`对标/{书名}/写法技巧清单.md`。

## Stage 6：文风分析

**目标**：产出整书级文风视图，供文风校准和迁移参考。

**执行**：
1. 用 `style_fingerprint.py` 跑六维量化（句长/对话占比/段落中位长度/标点节奏/高频词/
   句式偏好），获得确定性测量数据。
2. 模型分析对话潜台词模式（角色说A但意思是B的频率和手法）。
3. 模型分析情绪交替周期（章内基调切换频率/跨章基调周期/喜剧与重击的转场手法）。
4. 选取 4-6 段原文锚点片段（每段 300-500 字），覆盖典型对话段/典型动作段/典型情绪
   高潮段/典型转场段/典型描写段/典型节奏段。
5. 给出分层模仿建议（基础层必学/进阶层结构/适配层本书化）。

**产出**：`对标/{书名}/文风.md`（详见 `craft/style-profile.md` 的产物结构协议）。

## 质量阈值

每个阶段产出后做质量校验，不达标则补做：

| 指标 | 阈值 | 含义 |
|---|---|---|
| 置信度 | >=0.85 | 模型对产出结论的自信程度，低于阈值标 `[需复核]` |
| 覆盖率 | 85%-95% | 逐章摘要覆盖的章节占总章数的比例 |
| 重叠率 | <=35% | 相邻章摘要的信息重叠度，过高=摘要没区分度 |

覆盖率低于 85% = 有大量章节未被处理（拆文不完整）；高于 95% = 可能把残稿/番外也
算进去了（需剔除非正文）。重叠率高于 35% = 摘要太泛，没抓住每章的独特信息。

## 事实可溯源自检

设定/角色/报告里的硬事实（人名/地名/设定规则/事件因果）必须能 grep 回原文。

**自检方法**：从 Stage 4 的设定档案和 Stage 5 的汇总报告中随机抽取 10 条硬事实，
在 `对标/{书名}/原文/` 下全文搜索。找不到原文支撑的事实标 `[无据]`，需复核是模型
推测还是遗漏了搜索词。推测性结论必须标 `[推定]`，与 `import-book.md` 的推定标记
规则一致。

## 拆文纪律

- 拆的是「为什么有效」的结构，不是「写了什么」的内容——结构可学，内容不可抄。
- 绝不照搬人物名、地名、情节。拆文产出只供本书参考，不外传对标书原文。
- 七阶段不可跳步：Stage 3 的聚合依赖 Stage 2 的逐章摘要，跳过 Stage 2 直接聚合 =
  没有数据基础。
- 中断后必须从 `_progress.md` 恢复，不凭记忆续跑——进度状态以文件为准。
- 大型作品（>200 章）分批处理：首期 50 章 + 全书概要（Stage 0 已有），后续分批
  补跑 Stage 2-6，每批后更新 `_progress.md`。
