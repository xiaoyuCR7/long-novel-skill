# 导入旧稿深度逆向工程（import-deep）

`import-book.md` 是四阶段概述——定义了导入旧稿的骨架搭建、通读取样、反建档案、补登
大纲的骨架流程。本文件是**10 步执行细则**：把概述落地为可操作的阶段化管道，产出与
从头开书同等规格的完整书籍工程。

适用场景：作者带着已有书稿接手——别处写了几十章、断更多年的老书、或之前没用本 skill
工程化管理的作品。目标：把散稿变成标准书籍工程，接入单章循环。

## 与 import-book.md 的分工

| 维度 | `import-book.md` | 本文件 |
|---|---|---|
| 粒度 | 四阶段概述 | 三 Phase + 10 步执行细则 |
| 分析深度 | 通读取样 + 反建档案 | 调用拆文七阶段管道做深度分析 |
| 篇幅分流 | 不区分长短篇 | 篇幅分流判定 + 长篇/短篇分别走不同迁移路径 |
| 角色状态 | 以最后一章为快照点 | 反推算法从拆文产物推演，不重读原文 |
| 大型作品 | 提及分批但无细则 | 增量导入协议（>200 章） |

两者不互斥：`import-book.md` 是「做什么」的骨架，本文件是「怎么做」的执行手册。

## 核心原则

- 反建的一切信息先标 `[推定]`，经作者确认后才删标记——哪些是伏笔、哪些是人物真面目，
  只有原作者知道，猜错了就是埋雷。
- 不改原稿一个字。导入期只做「理解」和「建档」，修订是之后单独的事。
- 能从拆文产物推导的信息不重读原文——重读原文是最高成本操作，拆文产物已包含
  结构化摘要，应优先复用。

## Phase 1：确认导入源

**目标**：识别旧稿的篇幅、格式、完结状态，决定走长篇还是短篇迁移路径。

### 篇幅分流判定

| 总字数 | 分类 | 迁移路径 |
|---|---|---|
| < 3 万字 | 短篇 | Phase 3-S（4 步） |
| 3-30 万字 | 中篇 | Phase 3-L（10 步），卷划分简化为 1-2 卷 |
| > 30 万字 | 长篇 | Phase 3-L（10 步），完整卷划分 |

判定方法：统计 `原文/` 目录下所有文件的总字数。中文字数按字符计，不含标点和空格。

### 章节格式识别

扫描所有文件的文件名和正文首行，识别章节标记格式：

| 格式 | 识别特征 | 标准化目标 |
|---|---|---|
| 第X章 | 正文首行匹配「第\d+章」 | `第XXX章_{标题}.md`（三位补零） |
| Chapter X | 正文首行匹配「Chapter \d+」 | 同上，Chapter 转第X章 |
| 数字编号 | 文件名为纯数字 | 同上，数字转章号 |
| 无编号 | 无明显章节标记 | 按文件顺序自动编号 |

格式不统一的（混合多种格式）：先统一为「第X章」中文格式，再补零标准化。

### 最后一章是否残稿

检查最后一章的结尾状态：
- 有明确的收束（结局/完本感言/「全书完」标记）→ 完结稿，正常导入。
- 中断在某个场景中间（对话未结束/战斗未分胜负）→ 残稿，标 `[残稿]`，导入后从
  下一章续写时需先补完残章。
- 有「未完待续」但长期未更新 → 断更稿，按连载状态导入。

残稿判定写入 `参考资料/结构扫描报告.md`，提醒作者导入后优先处理残章。

**Phase 1 产出**：`参考资料/结构扫描报告.md`，含篇幅分类、章节数、格式识别结果、
残稿判定、各章字数分布。

## Phase 2：深度分析

**目标**：调用 `deconstruct-pipeline.md` 的拆文七阶段管道，对旧稿做深度拆解。

**执行**：
1. 把旧稿正文拷入 `对标/{书名}/原文/`（导入模式下，对标目录就是旧稿自身的分析目录）。
2. 启动拆文七阶段管道，从 Stage 0 开始自动执行。
3. 管道在 Stage 1 停靠点产出 `快速预览.md` 后，自动续跑 Stage 2-6。
4. 管道中断后从 `_progress.md` 恢复（详见 `deconstruct-pipeline.md` 的恢复机制）。

**与正常拆文的区别**：正常拆文拆的是别人的对标书，产出供学习参考；导入模式拆的是
自己的旧稿，产出直接迁移为本书工程的结构化资产。因此 Stage 4 的设定/角色档案不是
「学习参考」而是「直接可用」的工程文件。

**前置依赖检查**：Phase 2 启动前，检查 `对标/{书名}/剧情/节奏.md` 和
`对标/{书名}/剧情/情绪模块.md` 是否存在。这两个文件是 Stage 3 的权威索引产出，
后续迁移步骤依赖它们。如果拆文管道未跑到 Stage 3，这两个文件缺失，Phase 3 停止等待。

**缺失处理（fail-fast）**：

```
检查项: 对标/{书名}/剧情/节奏.md
状态: 缺失
动作: 停止 Phase 3，执行修复 → 重跑 deconstruct-pipeline Stage 2-3
修复命令: 参照 deconstruct-pipeline.md 的恢复机制，从 _progress.md 续跑

检查项: 对标/{书名}/剧情/情绪模块.md
状态: 缺失
动作: 同上
```

fail-fast 不继续执行后续步骤——缺了节奏索引和情绪模块就做结构迁移，等于盲迁，
产出的工程文件缺节奏参照，后续写作必踩坑。

## Phase 3-L：长篇结构迁移（10 步）

### Step 1：骨架建立

按 `assets/templates/book-structure.md` 创建书籍工程目录树：

```
{书名}/
├── 正文/
├── 设定/
│   ├── 角色/
│   └── ...
├── 大纲/
├── 追踪/
├── 对标/
└── 参考资料/
```

已有章节暂不入 `正文/`——Step 2 标准化后再拷入。

### Step 2：正文标准化

- 统一文件名格式：`第XXX章_{标题}.md`（三位补零，标题从正文首行提取或用「无题」）。
- 统一编码：全部转为 UTF-8（旧稿可能是 GBK/GB2312 编码）。
- 分章检查：一个文件含多章内容的，按章节标记拆分为独立文件。
- 拷入 `正文/`，保持原内容原顺序，不改一个字。

### Step 3：角色文件迁移

从 Phase 2 拆文产出的 `对标/{书名}/角色卡/` 提取角色卡，迁移到 `设定/角色/`：
- S/A 级角色：每个角色一个文件 `设定/角色/{角色名}.md`，从拆文角色卡迁移。
- B/C 级角色：合入 `设定/配角速查表.md`。
- 拿不准的设定标 `[推定]`（参照 `import-book.md` 的推定标记规则）。

### Step 4：关系文件迁移

从拆文产出的 `对标/{书名}/角色关系.md` 迁移到 `设定/角色关系.md`。关系演变时间线
保留——这是后续写作时查「这两个角色的关系在第几章发生了什么变化」的权威参考。

### Step 5：世界观同步

从拆文产出的 `对标/{书名}/设定/` 迁移到 `设定/` 目录：
- 世界观/力量体系/社会结构/地理/规则约束，按 `book-init.md` Step 2 的世界观模板
  格式化。
- 不完整的设定标 `[待补]`——旧稿作者可能没写全世界观，导入时只迁移已出现的设定。

### Step 6：大纲生成（卷划分用户确认制）

**模型建议卷边界**：从拆文产出的故事框架图（Stage 3 Step 1）和节奏分析
（`剧情/节奏.md`）提取卷边界建议——对标书的节奏曲线在哪些位置有明显转折，这些
转折点就是卷边界的候选位置。

**作者确认**：模型把卷边界建议列表交给作者：
```
卷边界建议：
  第1卷: 第1-45章 （理由：金手指亮相到第一次大高潮）
  第2卷: 第46-89章 （理由：地图切换+新势力介入）
  第3卷: 第90-120章 （理由：核心矛盾升级+中点反转）
  ...
请确认或调整卷边界。
```

作者确认后：
- 已写部分：总纲按「已发生的实际走向」反推填写（注明「追认版」）；已写区间不需要
  逐章补章纲，卷纲按单元补简版即可。
- 未写部分：从下一章起按正常流程出章纲。

### Step 7：追踪四文件按序生成

**按序生成**（顺序不可乱，后者依赖前者）：

1. **伏笔台账**（`追踪/伏笔台账.md`）：从拆文逐章摘要的关键信息表提取伏笔线索。
   已回收的进 ✅；没收的进 🟡 并标 `[疑似]`，回收窗口留空待作者填；分不清是伏笔还是
   闲笔的，列在台账末尾「待确认」区，问作者。
2. **时间线**（`追踪/时间线.md`）：从逐章摘要的时间标记提取。只记正文中明确出现的
   时间标记，不推测。
3. **角色状态**（`追踪/角色状态.md`）：用**角色状态反推算法**（见下文）从拆文产出
   推演角色当前状态。
4. **章节摘要**（`追踪/章节摘要.md`）：从拆文逐章摘要迁移，按本书的章节摘要模板
  （八字段）格式化。老章节「关键实体」字段务必填，这是日后检索的命根子。

### Step 8：题材定位

填写 `设定/题材定位.md`（题材/平台按作者当前打算填，不考古）。含主对标书：
- 如果旧稿本身就是对标书的同人/仿写，标注原对标书。
- 如果旧稿有明确的题材参照，标注参照书。
- 无明确对标的，从拆文产出的桥段标签（Stage 3 Step 9）反推题材分类。

### Step 9：对标结构化资产同步

如果作者有额外的对标书（非旧稿自身），用 `deconstruct-pipeline.md` 拆解对标书，
产出的结构化资产存入 `对标/{对标书名}/`。旧稿自身的拆文产物保留在
`对标/{书名}/`（自分析目录），与外部对标书目录并列。

### Step 10：文风同步

从拆文 Stage 6 产出的 `对标/{书名}/文风.md` 提取文风锚，写入 `设定/文风锚.md`：
- 用 `style_fingerprint.py extract` 跑旧稿前 3-5 章的六维量化基线。
- 从 `文风.md` 的分层模仿建议提取「基础层必学」项，作为续写的文风校准基准。
- 样板段落从 `文风.md` 的原文锚点片段中选取 3-5 段，填入 `设定/文风锚.md`。

前 3-5 章续写时用 `scripts/check_text.py --style-stats` 量化校准，保证续写不变味。

## Phase 3-S：短篇结构迁移（4 步）

短篇（< 3 万字）不需要完整的 10 步迁移，走简化 4 步：

1. **骨架建立**：创建短篇工程目录（`正文/` + `设定/` + `参考资料/`）。
2. **正文标准化**：统一文件名和编码，拷入 `正文/`。
3. **设定提取**：从 Phase 2 拆文产出提取核心框架（情绪目标/反转/人设），评估是否
   补写为五段式结构。角色提取为角色卡。
4. **文风锚**：用 `style_fingerprint.py extract` 提取文风六维基线，写入
   `设定/文风锚.md`。

短篇不需要卷划分、追踪四文件、对标资产同步——短篇的伏笔/时间线/角色状态简单到
不需要独立文件管理。

## 角色状态反推算法

**核心思路**：从拆文产出的角色档案 + 章节摘要反推角色状态，不重读原文。重读原文是
最高成本操作，拆文产物已包含结构化信息，应优先复用。

**算法步骤**：

1. **取角色档案基线**：从 `对标/{书名}/角色卡/{角色名}.md` 取角色的初始状态
  （身份/能力/关系/心理），作为反推起点。
2. **扫描章节摘要的事件链**：从 `对标/{书名}/剧情/逐章摘要/` 逐章扫描该角色参与
   的事件，提取状态变更点（升级/受伤/关系变化/获得/失去）。
3. **叠加状态变更**：按时间顺序叠加每个变更点到基线状态上，推演到最后一章。
4. **取最后一章快照**：反推出的最终状态写入 `追踪/角色状态.md`，标注
   「截至第 N 章」。
5. **标推定**：反推出的状态中标 `[推定]`——拆文摘要可能遗漏细节，反推结果需作者
   确认后才删标记。

**算法限制**：拆文摘要的情节点密度是 150-200 字/个，不可能覆盖原文所有细节。反推
出的状态是「主线变更」的叠加，细微的状态变化（如心理渐变）可能遗漏。因此反推结果
必须标 `[推定]`，作者会签时重点复核。

## 大型作品增量导入（>200 章）

**问题**：200+ 章的旧稿全文通读和拆文耗时极长，一次性导入不现实。

**增量导入协议**：

1. **首期导入**：前 50 章 + 全书概要。
   - 跑 Phase 1（确认导入源，全书范围）。
   - 跑 Phase 2（拆文管道），首期只处理前 50 章，全书概要从 Stage 0 的 200 字概要
     获取。
   - 跑 Phase 3-L 的 Step 1-7（骨架/正文/角色/关系/世界观/大纲/追踪），基于前 50 章
     的拆文产物。
   - 标注「首期导入完成，后续待补」。

2. **后续分批导入**：每批 50 章。
   - 跑拆文管道 Stage 2-3，处理该批章节。
   - 更新追踪四文件（追加该批的伏笔/时间线/角色状态/章节摘要）。
   - 更新 `_progress.md`。
   - 每批后跑 `validate_tracking.py` 复核格式合规。

3. **全书完成**：所有章节导入完成后，重跑 Stage 3 聚合分析（全书范围的剧情聚合/
   角色合并/情绪节奏曲线），更新 `剧情/节奏.md` 和 `剧情/情绪模块.md`。

增量导入期间，已导入的章节可以正常进入单章循环写作——追踪文件虽不完整但有覆盖，
够用。未导入的章节不影响续写（续写从最后一章往后写，不依赖未导入的前文细节）。

## 作者会签

Phase 3 完成后，把所有 `[推定]`/`[疑似]`/`[待补]` 清单一次性给作者过：
- 确认 → 删标记。
- 修正 → 改内容后删标记。
- 删除 → 从文件中移除该条目。

会签完，工程正式生效。下一章起走标准单章循环（`chapter-loop.md`）。

| Step 1 建骨架 | Phase 1 + Phase 3-L Step 1-2 |

| Step 3 反建档案 | Phase 3-L Step 3-7 |
| Step 4 补登记大纲 | Phase 3-L Step 6 |

本文件是 `import-book.md` 的展开执行版，不替代它——`import-book.md` 的原则和纪律
（推定标记/不改原稿/会签制度）在本文件中全程遵守。
