# 拆文产出结构化分目录规范（deconstruct-output-spec）

拆文产出不是一堆文件散落在目录里——是分角色/剧情/设定/章节/文风的**结构化资产树**。
每个文件有固定格式、固定用途、固定消费阶段。本文档定义拆文产出的完整目录结构、
各文件的内容规范、写作阶段的消费规则，以及与 `deconstruct.py` 的集成升级方案。

与 `deconstruct.md`（轻量四维统计）和 `deconstruct-pipeline.md`（七阶段深度拆解）
的关系：本文档是**产出规格层**——定义「拆完之后产出的文件长什么样、放在哪里、
怎么用」。`deconstruct.md` 和 `deconstruct-pipeline.md` 是**流程层**——定义「怎么拆」。

## 1. 产出目录结构

```
对标/{书名}/
├── 拆文报告.md                # 五维评分 + 爽点密度 + 可借鉴套路（总入口）
├── 文风.md                    # 整书级文风视图（详见 craft/style-profile.md 协议）
├── 文风指纹.json              # 六维量化指纹（供 style_fingerprint.py 消费）
├── 角色/
│   ├── {角色名}.md            # S/A 级角色档案卡
│   └── 角色关系.md            # 关系网络 + 关系演变时间线
├── 剧情/
│   ├── 故事线.md              # 框架识别 + 主线/副线/暗线
│   ├── 节奏.md                # 快/中/慢档分布 + 关键信息递进 + 情绪爆发节律
│   ├── 情绪模块.md            # 读者需求 + 情绪引擎 + 可复用模块卡
│   ├── 逐章摘要/              # Stage 2 逐章摘要（每章一个文件）
│   │   ├── 第001章.md
│   │   ├── 第002章.md
│   │   └── ...
│   └── {剧情单元名}.md        # 按桥段标签聚合的剧情单元（可选）
├── 设定/
│   ├── 世界观/
│   │   ├── 背景设定.md        # 时代/背景/社会结构/地理
│   │   ├── 力量体系.md        # 战力/修炼/异能/规则约束
│   │   └── 金手指.md          # 主角核心外挂/天赋/系统
│   └── 势力/
│       ├── {势力名}.md        # 各大势力档案
│       └── ...
├── 章节/
│   ├── 第001章_摘要.md         # 每章一句话摘要（索引用）
│   ├── 第001章_深度拆解.md     # 黄金三章逐章深度分析
│   ├── 第002章_摘要.md
│   ├── 第002章_深度拆解.md
│   ├── 第003章_摘要.md
│   ├── 第003章_深度拆解.md
│   └── ...
├── 快速预览.md                # 停靠产出（Stage 1，前三章快速参考）
├── 写法技巧清单.md             # 一笔两用/延迟揭示等写法技法清单（Stage 5）
├── 原文/                      # 原始文本（输入，只读）
│   ├── 第001章.md
│   └── ...
├── _progress.md               # 管道进度中枢（详见 deconstruct-pipeline.md）
└── _meta.json                 # 结构计数元数据（供工具脚本消费）
```

### 目录设计原则

- **扁平优于嵌套**：角色/剧情/设定/章节四大分目录，每层最多两层深度。
- **文件名可排序**：章节文件用零填充编号（第001章），保证 `ls` / glob 顺序正确。
- **入口文件唯一**：`拆文报告.md` 是总入口，写章纲前只读这一个文件即可快速对齐。
- **与 pipeline 一致**：目录结构与 `deconstruct-pipeline.md` 七阶段产出对齐，
  Stage 0 产出 `_progress.md`，Stage 1 产出 `快速预览.md`，以此类推。

## 2. 各产出文件的内容规范

### 2.1 拆文报告.md（总入口）

拆文报告是对标书的「一页纸总结」——写作时第一个读的文件，5 分钟内获得对标书的
核心特征。硬上限 ~2000 字。

```markdown
# 拆文报告（{书名}）

## 五维评分

| 维度 | 分数(1-10) | 一句话点评 |
|---|---|---|
| 情节 | {分} | {点评} |
| 人物 | {分} | {点评} |
| 节奏 | {分} | {点评} |
| 文笔 | {分} | {点评} |
| 爽感 | {分} | {点评} |

> 评分依据：与同平台同题材头部作品对比。7分=及格线，8分=优秀，9分=标杆。

## 爽点密度

- 全书平均：{X} 个爽点/万字
- 快档章节：{Y} 个爽点/万字
- 慢档章节：{Z} 个爽点/万字
- 高潮章峰值：{N} 个爽点/万字

## 可借鉴套路（Top 3-5）

1. {套路名}：{一句话说明骨架 + 适用场景 + 怎么用在本书}
2. ...

## 读者画像推断

- 核心读者：{谁在看这本书，为什么看}
- 核心需求：{读者看这本书满足什么需求——爽/虐/悬念/甜}
- 平台适配：{这本书的节奏和体量适合哪个平台}

## 适合对标的本书场景

- 开书节奏参考：{对标书前10章的节奏特征，适合模仿到本书的什么阶段}
- 卷级结构参考：{对标书的卷级规划，适合参考到本书的什么位置}
- 不适合参考的维度：{本书与对标书不同的地方，不要盲目对标}
```

### 2.2 文风.md

整书级文风视图，格式遵循 `craft/style-profile.md` 的产物结构协议。硬上限 ~4000 字。

关键内容项（完整结构见 `craft/style-profile.md`）：

- **元数据**：数据样本量、confidence 等级（high/med/low）、覆盖章节范围
- **整体语感**：句长分布（平均/中位/最长/最短 + 短句/中句/长句占比）、对话占比、
  段落中位长度、标点节奏（？！……各自频率）、高频词 Top20、句式偏好
- **对话技法**：潜台词模式 / 对话标签习惯 / 角色语气区分度
- **情绪交替模式**：章内基调切换频率 / 跨章基调周期 / 喜剧与重击的转场手法
- **可借鉴技巧 Top5**：每条配技法描述 + 原文位置 + 效果机制 + 迁移用法
- **可借鉴套路 Top3**：每条配结构描述 + 适用场景 + 原文位置 + 迁移注意
- **分层模仿建议**：基础层（句式/标点/对话标签）/ 进阶层（叙事手法/情绪交替）/
  适配层（本书题材化调整）
- **原文锚点片段**：4-6 段，每段 300-500 字，标注片段类型与锚点说明

### 2.4 角色/{角色名}.md

```markdown
## 基本信息
- 姓名：{全名/别名}
- 身份：{社会身份/职位}
- 年龄：{出场时年龄或年龄区间}
- 外貌特征：{2-3句，只记有辨识度的特征}

## 性格标签
- {标签1}：{一句话说明}
- {标签2}：{一句话说明}
- {标签3}：{一句话说明}
- {标签4}：{一句话说明}
- {标签5}：{一句话说明}

## 动机链
- 核心动机：{这个角色最根本的欲望是什么}

## 语言风格
```

### 2.9 剧情/逐章摘要/第XXX章.md

```markdown

## 关键信息投放
| 信息 | 类型 | 投放方式 |
|---|---|---|
| {信息内容} | 设定/角色/线索/规则 | 直接告知/间接暗示/伏笔 |
| ... | | |

## 扩写技法
- {本章用了什么扩写手法}
- {触发场景：什么情况下用这个手法}
- {执行方式：具体怎么做的}
```

**密度标准**：情节点 150-200 字/个。2000 字章 10-15 个，3000 字章 15-25 个，
4000+ 字章 25-40 个。

### 2.10 章节/第N章_摘要.md

每章一句话摘要，供索引和快速扫描用。不需要打开逐章摘要文件就能知道每章写了什么。

```markdown
| 章节 | 一句话摘要 | 档位 | 核心事件 |
|---|---|---|---|
| 第001章 | {一句话} | 快 | {核心事件} |
| 第002章 | {一句话} | 中 | {核心事件} |
| ... | | | |
```

多个章节的摘要可以合在一个文件里（按卷或按 50 章分批），也可以每章一个文件。
推荐按卷合批——索引文件太大不好检索，太小又太碎。

## 3. 拆文产出消费规则

拆文产出的使用遵循**最小上下文原则**——按需召回，不全量读取。不同写作阶段召回不同文件：

### 3.1 开书阶段

**目标**：确定本书的节奏基准和文风方向。

**读取**：
- `拆文报告.md`（必读）— 五维评分 + 爽点密度 + 可借鉴套路，5 分钟快速对齐
- `文风.md` 中的「整体语感」和「分层模仿建议」（必读）— 确定文风基准线

**可选读取**：
- `文风.md` 中的「原文锚点片段」（需要具体文风参考时）
- 多本对标书的 `拆文报告.md` 对比选主对标

### 3.2 做大纲阶段

**目标**：规划本书的卷级结构、情绪节奏、情绪模块。

**读取**：
- `剧情/故事线.md`（必读）— 学习对标书的故事框架识别和分阶段手法
- `剧情/节奏.md`（必读）— 学习档位分布、大节点间隔、铺垫-结算比
- `剧情/情绪模块.md`（必读）— 匹配适合本书题材的情绪模块

**可选读取**：
- `设定/` 目录下的文件（需要世界观结构参考时）
- `_meta.json`（需要量化数据做跨书对比时）

### 3.3 写正文阶段

**目标**：每章写完校准文风，防止逐章漂移。

**读取**：
- `文风.md`（仅主对标）— 按需召回对应部分（写对话读对话技法，写高潮读情绪高潮锚点）
- `文风指纹.json`（仅主对标）— 供 `style_fingerprint.py compare` 自动校准

**校准频率**：每 5-10 章校准一次，用脚本对比新章指纹与主对标指纹。
偏离容差回调，容差内正常。

### 3.4 写角色阶段

**目标**：设计角色功能位、动机链、语言风格。

**读取**：
- `角色/` 目录下对应角色卡 — 学习功能定位、动机链设计、语言区分度
- `角色/角色关系.md` — 学习关系网络设计和张力结构

**可选读取**：
- 对标书的 `剧情/情绪模块.md` — 理解角色在情绪模块中的功能

### 3.5 消费规则纪律

- **主对标 vs 副对标**：开书时选 1 本主对标（文风和节奏全面参照），1-2 本副对标
  （仅参考特定维度）。正文写作阶段只召回主对标的文风文件，避免多本混读导致
  文风混乱。
- **按需召回**：写什么读什么，不全量读取。写对话只读对话技法，不读世界观设定。
- **先读摘要后读原文锚点**：先读拆文报告和故事线获得整体认知，再按需深入到锚点片段。
  反过来 = 先见树后见林，效率低。
- **多本对比读报告不读细节**：对比多本对标书时，只读各自的 `拆文报告.md`，不深入子文件。
  细节是每本书单独参考的。

## 4. 与 deconstruct.py 的集成

当前 `deconstruct.py` 产出为扁平结构（量化统计/结构分析/节奏分析/文风指纹各一个文件），
需要升级为分目录结构化产出，与 `deconstruct-pipeline.md` 七阶段管道对齐。

### 4.1 当前产出 vs 目标产出

| 当前子命令 | 当前产出 | 目标产出路径 | 升级动作 |
|---|---|---|---|
| `stats` | `量化统计.md` | `拆文报告.md` + `_meta.json` | 合并到报告，量化数据写入 _meta |
| `structure` | `结构分析.md` | `章节/第N章_摘要.md` + `_meta.json` | 逐章产出，结构计数写入 _meta |
| `rhythm` | `节奏分析.md` | `剧情/节奏.md` + `_meta.json` | 档位分布写入 _meta |
| `fingerprint` | `文风指纹.md` | `文风指纹.json` + `文风.md` | 新增 JSON 输出格式，MD 产出遵循 style-profile 协议 |

### 4.2 升级方案

#### 新增子命令：`init`

`python scripts/deconstruct.py init "对标/{书名}" --title "{书名}"`

功能：创建分目录结构。

```bash
# 自动创建以下目录和占位文件
对标/{书名}/
├── 角色/
├── 剧情/逐章摘要/
├── 设定/世界观/
├── 设定/势力/
├── 章节/
├── 原文/
├── _progress.md          # 初始化进度文件
└── _meta.json            # 初始化元数据（仅有 schema_version 和 book_title）
```

#### 新增子命令：`meta`

`python scripts/deconstruct.py meta "对标/{书名}" --output "对标/{书名}/_meta.json"`

功能：聚合所有已有分析结果，生成/更新 `_meta.json`。从 `stats`/`structure`/
`rhythm` 的中间数据中提取结构计数、五维评分、档位分布、角色分级等，写入 JSON。

#### 新增子命令：`fingerprint-json`

`python scripts/deconstruct.py fingerprint-json "对标/{书名}/原文/第1章.md" ... \
  --output "对标/{书名}/文风指纹.json"`

功能：在现有 `fingerprint` 子命令基础上，额外输出 JSON 格式的文风指纹，
供 `style_fingerprint.py compare` 直接消费。

#### 修改现有子命令的默认输出路径

- `stats --output` 默认写入 `对标/{书名}/拆文报告.md`（而非独立的 `量化统计.md`）
- `structure --output` 默认逐章写入 `对标/{书名}/章节/第N章_摘要.md`
- `rhythm --output` 默认写入 `对标/{书名}/剧情/节奏.md`
- `fingerprint --output` 默认写入 `对标/{书名}/文风.md`（Markdown 格式），
  `fingerprint-json --output` 写入 `对标/{书名}/文风指纹.json`（JSON 格式）

#### 保持向后兼容

现有用法 `python scripts/deconstruct.py stats ch1.md ch2.md --output "量化统计.md"`
仍然有效——`--output` 参数指定路径时不改变行为。只有在使用 `init` 初始化后的
分目录结构下，才自动路由到规范化路径。

### 4.3 与七阶段管道的衔接

`deconstruct.py` 负责机器确定性统计（Stage 2 量化 + Stage 6 文风量化），模型推理部分
（Stage 0 概要、Stage 1 黄金三章深度拆解、Stage 3 聚合分析、Stage 4 设定档案、
Stage 5 写法技巧）由模型执行，产出直接写入规范化目录。

```
Stage 0:  模型 → _progress.md（章节边界表）
Stage 1:  模型 → 快速预览.md + 章节/第1-3章_深度拆解.md
Stage 2:  模型 → 剧情/逐章摘要/第N章.md
          脚本 → 剧情/节奏.md（档位分布）+ _meta.json（结构计数）
Stage 3:  模型 → 剧情/故事线.md + 剧情/情绪模块.md（聚合更新节奏.md）
Stage 4:  模型 → 角色/ + 设定/（设定档案与角色档案）
Stage 5:  模型 → 写法技巧清单.md + 拆文报告.md（汇总五维评分）
Stage 6:  脚本 → 文风指纹.json + 文风.md（六维量化）
          模型 → 文风.md（对话技法/情绪交替/锚点片段）
```

### 4.4 脚本修改优先级

| 优先级 | 修改 | 理由 |
|---|---|---|
| P0 | 新增 `init` 子命令 | 没有目录结构就无法分目录产出 |
| P0 | `fingerprint` 支持 JSON 输出 | `style_fingerprint.py compare` 需要机器可读格式 |
| P1 | `stats` 产出集成到拆文报告 | 消除冗余文件 |
| P1 | `structure` 逐章产出 | 与 pipeline Stage 2 逐章摘要对齐 |
| P1 | 新增 `meta` 子命令 | `_meta.json` 是工具消费的核心 |
| P2 | `rhythm` 输出路径规范化 | 低风险改进 |
| P2 | 默认路径自动路由 | 向后兼容基础上提供便利 |

## 拆文产出纪律

- 拆的是「为什么有效」的结构，不是「写了什么」的内容——结构可学，内容不可抄。
- 绝不照搬人物名、地名、情节。产出只供本书参考，不外传对标书原文。
- 每个文件有硬上限：`拆文报告.md` ~2000 字，`文风.md` ~4000 字，角色卡 ~800 字，
  逐章摘要按密度标准。超限 = 检索成本过高，写作时懒得读。
- `_meta.json` 在每次拆文阶段完成后更新，保持数据与产出文件同步。
- 中断后从 `_progress.md` 恢复，不凭记忆续跑——进度状态以文件为准。
