# 任务路由与上下文装配

当一次请求混合多个动作、项目状态不明确或某个依赖不可用时使用本文件。路由只决定“下一段
工作读什么、在哪里停”，不替作者扩展任务授权。

## 路由优先级

始终按以下顺序判定：

1. **用户明确动作**：如“只做卷纲”“诊断但别改”“直接续写第 38 章”。
2. **项目状态**：是否已有书籍目录、锁定大纲、未清欠账、未通过门禁、待确认冲突。
3. **关键词**：只在前两项不能确定时辅助路由；“卡文”不自动等于重写大纲。

若用户请求与项目状态冲突，先处理会破坏 canonical state 的阻塞项，再继续获授权的动作。

## 路由表

| Intent | 最小上下文包 | 路由 | 默认停止点 |
|---|---|---|---|
| 开书/规划 | 已知定位、事实与授权边界；缺项按动作判定 | `book-init.md`；允许排纲时再读 `outline-system.md` | 交付获授权提案与待定项；只聊设定不排纲，未授权不锁纲/写正文 |
| 补纲/改纲 | 当前总纲/卷纲/章纲、已写区间、作者授权范围 | `outline-system.md` → 下述改纲协议 | 影响与未写纲确认后停止，不默认修正文或开写 |
| 写章/续写 | 章纲、前章、出场人物最新状态、未结伏笔与时间线 | `chapter-loop.md` + `scene-rendering.md` | 章事务提交并报告 |
| 修订/去 AI 味 | 待修正文、作者意图、适用文风权威、明确问题 | `revision.md` + `anti-ai-style.md` | 只修授权范围，不新编剧情 |
| 中断恢复 | 最后正文、追踪五文件、门禁状态 | `resume.py`；失败则人工核对 | 给出可恢复 checkpoint |
| 导入旧稿 | 原稿、作者指定的 canonical 范围 | `import-book.md`；复杂项目加 `import-deep.md` | 反推结果经作者确认 |
| 审核/诊断 | 被审文本与适用标准 | `quality-checklist.md`；需要独立视角加 `cross-review.md` | 报告问题，不自动改稿 |
| 拆文/仿写 | 合法可用样本、分析目标 | `deconstruct-pipeline.md` → `imitation.md` | 先交结构/风格协议 |
| 市场/调研 | 平台、题材、时间范围、证据要求 | `market-scan.md` 或 `research.md` | 区分已核验事实与推断 |
| 短篇 | 平台字数、核心事件、结尾目标 | `short-story-loop.md` | 完整短篇或指定阶段 |
| 发布 | 成稿、平台、元数据和用户授权 | `platform-guide.md` | 发布前检查点；外部提交需明确授权 |
| Dashboard 工作台/编辑 | 活动书籍目录、待编辑文件、当前 revision | `dashboard-workbench.md` | 只打开/修改用户指定范围，冲突时保留草稿并停靠 |

表中的文件位于 `references/workflow/`、`references/craft/` 或 `references/platforms/`；脚本在 `scripts/`。

### 开书的局部前提

按 `book-init.md` Step 0 区分讨论、设计、排产、锁纲/正文和发布。允许规划时交付有依据的
定位、读者契约、核心设定、总纲、首卷与首批章纲；默认 5–10 章，用户指定批量优先，
均标为提案未锁定。缺书名、日更、样章或对标不阻断这些提案；临时目录名不是正式书名。
缺关键定位或事实冲突只暂停依赖部分，给出问题并继续其余安全交付，不编造已确认值。
作者明确只聊设定/禁止排纲时不进大纲流程；保留终局不代定，写正文和发布分别需要授权。
发布资料只在发布前核对；对标不可访问就明确未分析，benchmark 不升级为开书必需门禁。

## 外稿恢复分流

`resume.py` 的 `project_state` 区分 `native`、`external`、`empty`、`unknown` 与
`transaction_incomplete`。未完事务优先 recover；`external`/`unknown` 只列候选和缺口，
不得把“没找到标准正文”解释成空书。只有确认 `empty` 才建议准备第1章，仍不代表获准写作。

外稿先读作者指定的实际源文件，确认版本、停笔位置、已有事实与续写授权；多版本不能按修改
时间猜 canonical。作者只授权片段续写且已给足事件时，保留原文件，另交续写候选即可，
不强迫整书导入，也不声称已经完成原生章事务。长篇新章节仍须满足章纲与篇幅授权。
只有作者明确要求导入，才走 `import-book.md`；源文件备份和聊天字符串落盘分别使用该文档的
`source_materialize.py` 两种入口，报告实际字节数和 SHA-256，不把文字相似当作字节一致。
需证明“先备份后编辑”时，在备份命令成功返回后、编辑前记录目标状态（新目标仍不存在；
旧目标仍为原始哈希），随后编辑并读回校验。只有最终备份/成稿哈希不足以证明先后顺序。
保留工具实际响应；原生编辑没有子进程 stdout/退出码时明确标为不适用，不伪造执行日志。

## 补纲/改纲专属协议

先读 `outline-system.md`，区分滚动补未写章与重大改线。不得把“改纲”送进正文去 AI 味流程。
默认停在变更方案与影响清单；作者已授权实施时按以下顺序做，任何一步失败即停，不继续 rebuild：

1. **backup**：为将改变的大纲、锚点、人物/伏笔追踪与索引逐项保存带版本的可恢复副本；记录
   原文件与副本路径。`novel_flow.py` 的旧追踪快照不包含大纲，不能冒充完整改纲备份。
2. **impact / cascade**：先分析受影响实体，人工复核已写区间不可回改及未写纲承接；确认后才改纲
   并级联标记受影响节点。没有图谱时逐项人工追溯并报告降级，不伪造分析完成。
3. **anchor success**：更新受影响锚点/配额，运行 check 与 inject，确认成功再推进。已有锚点不得
   用 init 重置；check 失败则回到备份/变更方案，不重建索引掩盖错误。
4. **rebuild**：从已确认的新摘要/追踪重建实体索引，复核图谱与新大纲一致，报告改动及未决项。

```bash
python scripts/story_graph.py impact "{book}" "{受影响实体}"
python scripts/story_graph.py cascade "{book}" --from-chapter {N} --desc "{已授权改纲说明}"
python scripts/outline_anchor.py check "{book}" --chapter {N}
python scripts/outline_anchor.py inject "{book}" --chapter {N}
python scripts/entity_index.py build "{book}"
```

上述命令需逐条核验退出码；不是一次性盲执行脚本。补纲/改纲完成后停止，除非作者同时授权写章。

## 多意图拆解

把组合请求拆为有依赖顺序的短事务，而不是同时展开所有参考资料：

1. 列出用户明确要求的交付物。
2. 标记每项的前置状态与停止点。
3. 先执行能产出后续权威来源的事务，例如先锁章纲再写章。
4. 每个事务只装配自己的最小上下文包；已读取但与当前决策无关的资料不得强行影响结果。
5. 遇到需要作者选择的分支即停；已有明确授权时可连续执行到下一个停止点。

示例：“导入旧稿并续写两章”应先完成导入和状态反推，作者确认 canonical state 后，再逐章执行
两个独立章事务。不得一边猜角色状态一边续写。

## 上下文装配

### Required

缺失即会让当前动作不安全或不可判定。写长篇章节固定需要：当前章纲、前章正文或可靠摘要、
出场人物最新状态、相关未结伏笔与时间线硬约束。缺失时输出 `required_context_missing`，包含
路径、影响和具体修复动作。

### Conditional

题材卡、文风锚、对标节选、图谱邻域、RAG 命中、市场证据与研究材料只在当前意图确实用到时
加载。缺失时说明影响并回退：

- RAG/图谱不可用：按实体索引、摘要和关键词人工定位，说明检索范围。
- 对标材料不可用：保留作者文风与项目事实，不阻断无关情节。
- 联网不可用：只陈述本地证据，将时效性结论标为未核验。
- 题材卡未匹配：使用通用工艺并记录回退，不伪造专属规则。

可选依赖绝不能变成所有章节的固定门槛。

## 权威冲突

权威顺序：用户本轮明确决定 > 已发生正文 > 最新追踪状态 > 锁定大纲 > 设定 > 题材卡 >
对标材料 > 通用建议。

例：旧人物卡写“林辰佩剑”，最新正文明确写剑已遗失。续写时以已发生正文为准，在报告中标出
人物卡过期，并把最新状态写回追踪；不得因为人物卡字段更整齐就让剑自动出现。若用户本轮明确
决定找回剑，还必须通过新的已授权事件实现，不能回改既成事实。

## 失败与停止

- 大纲缺失：`outline_missing`，列出最小章纲字段。
- 大纲预算不足：`outline_underfilled` + 具体 `missing_beat_budget`；等待补纲或缩短篇幅。
- 状态矛盾且权威不足以裁决：`state_conflict`，给出候选解释与影响。
- 工具失败：`tool_unavailable`，说明未运行的能力和实际回退，不虚报成功。
- 门禁两轮修复后仍失败：`gate_blocked`，保留上个 checkpoint，交给作者决定。
- 只收到诊断授权：交付诊断后停止，不把“发现问题”等同于“获准修改”。

## 常见错误

| 错误 | 修正 |
|---|---|
| 看到多个关键词就一次读完所有 references | 先定 intent，只加载当前事务的 required 与 conditional 来源 |
| 把聊天里记得的内容当项目事实 | 读文件；读不到就报告缺失 |
| 为了满足字数替大纲发明反派、反转或支线 | 返回 `outline_underfilled` 与缺口预算 |
| 对标样本覆盖作者文风 | 作者明确文风更高权威；对标只作次级结构参考 |
| 可选脚本失败便阻断全部写作 | 采用明确的人工回退，只阻断确实依赖它的动作 |
| 完成正文后把追踪留到下一章 | 章事务未完成，回到 checkpoint，不开始下一章 |
