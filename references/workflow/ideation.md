# 交互式脑洞引导（ideation）

从模糊的「想写本书」到可进入 `book-init.md` 的创意种子，五轮收敛完成。每轮只做一件事，
不跳步；作者随时可回退到上一轮重选。产出 `设定/idea_seed.md`（创意种子）+
`设定/题材定位.md`（题材定位），衔接 `book-init.md` 正式开书。

## 何时用这个

- 作者说「帮我开个脑洞」「想个题材」「不知道写什么」「有什么好写的」。
- 作者有模糊意向但没成形（「想写本都市的」「最近想写点爽的」），给了 1–3 个灵感碎片。
- 作者刚扫完榜（`market-scan.md`），拿到报告但还没决定写什么。

不适用：作者已有一句话卖点 / 确定题材 / 确定人设 → 直接进 `book-init.md` Step 0，
不走走脑洞流程。

## 与现有文档的关系

| 文档 | 管什么 | 与本文档的关系 |
|---|---|---|
| `market-scan.md` | 扫榜、找市场缝隙 | 扫榜报告可选作为轮次1输入 |
| `book-init.md` | 开书全流程 | 脑洞产出 idea_seed.md 后进入此流程 |
| `references/craft/commercial-core.md` | 商业核心方法（卖点/金手指/崩盘） | 压力测试轮引用其崩盘原因检查 |
| `references/genres/INDEX.md` | 题材卡索引 | 定稿轮用其匹配题材卡 |

## 收敛原则

1. **每轮只做一件事**：发散→聚焦→深化→压力测试→定稿，五件事分五轮做，不合并。
2. **不跳步**：每轮的产出是下一轮的输入。跳过某轮 = 后续轮次缺乏根基。
3. **可回退**：作者随时可以说「上一轮选错了，改一下」→ 回退一轮重做。同一次脑洞最多
   回退 2 次（回退超过 2 次说明需求太模糊，建议先扫榜或先读对标书）。
4. **模型不替作者做决定**：每轮模型给选项和分析，选择权在作者。定稿轮的产出是综合
   作者选择的汇聚，不是模型自作主张的方案。
5. **五轮内必须收敛**：第 5 轮结束时必须产出可进入开书流程的创意种子。收敛不了 =
   作者需求太模糊，建议先扫榜或先拆 2–3 本对标书找感觉。

## 五轮收敛流程

### 轮次1：发散轮

**目标**：作者给出题材方向 + 1–3 个灵感碎片，模型扩展为 10 个切入点候选。

**输入格式**（作者提供）：

```
题材方向：{男频/女频/不限} × {仙侠/都市/科幻/悬疑/言情/...}
灵感碎片（1–3 个）：
  1. {一句话描述，如「主角能听到物品的心声」}
  2. {一句话描述}
  3. {一句话描述，可选}
目标平台（可选）：{番茄/起点/晋江/知乎盐选}
```

**模型动作**：
1. 读灵感碎片，提取每个碎片的核心意象。
2. 对每个意象做 3–4 个维度的变体（换身份/换场景/换金手指形式/换目标读者）。
3. 合并去重，输出 10 个切入点候选，每个含一句话定位 + 差异化标签。

**Prompt 模板**（模型内部使用）：

```
你是网文选题顾问。作者给了以下灵感碎片：
{作者输入}

任务：把每个碎片扩展为 3–4 个切入点变体，合并输出 10 个候选。
每个候选格式：
  [编号] {一句话定位} | 差异化：{与同类热门书的不同} | 平台适配：{番茄/起点/晋江}
变体维度：换身份（主角是谁）/换场景（在哪发生）/换金手指形式/换目标读者。
不要重复，10 个候选必须各有不同的核心钩子。
```

**产出格式**（输出给作者）：

```
基于你的灵感碎片，我扩展了 10 个切入点：

[1] {一句话定位} | 差异化：{} | 平台：{}
[2] {一句话定位} | 差异化：{} | 平台：{}
...
[10] {一句话定位} | 差异化：{} | 平台：{}

从中选 2–3 个你感兴趣的，进入下一轮聚焦。
```

**收敛判定**：作者选了 2–3 个 → 进轮次2。作者「都不感兴趣」→ 换角度重出 10 个（算一次回退）。

### 轮次2：聚焦轮

**目标**：作者选了 2–3 个切入点，模型为每个构建「核心冲突 + 情绪目标 + 目标读者画像」。

**输入**：轮次1选定的 2–3 个切入点编号。

**模型动作**：
1. 对每个选定的切入点，设计核心冲突（主角想要什么 × 谁阻碍 × 为什么阻碍不了别人只阻碍他）。
2. 定义情绪目标（读者读完应该感到爽/虐/甜/燃/悬，具体到情绪类型）。
3. 描绘目标读者画像（年龄段/阅读偏好/追读习惯/弃书雷区）。
4. 评估每个切入点的长篇潜力（能否撑 50 万字以上）。

**Prompt 模板**：

```
你是网文策划。对以下切入点分别构建三件套：
{选定的切入点列表}

每个切入点输出：
  核心冲突：主角想要{X}，{谁}阻碍，因为{为什么是他}
  情绪目标：读者应该感到{爽/虐/甜/燃/悬}，具体是{什么感觉}
  目标读者：{年龄/性别/阅读习惯/追读偏好/弃书雷区}
  长篇潜力：{能撑多少字，分几个阶段}
```

**产出格式**：

```
为每个切入点构建了三件套：

◆ 切入点 [N]：{一句话定位}
  核心冲突：主角想要{X}，{谁}阻碍，因为{为什么是他}
  情绪目标：{情绪类型} —— 读者应该感到{具体感觉}
  目标读者：{画像}
  长篇潜力：{字数预估 + 阶段划分}

◆ 切入点 [M]：{...}
  ...

从中选 1 个进入下一轮深化。
```

**收敛判定**：作者选了 1 个 → 进轮次3。作者「想要 N+M 的结合」→ 允许合并，但合并后核心
冲突不能自相矛盾（两个冲突拉不同方向 = 这本书精神分裂）。

### 轮次3：深化轮

**目标**：作者选了 1 个切入点，模型深化为「一句话梗概 + 主角人设速写 + 金手指设计 + 核心矛盾」。

**输入**：轮次2选定的切入点编号。

**模型动作**：
1. 写一句话梗概（主角是谁 × 核心矛盾 × 金手指 = 这本书看什么）。
2. 主角人设速写（身份/性格/核心欲望/成长弧光方向）。
3. 金手指设计（类型/作用/限制/与核心矛盾的匹配）。
4. 核心矛盾深化（阶段划分：前30章/中期/后期分别解决什么）。

**Prompt 模板**：

```
你是网文策划。把以下切入点深化为完整创意包：
{选定的切入点 + 三件套}

输出：
  一句话梗概：{主角}×{核心矛盾}×{金手指}={这本书看什么}
  主角人设速写：
    身份：{}
    性格：{表面/真实两层}
    核心欲望：{}
    成长弧光：从{}到{}
  金手指设计：
    类型：{信息差/资源差/能力差}
    作用：{怎么帮主角}
    限制：{为什么不能一步到位}
    与矛盾匹配：{金手指如何服务于核心矛盾}
  核心矛盾深化：
    前30章：{什么矛盾}
    中期：{什么矛盾升级}
    后期：{什么终局矛盾}
```

**产出格式**：

```
◆ 一句话梗概
  {主角是谁}×{核心矛盾}×{金手指}={这本书看什么}

◆ 主角人设速写
  身份：{}
  性格：表面{} / 真实{}
  核心欲望：{}
  成长弧光：从{}到{}

◆ 金手指设计
  类型：{信息差/资源差/能力差}
  作用：{}
  限制：{}
  与矛盾匹配：{}

◆ 核心矛盾深化
  前30章：{}
  中期：{}
  后期：{}

如果整体方向认可，进入压力测试轮。如果想改某部分，直接说改什么。
```

**收敛判定**：作者认可 → 进轮次4。作者要改某部分 → 在当前产出上局部修正，不回退到轮次2。

### 轮次4：压力测试轮

**目标**：模型对选定的核心设定做压力测试，抛出 3 个挑战。作者确认能扛住才进定稿。

**输入**：轮次3的完整创意包。

**模型动作**：对创意包做 3 个维度的压力测试，每个维度给出「挑战→如果扛不住的后果→建议加固」。

**三个挑战**：

#### 挑战一：金手指会不会太强

- **测试方法**：假设主角金手指全开，能否在 30 章内解决核心矛盾？
  - 能 → 金手指太强，没有长篇空间。需要加限制。
  - 不能但接近 → 边界模糊，需要明确天花板。
  - 差很远 → 合格。
- **引用方法**：`commercial-core.md` 的金手指原理——金手指的本质是制造差距，差距太大 =
  主角无敌 = 没张力。检查差距类型（信息差/资源差/能力差）是否有局限设置。
- **输出**：

  ```
  挑战一：金手指强度测试
  假设金手指全开，主角能在 30 章内解决核心矛盾吗？{能/接近/差很远}
  {如果能/接近}：金手指过强。建议加限制：{具体限制建议}
  {如果差很远}：合格。金手指有合理的成长空间。
  ```

#### 挑战二：核心矛盾能否撑百万字

- **测试方法**：核心矛盾分几个阶段？每个阶段是否有新的阻力升级？最后一个阶段解决后
  读者还有追读动力吗？
  - 分少于 3 个阶段 → 矛盾太单薄，撑不到百万字。
  - 分 3–5 个阶段但后期重复 → 矛悔回环，读者会腻。
  - 分 3–5 个阶段且逐步升级 → 合格。
- **引用方法**：`commercial-core.md` 的五大崩盘模式——「核心矛盾过早解决」和「升级体系
  天花板」是长篇最常见的崩盘点。检查核心矛盾是否有终局储备（见 `commercial-core.md`
  的持续卖点测试）。
- **输出**：

  ```
  挑战二：长篇空间测试
  核心矛盾分 {N} 个阶段：{列举}
  {N<3}：矛盾太单薄。建议扩展：{增加什么维度}
  {N>=3 但后期重复}：后段重复。建议：{后期引入什么新变量}
  {N>=3 且逐步升级}：合格。
  终局测试：最后阶段解决后读者还有追读动力吗？{有/没有}
  {没有}：建议预留终局悬念：{什么悬念}
  ```

#### 挑战三：读者契约是否清晰

- **测试方法**：用一句话说出「读者追这本书是追什么」。说不清 = 读者契约模糊 =
  读者不知道在追什么 = 前十章流失。
  - 能一句话说清且只说一件事 → 合格。
  - 能说清但说了两三件事 → 契约不聚焦，建议砍到一件。
  - 说不清 → 契约缺失，需要重新定义核心卖点。
- **引用方法**：`commercial-core.md` 的核心卖点论——核心卖点必须一句话说清，超过一句 =
  卖点不聚焦 = 不知道在卖什么。检查核心卖点是否有持续兑现能力（持续卖点测试）。
- **输出**：

  ```
  挑战三：读者契约测试
  一句话说清「读者追什么」：{这句话}
  {能说清且只说一件事}：合格。
  {说了两三件事}：契约不聚焦。建议砍到：{哪一件}
  {说不清}：契约缺失。建议重新定义核心卖点。
  持续兑现测试：这个卖点能支撑 100 章不重复吗？{能/不能}
  {不能}：建议扩展卖点维度：{增加什么}
  ```

**整体产出格式**：

```
压力测试结果：

挑战一（金手指）：{合格/需加固} —— {加固建议}
挑战二（长篇）：{合格/需加固} —— {加固建议}
挑战三（契约）：{合格/需加固} —— {加固建议}

三个挑战都合格或已接受加固建议 → 进入定稿轮。
任一挑战扛不住且无法加固 → 回退到轮次3重新深化。
```

**收敛判定**：
- 三个挑战都合格 → 进轮次5。
- 有挑战需加固 → 作者确认加固方案后进轮次5。
- 有挑战扛不住且无法加固 → 回退到轮次3，重新深化（保留轮次1/2 的选择不变）。

### 轮次5：定稿轮

**目标**：综合前四轮产出，输出 `设定/idea_seed.md`（创意种子）+ `设定/题材定位.md`
（题材定位），衔接 `book-init.md`。

**输入**：前四轮的全部产出（含压力测试加固方案）。

**模型动作**：
1. 汇聚五轮产出为创意种子文档。
2. 用 `references/genres/INDEX.md` 匹配主题材卡，写入题材定位。
3. 输出下一步指令。

**收敛判定**：作者认可 → 脑洞流程结束，进入 `book-init.md`。作者要改 → 在 idea_seed.md

## 收敛失败的处置

5 轮内收敛不了（作者频繁回退、每轮都推翻上一轮的选择）：

1. **诊断原因**：
   - 作者其实不知道自己想写什么 → 建议先扫榜（`market-scan.md`）或先拆 2–3 本
     对标书（`deconstruct.md`）找感觉。
   - 作者想写的太多、什么都想要 → 建议先选一个写，其他留作下一本。
   - 选项不够差异化 → 换角度重出选项（算一次回退）。
2. **降级方案**：跳过脑洞流程，作者直接给一句话卖点进 `book-init.md`。脑洞是辅助
   不是必经流程，作者有明确想法时不需要走五轮。
3. **归档**：未收敛的脑洞记录写入 `设定/idea_seed_draft.md`（注意是 draft），
   保留中间产出，下次想继续时可以从草稿恢复。

## 与 commercial-core.md 的衔接

压力测试轮（轮次4）直接引用 `commercial-core.md` 的方法论：

| 挑战 | 引用的 commercial-core 章节 | 检查点 |
|---|---|---|
| 金手指太强 | 金手指原理 → 金手指的本质：三种差 | 差距类型是否有局限设置 |
| 核心矛盾撑不住 | 崩盘原因 → 五大崩盘模式 | 是否有「核心矛盾过早解决」「升级体系天花板」风险 |
| 读者契约不清 | 卖点论 → 核心卖点 | 核心卖点能否一句话说清 + 持续卖点测试 |

压力测试不是为了否定创意，而是提前暴露长篇风险。暴露的问题在定稿轮加固，比写到
30 万字才发现崩盘成本低得多。

## 与 book-init.md 的衔接

脑洞流程产出 `设定/idea_seed.md` 后，进入 `book-init.md` 的正式开书流程：

| book-init.md 步骤 | 读取的脑洞产出 |
|---|---|
| Step 0 创意与定位 | idea_seed.md 的一句话梗概、核心卖点、目标平台 |
| Step 1 一键建骨架 | 题材定位.md 的主题材（用于 --genre 参数） |
| Step 2 世界观、人物与文风 | idea_seed.md 的主角人设速写（转成人物卡初稿） |
| Step 3 总纲 | idea_seed.md 的核心矛盾阶段划分（转成分卷规划） |

book-init.md 不强制依赖 idea_seed.md——作者直接进 book-init 也可以，Step 0 会正常
走创意确认流程。idea_seed 是可选输入，有了它 Step 0 更快（不用重新聊创意）。

## 脑洞纪律

- **不替作者做决定**：每轮只给选项和分析，选择权在作者。
- **选项要真差异化**：轮次1 的 10 个候选如果只是换了个说法，作者会选不出来。每个候选
  的核心钩子必须不同。
- **不脱离市场**：轮次1 的题材方向要有数据支撑（扫榜报告或平台热门趋势），不凭空捏造。
  没有数据支撑的方向要标注「未经市场验证」。
- **不堆砌设定**：脑洞阶段只定核心要素（题材/卖点/人设/矛盾/金手指），世界观细节、
  配角、伏笔等留给 `book-init.md` 展开。脑洞不是写设定集。
- **收敛优先于完美**：五轮收敛的目标是「能开书的创意种子」，不是「完美的方案」。
  方案不完美可以在开书后用 `revision.md` 调整，但一直收敛不了 = 这本书开不了。

## 与其他工作流的关系

| 场景 | 用哪个 |
|---|---|
| 不知道写什么 | `ideation.md`（本文件）→ 产出 idea_seed.md |
| 看市场缺什么 | `market-scan.md` → 产出扫榜报告（可作为本文件轮次1输入） |
| 学对标书的结构 | `deconstruct.md` → 产出拆文素材（可作为本文件参考） |
| 创意确定要开书 | `book-init.md` Step 0 读取 idea_seed.md |
| 写到一半改方向 | `revision.md`（不走脑洞，走改纲级联） |
| 商业核心方法 | `references/craft/commercial-core.md`（压力测试轮引用） |

脑洞流程是开书前的「选题阶段」，产出的是方向不是细节。方向定了，细节交给
`book-init.md` 和 `outline-system.md` 展开。
