# 三级大纲体系

总纲管方向，卷纲管结构，章纲管执行。任何一级的修改都可能波及下级——改纲必须级联检查。

## 各级职责

| 级别 | 文件 | 回答的问题 | 粒度 |
|---|---|---|---|
| 总纲 | `大纲/总纲.md` | 这本书讲什么、往哪去、分几卷走 | 全书卷级鸟瞰 |
| 卷纲 | `大纲/卷纲_第X卷.md` | 这一卷给读者什么、怎么起承转合 | 剧情单元级（5–15 章/单元） |
| 章纲 | `大纲/章纲_第XXX章.md` | 这一章具体写什么 | 情节点级 |

模板分别在 `assets/templates/` 下的 `outline-master.md`、`outline-volume.md`、`outline-chapter.md`。

## 总纲（开书时写，之后少动）

核心内容：一句话主线、分卷规划表（每卷的卷目标一句话 + 主角阶段状态）、终局方向、
红线（绝不写的走向）、读者契约摘要（核心快感 + 兑现频率）。总纲是全书的锚，
改动视同「重大决策」，必须作者确认。

### 终局储备边界

总纲里必须标明「终局前不能动用的储备」——为最后爆发攒的底牌：

- 终局真相/反转：全书最大的秘密，不到最后一卷不揭
- 终局战力：主角/势力的最终底牌，不到终局不亮
- 终局关系：终局才有意义的关系转变（宿敌联手/导师背叛/身份互换）

每卷卷纲检查：本卷有没有提前动用终局储备？动用了 = 透支，必须改纲。

## 卷纲（每卷开卷前写）

核心内容：

- **卷契约**：这一卷兑现给读者什么（主角登上新台阶？揭开一层真相？感情线质变？）——
  卷末交不出契约就是水了一卷。卷契约必须与读者契约（见 `craft/reader-contract.md`）一致。
- **剧情单元划分**：本卷拆成几个单元（一个单元 = 一个相对完整的事件链，5–15 章）。
- **情绪弧线**：本卷的情绪起点、谷底、高点各在哪个单元。
- **本卷伏笔计划**：计划埋哪些、收哪些（与 `追踪/伏笔台账.md` 双向核对）。

### 大纲锚点配额

卷纲里必须标明本卷的「锚点」——不可跳过的关键情节点。锚点不是事无巨细地排满每章，
而是标出「这卷走到这里必须经过的几个关键站」。

| 锚点类型 | 说明 | 每卷上限 | 每卷下限 |
|---|---|---|---|
| 主线锚点 | 主线矛盾的不可逆推进点 | 2-3 | 1 |
| 关系锚点 | 主要关系到达决定性节点 | 2 | 1 |
| 秘密锚点 | 核心秘密被部分揭露 | 1-2 | 0 |
| 高潮锚点 | 卷级大爆发 | 1 | 1（卷末） |

**配额纪律**：
- 锚点总数每卷 ≤ 6（超过 = 节奏太赶，主线被塞满）
- 每个锚点之间至少间隔 3 章（给铺垫留空间）
- 锚点不能连续两章集中爆发（见 `craft/reverse-brake.md` 的 A/B/C 冷却规则）
- 锚点与 A/B/C 配额联动：一个主线锚点 = 触发 1 次 A，受 A 的 2 章冷却约束

**锚点检查**：写完每卷后，核对实际写的锚点与卷纲计划是否一致。多了 = 节奏失控，
少了 = 卷契约没兑现。

### 卷级档位规划

卷纲里附一张本卷的档位分布草表（粗排，不用精确到每章）：

```
单元1（章1-8）：中→中→慢→中→中→快→慢→中
单元2（章9-16）：中→慢→中→中→快→快→慢→中（卷末高潮）
```

这张表是节奏的「预算」——实际写作时允许微调，但快档总数不能超配额（每卷 ≤2-3 次）。

## 章纲（滚动补纲，不一次写满）

核心字段（见模板）：

- 核心事件、目标情绪、出场人物
- 情节点清单（每个情节点带字数预算，总和 Σ∈[目标字数, 目标×1.1]）
- 章首承接、章尾钩子
- 伏笔操作（埋/推/收）
- **节奏档位声明**：本章是慢/中/快档
- **A/B/C 配额预声明**：本章至多触发哪一项（或「不触发」）
- **事件类型声明**：本章的主 Beat 属于哪个事件类型（见 `reverse-brake.md` 事件矩阵）

字数预算的作用：防注水也防赶进度。写完对照预算，哪个情节点超了或没写到，一眼可见。

### 章纲的配额自检

补纲时自检：
1. 本章的档位与近 3 章的分布合理吗？（快档后不能接快档）
2. 本章预声明的 A/B/C 项，上一个同类配额的冷却期过了吗？
3. 本章的事件类型在上一个同类事件的冷却期内吗？
4. 本章锚点（如有）与卷纲计划一致吗？

## 滚动补纲纪律

1. **一次只补一个剧情单元**（5–15 章的章纲），写完一个单元再补下一个。
2. **已写区间锁定**：已发布的章纲只增不改——只允许追加批注（实际执行情况），
   不允许改写历史。历史要改，改的是「后面的纲」。
3. **补纲前先回看**：补下一个单元前，读上一单元的章节摘要，确认实际剧情与卷纲的
   偏差；偏差大了，先修订本卷卷纲再排新章纲。
4. **补纲时查配额**：补新章纲时必须查近 3 章的 A/B/C 记录和事件冷却状态，
   确保新章纲的配额预声明不越界。

## 改纲级联规则

任何一级大纲改动后，按波及面依次检查：

- 改总纲 → 检查各卷卷纲是否还成立 → 检查未写章纲 → 检查伏笔台账（长线伏笔的回收
  计划是否受影响）→ 检查人物卡（角色弧光方向）→ 检查终局储备边界是否被提前动用。
- 改卷纲 → 检查本卷未写章纲 → 检查伏笔台账中本卷的埋收计划 → 检查本卷锚点配额
  （改纲后锚点总数是否超限）→ 检查本卷档位分布是否合理。
- 改章纲（未写的）→ 检查同单元相邻章纲的承接 → 检查伏笔台账（本章原定的埋收操作
  挪到哪章了）→ 检查配额预声明是否越界。
- 人物设定变更视同改纲：级联检查人物卡、角色状态、未写章纲。

级联检查的结果写进被波及文件的批注里，不留「脑子里记得要改」的账。

## 断更与接手

- 断更后恢复写作：不要凭记忆续写。依次读：总纲 → 当前卷卷纲 → 最近一个单元的章纲 →
  章节摘要（近 10 章）→ 角色状态 → 伏笔台账 🟡/🔴 表 → 节奏配额记录。读完再进入单章循环。
- 换作者/换 agent 接手：上面的恢复流程 + `设定/题材定位.md` + `设定/读者契约.md`，
  就是完整的交接包。
